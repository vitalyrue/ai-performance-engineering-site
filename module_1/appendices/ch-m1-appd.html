Appendix A — Libraries and frameworks used in the book

The tables identify packages, model IDs and connection interfaces used in the book. Entries marked Example give a concrete implementation where a chapter leaves that choice open. The reference architecture in Section 12.1 shows how the libraries work together.

The code examples use Python. The commands below identify the packages to install, not a tested set of pinned versions. PyPDFLoader and RecursiveCharacterTextSplitter are classes supplied by the listed packages, not separate packages.

An alternative JavaScript and TypeScript OpenAI SDK installs with npm install openai.

BGE is a family of embedding and reranking models. The IDs below locate model repositories. An exact saved version is selected with a pinned repository commit ID. A Python library loads and runs the model. Chapters 6 and 12 use the first model, while the reranker is an example implementation.

Chat Completions and Responses are APIs, not installable libraries. They use different request and response formats over HTTP. MCP is a protocol for exchanging tool, resource and prompt messages between a client and a server.

The Nebius examples use the OpenAI Python SDK with a different base_url and the provider’s Chat Completions API. Nebius Token Factory’s API reference documents that connection. OpenAI compatibility alone does not establish support for the Responses API. The provider must document the endpoint and features it supports.

Chapter 13 describes experiment records and traces. The following entries identify tools for collecting them, plus a container runtime as an example implementation for code execution.

A default Docker container is not a complete sandbox for untrusted code. Its security documentation describes isolation limits and configuration requirements.
