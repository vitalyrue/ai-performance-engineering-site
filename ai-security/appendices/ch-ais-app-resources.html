Appendix C — Implementation and research resources

Tools, case collections, and research groups that support the book’s controls and evidence methods.

This appendix points to implementation tools and research communities that the chapters use for demonstrations or context. Entries are summaries for study and not endorsements. Each item states its maintainer and where to find its primary documentation. No product was installed or run to build the guide.

C.1 Tools and platforms

Tools that evaluate or enforce security checks described in Part 2 to Part 5. A tool implements an algorithm or control but does not by itself guarantee a secure system.

  • Adversarial Robustness Toolbox (ART), maintained by IBM Trusted-AI group. Primary docs at https://adversarial-robustness-toolbox.readthedocs.io/. Python library that tests and defends models against evasion and poisoning and other attacks.
  • Microsoft PyRIT, maintained by Microsoft Azure AI Red Teaming team. Primary docs at https://microsoft.github.io/PyRIT/. Automation for AI red teaming against generative AI endpoints.
  • NVIDIA garak, maintained by NVIDIA. Primary docs at https://docs.garak.ai/. Scanner that probes large language models with crafted prompts and checks outputs.
  • Giskard, maintained by Giskard AI. Primary docs at https://giskard.ai/. Red teaming and testing platform for language model agents.
  • Open Policy Agent (OPA), maintained by Cloud Native Computing Foundation. Primary docs at https://www.openpolicyagent.org/docs/. Policy engine that evaluates Rego policies and returns allow or deny decisions for an application to enforce.
  • SPIFFE and SPIRE, maintained by Cloud Native Computing Foundation. Primary docs at https://spiffe.io/docs/latest/. Identity framework that issues workload identities for services across platforms.
  • Sigstore, maintained by Open Source Security Foundation. Primary docs at https://docs.sigstore.dev/. Signing and transparency log service for software artifacts.
  • SLSA, maintained by Open Source Security Foundation. Primary docs at https://slsa.dev/. Framework that defines build integrity levels for supply chains.
  • C2PA, maintained by Coalition for Content Provenance and Authenticity. Primary docs at https://c2pa.org/. Standard that binds provenance statements to digital content.

C.2 Incident and case collections

Collections that record threat techniques or reported incidents. They document cases and do not detect or prevent incidents by themselves.

  • MITRE ATLAS, maintained by MITRE. Primary docs at https://atlas.mitre.org/. Knowledge base of tactics and techniques that target AI systems mapped to ATT&CK.
  • AI Incident Database, maintained by Responsible AI Collaborative. Primary docs at https://incidentdatabase.ai/. Public index of reported AI harms and near harms.
  • CERT Coordination Center reporting, maintained by Carnegie Mellon University Software Engineering Institute. Primary docs at https://www.kb.cert.org/vuls/report/. Public route for reporting software vulnerabilities for coordination.

C.3 Research groups and communities

Research communities that study AI security and publish guidance or evaluations. Each entry notes its home institution and focus areas drawn from the preparation directory.

  • ETH Zurich SRI Lab, based at ETH Zurich Department of Computer Science. Home page at https://sri.inf.ethz.ch/. Reliable and secure machine learning with focus on large language models and robustness.
  • CMU SEI AISIRT, based at Carnegie Mellon University Software Engineering Institute. Home page at https://www.sei.cmu.edu/history-of-innovation/aisirt. Operational team that responds to AI vulnerabilities and coordinates disclosure.
  • Berkeley CLTC AI Security Initiative, based at University of California Berkeley Center for Long-Term Cybersecurity. Home page at https://cltc.berkeley.edu/ai-security/. Risk management profiles and standards for general-purpose and agent AI.
  • Georgetown CSET, based at Georgetown University. Home page at https://cset.georgetown.edu/. Analysis of security implications of emerging technologies including AI and cybersecurity.
  • RAND CAST, based at RAND Corporation. Home page at https://www.rand.org/global-and-emerging-risks/centers/ai-security-and-technology.html. Center for AI security and technology including model weight protection and evaluations.
  • Alan Turing CETaS, based at Alan Turing Institute. Home page at https://cetas.turing.ac.uk/. Study of generative AI risks and evaluation including disinformation and safety assessment.
