6  Resisting adversarial inputs

This chapter defines adversarial-input claims precisely enough to distinguish a measured weakness from a broad claim that a model or system is generally insecure.

Security question. How can a changed input cause a deployed model to make the wrong decision?

Reference frame. Use a small controlled classifier with a fixed deployed model. The attacker changes allowed test inputs, not training data. A later comparison considers an API where gradients and weights are unavailable.

Connection through the book. The laboratory from Chapter 4 supplies a baseline, but the allowed intervention changes. Chapter 14 reuses these constraints when judging robustness evidence.

6.1 Evasion threat models

An error caused by an unusual input becomes a security test only after the attacker’s goal and allowed changes are stated. An evasion attack changes an inference input to alter model behavior without changing model parameters. An adversarial example is the resulting input. A perturbation constraint defines the changes the attacker may make.

NIST classifies evasion as a deployment-stage attack and separates white-box, black-box, digital, and physical settings.1 These classes define access and setting. They do not show that a mathematically small change is feasible or harmless in the real system.

The threat model records the starting input, target or untargeted objective, permitted region, model knowledge, query budget, and physical constraints where relevant. That objective and feasible set supply the inputs to gradient-based attacks.

The evaluation harness enforces this test boundary. It checks that each candidate starts from an eligible input and remains within the stated digital, physical, or business constraint before counting an attack result. Evidence includes rejected candidates, valid candidates, model decisions, and the exact constraint. Coverage is valid attacked inputs divided by all eligible reference inputs. Validity checks add test design and review cost. A poor representation of real constraints can admit impossible inputs or reject feasible ones. Recovery blocks the model version when its accepted threshold fails and returns to the previous accepted version. Passing does not cover another attacker goal or feasible set.

6.2 Gradient-based attacks

A loss function returns one scalar that measures how poorly the model meets the stated objective for an input and reference. The input gradient gives the local rate and direction of loss change for each input feature. An L-infinity budget limits the absolute change of every feature. A budget of 0.10 permits at most 0.10 of change in each feature. Projection returns a proposed update to the allowed set when a step leaves it. The mathematical set still requires the business or physical validity check introduced in the preceding section.

With white-box access, the attacker can use derivatives of the loss with respect to the input. The fast gradient sign method, or FGSM, takes a step in the sign of that gradient under a stated norm budget. Projected gradient descent, or PGD, repeats an update and projects the candidate back into the allowed set.

Goodfellow, Shlens, and Szegedy derived FGSM from a linear explanation of adversarial vulnerability.2 Madry and colleagues used iterative first-order updates with projection in their study of optimization against adversarial inputs.3

The mechanism follows the local gradient to increase loss while projection enforces the mathematical budget. Its strength is relative to that norm, step schedule, restart count, and optimization result. The next section removes direct gradient access and examines query and transfer attacks.

For a fixed model with parameters \(\theta\), input vector \(x\), reference label \(y\), and loss \(L(\theta,x,y)\), the input gradient \(\nabla_x L\) states how a small change in each input feature changes the local loss. FGSM under an \(L_\infty\) budget \(\varepsilon\) uses

\[ x_{adv}=\operatorname{clip}\left(x+\varepsilon\operatorname{sign}(\nabla_x L)\right). \]

The clip operation enforces valid feature limits. PGD uses smaller repeated steps and projects each candidate into the allowed region around the original input. The model parameters remain unchanged during both attacks.

Two-feature numerical step (hypothetical). The operating mode is inference against a fixed binary classifier. The task is to raise loss for the reference class \(y=0\). The input is \(x=(0.40,0.70)\), each feature must remain between 0 and 1, and the \(L_\infty\) budget is 0.10. Suppose \(\nabla_x L=(2.0,-0.5)\). FGSM uses the sign vector \((1,-1)\), producing \(x_{adv}=(0.50,0.60)\). For PGD with step size 0.06, the first candidate is \((0.46,0.64)\). A second equal-direction step reaches \((0.52,0.58)\), then projection returns it to \((0.50,0.60)\). The observed candidate is within 0.10 of each original feature. The conclusion is only that the update obeys this mathematical constraint. A changed model decision would still need to be measured.

The projection step enforces the attack’s mathematical input limit, while the release evaluator enforces the security decision. It records successful objective changes out of all eligible attacked inputs, clean results over the same reference set, restart count, and compute time. More restarts can find stronger candidates but increase evaluation cost. Vanishing or hidden gradients can make this attack appear to fail. Recovery withholds the model or restores the accepted version, then repeats the test with an adaptive method. The result does not cover black-box access or a physical constraint that the norm omits.

6.3 Black-box attacks and transfer

A remote interface may hide weights and gradients but still expose useful feedback. A score-based attack uses returned scores to estimate a productive direction. A decision-based attack sees only the final label or decision. A substitute model approximates the target and can produce inputs tested for transfer.

NIST separates score-based and decision-based black-box attacks and describes transfer attacks that use a surrogate against another model.4 Because transfer depends on the models, data, constraints, and query process, the taxonomy does not give a universal success rate.

The evaluation keeps the same objective and feasible set used for white-box tests while changing the observations available to the attacker. It reports query count and attack success separately. These attack families define what a robustness measurement includes or leaves outside scope.

Concrete black-box trace (hypothetical). The operating mode is inference through a remote label-only API. The task is to change one accepted transaction classification while each normalized feature may move by at most 0.05. The attacker cannot inspect parameters or gradients. It queries 40 nearby inputs, uses the returned labels to choose a direction, and tests 12 more candidates. Candidate 52 changes the output while remaining inside the recorded feature box. The observed result is one decision change after 52 queries. The conclusion applies to this input, interface, budget, and validity check. It does not establish transfer to another model or feasibility in the original business process.

The query gateway enforces account and request budgets, and the evaluator checks candidate validity before counting success. Evidence includes queries accepted and rejected, outputs returned, valid candidates, and final decisions. The report states successful attacks over all eligible starting inputs and queries used per successful and failed attempt. Strict limits can reduce abuse while also blocking legitimate repeated use. Distributed accounts or another output interface can bypass them. Recovery closes the unmetered path and changes the interface if needed. The evaluation then runs again. A failed search within one budget does not prove that no black-box attack exists.

6.4 Robustness measurement

A defense may look successful because the test attack failed to optimize. Robust accuracy is task accuracy under the stated adversarial evaluation. Attack success rate is the fraction of eligible cases where the attack reaches its objective. Adaptive evaluation changes the attack to account for the defense.

NIST warns that stronger evaluations have defeated many proposed evasion mitigations and treats adaptive testing separately from certified results.5 Athalye, Carlini, and Wagner identified symptoms of obfuscated gradients and bypassed most defenses in their nine-defense case study with adaptive attacks.6

The report pairs clean accuracy with accuracy under the stated attack. It also records attack success, budget, restarts, and any adaptation to the defense, without extending the case study to every defense. A stable baseline under the same threat model is needed before judging adversarial training.

The release gate checks clean and attacked results from the same eligible set against separate thresholds. The report gives correct clean decisions over all clean cases, correct attacked decisions over all valid attacked cases, and successful attacks over all cases eligible for the attack objective. It also records invalid candidates and attack failures caused by resource limits. Adaptive evaluation costs more compute and analyst effort. A weak optimizer, unexamined randomization, or a changed input pipeline can make the defense look stronger than it is. A failed threshold blocks release and triggers a return to the prior version. Passing does not establish a universal robustness property.

6.5 Adversarial training

One defense changes training so the model learns from difficult inputs. Adversarial training minimizes loss on adversarial examples produced inside the training procedure. In this min-max form, an inner maximization searches for a high-loss allowed input and an outer minimization updates parameters against that result.

Madry and colleagues formulated this process as a min-max problem and trained against PGD adversaries.7 NIST reports that adversarial training can reduce ordinary accuracy and increase training cost.8

The defense should be tested with the same constraint used in training and with attacks that were not part of parameter updates. Its evidence supports empirical robustness under that model, not general security. Other defenses make different claims, including detection, abstention, and formal bounds.

Worked training comparison (hypothetical). The operating mode is training, followed by evaluation with no further parameter updates. A baseline classifier and an adversarially trained classifier use the same 800 training cases. The reference test contains 200 clean cases plus PGD cases under an \(L_\infty=0.10\) constraint. The baseline records 184 correct clean decisions and 62 correct PGD decisions. The defended model records 178 clean and 131 PGD decisions, while training time rises from 10 to 34 minutes. The conclusion is a clean-performance and cost trade-off with stronger empirical robustness in this test. It is not a guarantee against other constraints, attacks, or data.

The training loop enforces the inner attack constraint and updates parameters against the resulting examples. The release gate then compares 178 correct clean decisions over 200 cases and 131 correct attacked decisions over 200 eligible attacked cases with the accepted thresholds. The run record also captures the increase from 10 to 34 minutes. A different norm, radius, attack, or population can bypass the tested protection. Recovery restores the baseline or another accepted checkpoint and repeats clean and attacked evaluation. The observed gain does not establish certified robustness.

6.6 Other defense claims

Defense reports can refer to different outcomes. A detector flags suspected adversarial input. Abstention withholds a model decision under a stated rule. A certified bound proves a property for specified inputs and perturbations under its mathematical assumptions.

NIST separates empirical mitigations from certified defenses and notes that certificates are limited to their perturbation model and often to a subset of inputs.9 Athalye and colleagues showed that hidden or unusable gradients can make an unsuitable attack report false confidence.10

Each claim needs the defended property, threat model, coverage, failure rule, and cost. A certificate outside its assumptions says nothing about other attacks or the surrounding application. Chapter 7 applies the same evidence discipline when deciding which external components may enter the trusted environment.

Concrete defense comparison (hypothetical). The operating mode is evaluation on 100 eligible adversarial cases. The detector flags 70 cases and produces 15 false alarms on 100 clean cases. Under the abstention rule, 55 decisions are withheld and 10 attacks succeed among the remaining cases. A certificate covers 38 inputs under an \(L_2\) radius of 0.20. The intermediate record keeps these denominators and perturbation rules separate. The observed results cannot be ranked by one number because detection, abstention, and certification make different claims. The conclusion is to report each property, coverage set, error rate, and operating cost without extending an \(L_2\) certificate to the earlier \(L_\infty\) attack.

The application enforces detector and abstention decisions, while a certificate checker verifies the formal predicate for each covered input. Evidence records 70 detections over 100 adversarial cases, 15 false alarms over 100 clean cases, 55 abstentions over their 100 eligible cases, and 38 certificates over the specified input set. Detection review and abstention reduce throughput and may deny useful work. An adaptive attack can evade the detector, and the certificate says nothing beyond its radius and assumptions. Recovery disables the failed path, returns to an accepted model or policy, and retests. None of the three records proves that the whole application is secure.
