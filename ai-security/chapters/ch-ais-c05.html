5  Limiting query disclosure

This chapter separates disclosure that occurs through normal application data handling from disclosure inferred or extracted through model queries, then matches each mechanism to evidence and limits.

Security question. What can an adversary learn by querying a deployed model?

Reference frame. Use a query interface to the laboratory model, then compare query-only access to a hosted service. State whether the attacker sees labels, scores, or generated text and which data they are trying to infer.

Connection through the book. Reuse the data and attacker definitions, then distinguish ordinary unauthorized access from inference through outputs. The resulting measurements feed Chapter 14 and supplier questions in Chapter 21.

5.1 Specifying query observations

A disclosure result has little meaning until the interface and attacker are fixed. Black-box access permits queries and observations without exposing model internals. The interface may return a label or generated text. Some systems also expose confidence scores and logits. The attacker may also possess auxiliary data and a fixed query budget.

NIST distinguishes black-box attackers by returned outputs, query access, and prior knowledge.1 These fields define a threat model but do not predict attack success.

The organization records the output fields, rate limits, account rules, adaptive-query allowance, prior knowledge, and target secret. Changing one can change the conclusion. This fixed observation model supports the first disclosure question: membership inference.

The query gateway enforces the exposed interface. It checks account identity, allowed output fields, rate state, and query budget before returning, changing, or blocking a response. Evidence includes accepted and rejected queries, returned fields, account state, and model version. Tests report exposed fields out of all requested fields and accepted queries out of all attempts, with authorized controls kept separate. Restriction can reduce utility and add latency. Distributed accounts or an unmetered route can bypass the budget. Recovery closes that route and revokes affected credentials while preserving query records. Allowed outputs can still disclose information.

Concrete interface comparison (hypothetical). The operating mode is inference through a hosted classifier. The task is to assess what a query-only attacker can observe about one target record. Interface A returns only a class label. Interface B returns the label and three class probabilities. Both allow 100 adaptive queries from one account. The same 10 inputs produce identical labels, while interface B also exposes how sharply the model separates the classes. The observed result is a larger attack input at the same query count. The conclusion is that a disclosure result from interface B cannot be assigned to interface A without a new test. These outputs and limits are hypothetical.

5.2 Membership inference

The decision here concerns one record, not recovery of its content. Membership inference estimates whether a record was used in training. A shadow model is trained by the attacker to imitate the target setting and produce examples for an attack classifier. Results should report both true-positive and false-positive rates.

Shokri and colleagues introduced a membership-inference attack that uses target outputs and shadow-model data.2 NIST also summarizes loss-based and shadow-model attacks through a challenge game.3

An evaluation samples members and non-members under a stated distribution. The allowed outputs become inputs to the attack score. Its operating point matters because a high false-positive rate can make an apparent advantage unusable. The published experiments apply to their models and interfaces. The next section changes the secret from membership to record content, attributes, or population properties.

Worked membership test (hypothetical). The operating mode is evaluation. The input is a balanced set of 100 known training members and 100 non-members from the same reference population. An attack score and threshold classify 34 members as members and incorrectly classify 18 non-members as members. The observed true-positive rate is (34/100=0.34), and the false-positive rate is (18/100=0.18). Among the 52 positive decisions, only 34 are correct. The conclusion is that the attack separates these test groups at this threshold, but the result does not establish usefulness when real members are rare or the target population differs.

The release evaluator enforces the organization threshold by checking the member and non-member sampling rule, attack score, threshold, and model version. It allows release only at the accepted threshold. Otherwise, the interface changes or the version remains blocked. The report keeps 34 true positives over 100 members and 18 false positives over 100 non-members rather than one combined percentage. More attack runs improve coverage but consume queries and analyst time. A different population, prior, or adaptive strategy can bypass the tested conditions. Recovery restricts the interface or returns to the accepted model. It cannot undo information already released.

5.3 Reconstruction and property inference

Several privacy attacks are often grouped together even though they answer different questions. Data reconstruction seeks a record or a close representation. Attribute inference estimates a missing field about an individual. Property inference estimates a feature of the training population.

NIST separates reconstruction, attribute inference, and property inference and assigns different access and knowledge assumptions to them.4 A semantically similar reconstruction need not be the original record, and a population property is not an individual attribute.

The evaluation states the target secret and auxiliary knowledge. It also records the correctness criterion and comparison baseline. This separation prepares the stricter case where generated content can be checked against known training data.

The evaluation harness checks one stated secret at a time and records correct inferences out of all eligible targets, along with the baseline and false positives. The release owner changes or blocks the interface when the accepted threshold fails. Building representative targets and auxiliary data costs review time and may expose sensitive test material. Another secret, stronger auxiliary knowledge, or a shifted population can escape the test. Recovery limits outputs and access, then repeats the evaluation after a model or data change. A passing result does not cover secrets absent from the target set.

5.4 Training-data extraction

A plausible output is not yet evidence that the model revealed a training record. Training-data extraction produces content that can be verified against training data or another reliable record. A canary is a controlled sequence inserted into training data to measure memorization, and exposure measures how unusually easy it is to recover within the defined canary distribution.

Carlini and colleagues extracted verifiable examples from GPT-2 through a staged method. Candidate generation came first. A ranking step selected likely memorized text for checking against the training data.5 Earlier work by Carlini and colleagues defined exposure for inserted canaries as an empirical measure of unintended memorization.6

These results establish methods and examples, not a universal extraction rate. A canary test covers its chosen distribution and cannot prove the absence of other memorized content. The next target is model functionality rather than training data.

The extraction evaluator checks each generated candidate against an authorized reference and records verified recoveries out of all generated candidates. A canary test separately reports recovered canaries out of all inserted canaries and the query budget used. Candidate generation and verification can be costly, and the reference comparison may require restricted-data handling. A prompt strategy or memorized sequence outside the chosen distribution can bypass the test. Recovery restricts the interface and removes the model from release while the data and training path are reviewed. It cannot retract a verified sequence already disclosed.

5.5 Model extraction

An organization may protect a model’s behavior even when no record is disclosed. Model extraction uses observations from a target model to build an extracted model. Functional agreement measures how often the two produce the same result over a stated input distribution.

Tramèr and colleagues defined black-box model extraction through prediction application programming interfaces and evaluated copies by agreement with the target over an input space.7 The studies cover specified model classes and services. Agreement does not show that original parameter values were copied.

A useful test separates queries used to build the copy from unseen inputs used to measure agreement. It also records query cost and the baseline agreement of a model trained without target outputs. This empirical risk leads to a mechanism-level privacy guarantee: differential privacy.

The query gateway can reduce returned detail and enforce account budgets. It blocks abusive access under the stated rule. The evaluator reports agreement on unseen inputs as matching outputs divided by all unseen test inputs, with extraction queries and cost reported separately. Output restriction may reduce legitimate use, and strict budgets may affect shared accounts. Distributed identities or another interface can bypass the control. Recovery rotates credentials or changes the exposed interface, then retests agreement. It cannot erase an extracted copy already built, and low agreement does not prove that the original weights stayed private.

5.6 Differential privacy

Attack testing samples known methods, while differential privacy bounds how much a randomized mechanism’s output distribution may change when one protected unit changes. The neighboring-data relation states what one change means. The parameters epsilon and delta quantify the allowed distributional difference under the formal definition.

Dwork and Roth define differential privacy over neighboring data sets and a specified randomized mechanism.8 Their composition results show that privacy loss accumulates across repeated mechanisms.9 The applicable accounting method must match the mechanisms and sampling assumptions.

The guarantee does not cover data that bypass the mechanism, and its meaning depends on the protected unit and neighboring relation. A small parameter is not a complete privacy program. The final section compares this formal statement with empirical tests and operational controls.

The private training or release mechanism enforces this guarantee. Its accountant checks the protected unit, neighboring relation, mechanism parameters, sampling assumptions, and prior releases before allowing another release. Evidence is the mechanism configuration, accounting entries, and the resulting cumulative epsilon and delta. Epsilon and delta are guarantee parameters, not empirical success fractions. Utility is measured separately over a stated test denominator. Randomization can reduce utility and private training can add compute cost. Data sent outside the mechanism or omitted releases invalidate the account. Recovery stops further release and fixes the path, although spent privacy loss cannot be revoked and the guarantee does not prove that one output hides a person.

The formal relation makes those dependencies explicit. Let \(D\) and \(D'\) be neighboring data sets that differ in one protected person’s record. For a randomized mechanism \(M\) and any possible set of outputs \(S\),

\[ \Pr[M(D) \in S] \le e^{\varepsilon}\Pr[M(D') \in S] + \delta. \]

Here, ε limits the multiplicative change in output probability, while δ allows a small additive exception. The mechanism, neighboring relation, protected unit, and repeated releases are part of the claim.10

Small randomized example (hypothetical). The task is to release one person’s yes-or-no response with less direct disclosure. The input is the true bit. The mechanism reports the truth with probability 0.75 and the opposite with probability 0.25. If neighboring inputs change from yes to no, the largest probability ratio for either reported value is (0.75/0.25=3). This toy mechanism satisfies the relation with \(\varepsilon=\ln(3)\approx1.10\) and \(\delta=0\). The observed result is a distributional bound, not a promise that one output is false. The bound permits some learning about an individual.

Limited composition illustration (hypothetical). If the organization runs this same mechanism twice for the same protected unit, basic composition gives an upper bound of \(2\ln(3)\approx2.20\) with \(\delta=0\). The intermediate privacy record adds the two ε values. The conclusion applies to this simple accounting illustration. Other mechanisms, dependence, and sampling can require a different accountant, so the example does not set a deployment budget.

5.7 Privacy defenses and evidence

The organization now has to match each defense to the path it changes. An output restriction removes or coarsens returned information. A rate limit reduces query volume. An empirical attack test measures selected attacks, while a formal guarantee follows from a defined mechanism and assumptions.

NIST lists access restriction, query monitoring, output restriction, regularization, and privacy-preserving training as distinct mitigation classes.11 NCSC guidance recommends controls on query interfaces to detect or prevent attempts to access confidential information.12

Mitigation names alone do not establish effectiveness. Evidence should pair task quality with attack success, false-positive rates, query cost, privacy parameters where used, and operating cost. That comparison closes the disclosure branch and moves to Chapter 6, where the attacker changes inputs to alter decisions.

The release owner compares these unlike records without collapsing them into one score. Empirical attack records include successes over eligible targets and false positives over non-target controls. Query-control records include blocked attempts over all attempts and legitimate requests denied over all legitimate controls. For differential privacy, it includes the accounted parameters and utility measured on the stated test set. Tight limits can reduce service quality and increase support work. New interfaces, identities, models, or data paths can bypass earlier evidence. Recovery restricts access, restores an accepted version, and repeats the affected tests. These results provide bounded evidence for the stated disclosure mechanisms.

Note

Chapter checkpoint. A hosted classifier returns labels and probabilities. A membership test reports 34 true positives and 18 false positives on 100 members and 100 non-members. A separate private release uses the toy mechanism from this chapter twice. What can the organization conclude?

Answer. The membership test has a 0.34 true-positive rate and a 0.18 false-positive rate at the tested threshold. Its meaning remains tied to the interface, query budget, and balanced evaluation population. Basic composition for the two private releases gives a bound of about 2.20 for ε with δ equal to zero under the stated neighboring relation. This formal bound does not cover data sent outside the mechanism. Each result measures one stated property and leaves other privacy risks and the acceptable operating point unresolved.
