24  Security under changed assumptions

Changes in physical access, participant trust, persistence, delegated authority, or systemic uncertainty reopen earlier security assumptions.

Security question. Which controls and evidence stop applying when access, time, location, coordination, or possible impact changes?

Organization setting. The examples are hypothetical extensions of the organization used in the earlier cases. Each example changes one major condition and keeps the resulting evidence limit explicit.

Sector context is not the only source of change. Physical access, distributed training, device control, long running agents, delegation, and frontier capabilities can invalidate earlier technical assumptions.

For each branch, record the earlier assumption and the changed condition. Then identify the affected control and the new possible failure. Record which evidence must be collected again. The final comparison uses these fields for every branch.

24.1 Edge deployment security

A centrally operated application can rely on a stable network and controlled facilities. It can also send records to consolidated logs. An edge deployment runs a model or AI application on or near the device that supplies data or receives action. Offline operation continues without a remote dependency. A device security state reports if security functions operate as expected.

NIST’s Internet of Things baseline covers protection of stored and transmitted data, limits on local and network interfaces, authenticated software updates, rollback, and reporting of device security state.1 The same baseline permits local or remote updates and requires verification and authentication. It also includes authorized rollback.2 It does not establish protection of AI weights or select a cryptographic design for a specific device.

The threat model now includes physical access, extracted secrets, intermittent links, delayed revocation, limited storage, and lost telemetry. A hypothetical inspection camera may continue inference while disconnected, but it can accept only a signed model version and records enough state to reconcile after reconnection. A rollback also has to match the compatible software and data state. Edge operation changes location and connectivity. Federated learning changes who computes training updates and what the coordinator can inspect. Both changes reopen parts of the Chapter 1 system record, but neither requires the other.

Control review. The device boot and update service checks software and model identity, signature, compatible state, local authorization, and offline budget. It runs, holds, or restores the accepted package and records the decision for later reconciliation. Tests report rejected unauthorized packages over all attempted packages, bounded offline actions over all offline actions, and time to reconcile after reconnection. Secure storage, update capacity, and retained logs add hardware and operating cost. Extracted signing keys, damaged sensors, or full device compromise can defeat a control whose checks cover only specified physical attacks. Recovery enters the specified safe mode and restores a verified package. It rotates keys and reconciles records.

24.2 Federated learning security

Federated learning is training in which participants compute local updates and a coordinating process combines them. Raw training records can remain on participant devices. Client updates and participant selection still create disclosure and manipulation paths, as do aggregation and the resulting model.

McMahan and colleagues define Federated Averaging around a weighted record objective. Let client \(k\) hold \(n_k\) records and \(N=\sum_k n_k\). The objective is \(F(w)=\sum_k (n_k/N) F_k(w)\) where \(F_k\) averages loss over that client’s records.3 A server sends the current model \(w_t\) to selected clients. Each client runs \(E\) local epochs with batch size \(B\) and step \(w \leftarrow w - \eta_{\rm local} \nabla \ell(w, b)\). When \(B\) divides \(n_k\) the count is \(E n_k / B\) steps. The server then forms a weighted average of returned models. For full participation \(w_{t+1}=\sum_k (n_k/N) w_{t+1}^k\). With a sampled set \(S_t\) this chapter defines \(a_{k,t}=n_k/\sum_{j \in S_t} n_j\) for the worked example, and \(w_{t+1}=\sum_{k \in S_t} a_{k,t} w_{t+1}^k\). Equal client weighting changes the objective and does not check a reported count. Several local steps need not equal one global gradient step.

Secure aggregation is a protocol that reveals an allowed aggregate while hiding individual values beyond what that aggregate and any colluding set already reveal. Bonawitz and colleagues prove input privacy for two models. The honest-but-curious model needs \(c < t\) where \(c\) colluding clients help the server and \(t\) is the reconstruction threshold. The active model needs \(2t > n + c\) and assumes authenticated setup, signatures, and a consistency check plus random oracle and Two Oracle Diffie-Hellman assumptions.4 Completion with honest dropouts needs at least \(t\) clients to continue. Up to \(n-t\) nonresponders can be tolerated in that setting. Too few continuing clients cause abort. The protocol does not check that an update came from real training. The active proof shows privacy only. Correctness and availability can still fail when a participant sends an out of range value. Section 7 evaluates the honest-but-curious version and its dropout simulations. It does not measure the active variant. Secure aggregation also does not provide differential privacy for the sum or the released model. It does not detect a hidden malicious update.

Byzantine robust aggregation uses a rule designed to tolerate a bounded number of arbitrary participant updates. Blanchard and colleagues propose Krum. For \(n\) submitted vectors and a bound \(f\) it computes \(s(i)=\sum_{j \in N_i} \|v_i - v_j\|_2^2\) where \(N_i\) holds the \(n-f-2\) closest other vectors to \(v_i\) and returns \(v_{\arg\min_i s(i)}\).5 It returns one submitted vector. The selected vector may still be Byzantine. The resilience result needs a reliable server and synchronous round, independent and identically distributed unbiased estimates \(G\) of the same gradient with \(E\|G-g\|^2 = d\sigma^2\), arbitrary colluding Byzantine vectors, and

\[2f+2 < n \qquad \text{and} \qquad \eta(n,f)\sqrt{d}\,\sigma < \|g\|\]

where \(\eta(n,f)\) is a theorem constant distinct from a learning rate. Convergence needs further bounds on smoothness, moments, and step sizes. Several local epochs on different branch data do not satisfy this model by default. The count concerns the round’s \(n\), not the whole fleet.

Other rules use coordinate median and coordinate trimmed mean.6 Coordinate median takes the median per coordinate. Trimmed mean removes the largest and smallest \(\beta\) fraction per coordinate and averages the rest. The Yin and colleagues results assume \(m\) workers each with \(n\) independent records from one common distribution and fixed datasets across iterations. The server sees empirical gradients at one shared model, not multi epoch non independent updates. Median needs smoothness, bounded variance and skewness, strong convexity for some claims, and a finite sample margin \(\alpha + \sqrt{d\log(1+nm\hat L D)/(m(1-\alpha))} + 0.4748 S/\sqrt{n} \le 1/2 - \epsilon\) where \(\alpha\) is the Byzantine fraction. Trimmed mean needs sub exponential tails and \(\alpha \le \beta \le 1/2 - \epsilon\) plus similar smoothness and parameter space limits. These are error bounds, not proof of backdoor absence. They also trade learning quality. These methods are candidates to test against an expected attack, not proof that a hidden update is benign.

A model replacement attack scales a malicious local update to steer the next combined model. For \(G_t\) and target \(X\) the paper’s sum is \(G_{t+1}=G_t+(\eta/N)\sum_{i=1}^m (L_i^{t+1}-G_t)\) where \(m\) is the selected count and \(\eta\) is a global rate.7 When \(\eta=N/m\) the new model is the average of selected models. One attacker can aim for \(X\) with exact

\[\tilde L_m^{t+1}=G_t+(N/\eta)(X-G_t)-\sum_{i\ne m}(L_i^{t+1}-G_t)\]

The attacker often lacks the benign sum, so the practical form drops it

\[\tilde L_m^{t+1}\approx G_t+(N/\eta)(X-G_t) \qquad G_{t+1}=X+(\eta/N)\sum_{i\ne m}(L_i^{t+1}-G_t)\]

Scaling acts on \(X-G_t\), not on \(X\) alone. Replacement is approximate unless the benign residual is small. Near convergence that residual may partly cancel, but this is a setting dependent approximation, not an identity. Clipping, changed weights, nonlinear aggregation, rejection, or missing knowledge change the multiplier. In a weighted rule \(G_{t+1}=G_t+\eta_s\sum_i a_i\Delta_i\) the analogous form is \(\Delta_m \approx (X-G_t)/(\eta_s a_m)\). Bagdasaryan and colleagues evaluate this in two tasks. CIFAR-10 uses 100 total clients, 10 per round, a lightweight ResNet18, and two local epochs. Reddit word prediction uses 83293 retained participants, 100 per round, a two layer LSTM, and two local epochs. Single shot selection of one malicious participant can give a backdoor. Persistence varies by trigger and task. Those results apply to the tested models, data, aggregation, and attacker control of data and updates, not to every deployment. Secure aggregation is not needed for the algebra. It only removes server inspection of the individual update. Distributed computation changes which parties can see or change training, and the next section adds physical consequences to that trust problem.

Changed-assumption trace. The base training design assumes one controlled data store and one training operator. The hypothetical federated design changes the input path. Ten branches start from the same model version \(G_t\) and compute local updates. The exercise observer sees that nine branches submit updates near the prior direction while branch B7 submits a much larger change. Two coordinator views are distinct. If the coordinator receives individual updates it can record participant identity, update norm, pairwise distances, and apply a stated robust rule before forming \(G_{t+1}\). If it receives only a secure sum it sees the aggregate and participation record, so B7’s individual norm and pairwise distances are not available to that coordinator and ordinary Krum or coordinate checks cannot run on the sum alone. A hidden contribution bound or private robust aggregation would need a separate specified design and proof. In either view the observed result is a candidate model that needs normal task and backdoor evaluation before release. The ten branch values and the single large change are exercise assumptions.

Control review. The coordinator checks participant eligibility, round identity, submitted format, and candidate model tests before release. When individual updates are visible it can also check allowed contribution per participant and run the stated robust rule. When only a secure sum is visible those per update checks need an extra specified enforcement method. A compromised client can ignore a local clipping instruction. The coordinator either accepts the round or rejects the candidate. A rejection restores the prior model. Measures report accepted participants over all scheduled participants and rejected rounds over all rounds and security test failures over all candidate cases. An extra measure for the visible case is flagged large norms over all flagged large norms that the rule caught. A failed candidate test alone does not identify the responsible branch. Secure aggregation and repeated evaluation add communication and compute cost. Colluding participants, hidden malicious updates, or a test blind spot can defeat the design. Input privacy, robust optimization, and backdoor integrity do not imply each other. A private sum can still include a malicious value and a low loss model can still contain a targeted backdoor. Recovery discards the candidate and revokes identified participants where evidence supports it. Training resumes from the accepted model. A passed aggregate and test set do not prove that individual updates were benign or private outside the protocol assumptions.

24.3 Physical system effects

A model output becomes a safety concern when software can move equipment or alter a process. A cyber-physical system joins computing, communication, people, and physical components. An actuator changes the physical process. A safe state is a specified physical condition selected to limit harm after a fault or loss of control.

NIST describes operational technology as systems that detect or cause direct changes in physical devices, processes, and events. Such systems have distinct safety, reliability, availability, and performance requirements.8 Its guidance says safety-critical systems need detection of unsafe conditions, movement toward safe conditions, and often human oversight. It also discusses fail-to-a-known-state design and independent non-digital safeguards.9 These are general design considerations. Evidence for one architecture still requires system-specific tests.

In a hypothetical warehouse, an AI model may propose a route while a separate controller enforces speed, zone, load, and emergency-stop limits without depending on the model’s explanation. Tests include sensor failure, stale state, lost communication, and unsafe commands. Physical supervision makes time and authority limits visible, which prepares the analysis of agents that retain state across extended work.

Control review. The independent controller checks current sensor state, route command, speed, zone, load, and communication status. It allows a bounded motion or changes the command. An unsafe state moves the equipment to the specified safe state. Tests report blocked unsafe commands over all injected unsafe commands, mistaken stops over all allowed scenarios, and time to safe state. Independent hardware, validation, and downtime add cost. Shared sensors, common power loss, or a failed actuator can bypass the intended separation. Recovery isolates the equipment and uses the physical emergency path. Motion resumes only after a verified reset. These tests are part of a safety case, not proof of complete physical safety.

24.4 Long running agent limits

A short request ends when the response returns. A long-running agent retains state or authority across multiple tasks or an extended period. A stale permission no longer matches the current task, role, or risk. Reauthorization is a new decision that confirms or changes continued access or action authority.

OWASP’s agentic risk taxonomy separates identity and privilege abuse, memory and context poisoning, tool misuse, and cascading failures.10 Zero trust architecture bases access decisions on the subject, resource, and current context rather than network location alone.11 The taxonomy does not measure prevalence, and zero trust guidance does not set goal refresh or memory retention periods for AI agents.

The control loop binds credentials, memory, remaining budget, and allowed actions to a current task state. Time expiry, role change, unexpected resource growth, or a new action class can trigger reauthorization. The packet contains no peer-reviewed or standards-based evaluation that establishes the right intervals, memory expiration, or resource caps. Those values remain hypotheses for system-specific testing. Delegation across multiple agents adds message and conflict problems to the same state-management challenge.

Changed-assumption trace. The earlier assistant handled one request with credentials that expired after the response. The hypothetical long-running version works for eight hours, retains a task queue, and can create support tickets. At hour four, the employee changes role and loses access to customer C44. The agent’s next step attempts to reuse the earlier customer context. The authorization service checks the current employee role and rejects the customer access. It removes the queued action and records the stale context reference. The observed result is a denied action rather than a carried-over permission. The four-hour point and eight-hour duration are test values. They do not establish suitable intervals for another system.

Control review. The authorization service checks the current employee role, task state, retained context, credential age, action class, and remaining resource budget before each consequential step. It permits, changes, or stops the step and records discarded state. Tests report denied stale actions over all stale-action attempts, orphaned tasks over all interrupted tasks, and cleanup time. Reauthorization and state review add latency and storage work. An alternate tool path, shared token, or hidden memory store can bypass the loop, and the test cannot establish the right reauthorization interval for another workload. Recovery revokes credentials and clears or quarantines retained state. Work restarts from an approved checkpoint.

24.5 Multi agent delegation

A multi-agent design divides work among several software actors. A delegation chain records how one actor grants another limited authority. An inter-agent message encodes information, a request, or an instruction sent between agents. Conflicting authority exists when two instructions or permissions cannot both be followed safely.

OWASP’s agentic taxonomy includes insecure inter-agent communication and cascading failures alongside identity, privilege, and memory risks.12 CSF 2.0 calls for service identities and credentials to be managed and for permissions and authorizations to be defined, enforced, reviewed, and separated by duty.13 These sources do not establish a standard multi-agent architecture or resolve conflicting goals and message meaning.

The system needs authenticated senders and typed messages. Bounded delegation and conflict rules constrain behavior. Separate action authorization limits the resulting operations. Records connect a final action to its delegation chain. A hypothetical research agent can ask a retrieval agent for documents but cannot transfer its own write permission. The packet still lacks a primary specification or evaluated system covering authentication, delegation, conflict, and audit assumptions together. This distributed uncertainty provides a contrast for frontier release decisions.

Control review. The message gateway checks sender identity, message type, task identifier, delegated rights, expiry, and conflict state. The action service then checks the final operation against the complete delegation chain. It permits, rejects, or escalates the request. Tests report rejected forged messages over all forged cases and blocked excess rights over all delegation attempts. Signing, policy checks, and trace storage add latency and compute cost. Shared credentials, colluding agents, or ambiguous message meaning can defeat parts of the scheme. Because these checks do not prove that the agents share a correct goal, recovery stops the chain and revokes delegated credentials. It restores the last accepted task state and replays the trace.

24.6 Frontier release decisions

Past test results become weaker evidence when a model’s capabilities, access, or deployment scale move beyond the evaluated range. In the Seoul commitments, frontier AI refers to highly capable general-purpose models or systems near the most advanced capability level.14 Systemic risk is a legal or governance category whose meaning depends on the controlling source.

The 2024 Seoul commitments ask participating organizations to assess severe risks across the lifecycle, define assessable thresholds, specify mitigations, and avoid development or deployment when residual risk cannot be kept below those thresholds.15 These voluntary commitments have no legal force, and publication does not show that each organization carried out the commitments. The European Commission states that the Safety and Security chapter of the General-Purpose AI Code of Practice applies only to providers of general-purpose AI models with systemic risk under Article 55.16 The code is voluntary, while binding duties come from the AI Act.

A release record connects capability evidence, attacker access, misuse tests, safeguard results, deployment scale, and uncertainty to a release threshold. Public frontier evaluation programs group tests around cyber capability, chemical and biological work, autonomy or self-replication, safeguard bypass, and behavior that can invalidate an evaluation.17 A result in one category remains tied to its elicitation method, tools, human baseline, stopping conditions, and protected test environment. No universal capability threshold or reliable rule for extending laboratory results to every deployment was found in the packet. The decision remains specific to the organization, model, use, law, and available evidence. The final whole-system decision retains these changed assumptions and unresolved evidence.

Release control. The release authority checks each specified capability threshold, attacker-access condition, safeguard result, deployment scale, legal duty, and unresolved uncertainty. It either allows a restricted stage or holds release. An active deployment can also be stopped. Coverage is supported release claims divided by all claims required for the decision, with failed and missing evidence retained. Evaluation, restricted staging, and rollback capacity consume substantial staff and compute. Unknown capabilities, weak tests, or access outside the staged boundary can defeat the decision. Because meeting the selected thresholds does not prove that every severe risk is absent, recovery withdraws access and restores the last accepted model and system configuration. The assessment then reopens.

Assumption-change record. The table compares the changed assumptions and their effects. Each row states an earlier assumption and one changed operating condition. It also identifies the evidence that must be renewed.

Chapter checkpoint. A read-only assistant is changed into a long-running agent that retains customer context and can create tickets. Which earlier claims become stale before any test runs?

Answer. The request boundary, credential lifetime, memory boundary, action authority, resource limit, monitoring period, and recovery claim all change. Earlier answer-quality evidence may still describe the model on the old task, but it does not support the new persistence or ticket action. The new evaluation must cover changed roles and stale context, then action authorization and resource growth. It must also cover interruption and state cleanup under stated time limits.
