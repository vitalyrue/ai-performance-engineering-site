Mathematical Foundations of LLM Training and Inference

Author

Vitaly Rubinovich

A language model’s behavior depends on calculations you can inspect: how text becomes numbers, how errors change weights, and how a trained model produces an answer. This book develops the mathematical foundations of large language models through small examples and computational labs. It helps you connect those calculations to practical decisions about model quality, adaptation, memory, and inference.

Contents

Front matter

  • Models, tasks, and learning
    A model output needs a defined task and success criterion, with inference, training, and evaluation serving different roles.
  • Roadmap
    Reading routes need the assumed starting knowledge and the teaching dependencies made explicit.
  • Notation
    Recurring symbols and dimensions need local meanings and compatible orientation and mask conventions.
  • Library Map
    Library operations need links to their mathematical roles, executable examples, and full experiment requirements.

Part I: From Text to Mathematical Objects

Text needs task-specific targets and numerical representations before a model can calculate predictions.

  • Chapter 1: Prediction targets and training pairs
    Training requires inputs paired with reference answers and a rule for combining their prediction errors.
  • Chapter 2: Token IDs and batches
    Text pieces need consistent integer IDs and a batch layout that distinguishes retained tokens from added positions.
  • Chapter 3: Subwords and sequence counts
    Reusable subword pieces balance vocabulary size against sequence length, while continuation counts supply a fixed-history prediction baseline.
  • Chapter 4: Count vectors and TF-IDF
    Document terms need shared feature coordinates before the same classifier weights can score texts of different lengths.

Part II: From Scores to Loss

Model scores need probability, loss, and evaluation rules before their predictions can be judged.

  • Chapter 5: Linear models
    Weighted feature contributions define predictions and decision boundaries whose local sensitivity guides small parameter changes.
  • Chapter 6: From scores to probabilities
    Real-valued scores need probability transformations with the appropriate range and normalization.
  • Chapter 7: Decoding strategies
    Next-token probabilities need a selection rule and repeated feedback to produce a generated sequence with fixed parameters.
  • Chapter 8: Cross-entropy and perplexity
    Assigned target probabilities need a logarithmic loss and an explicit inclusion rule before they can be averaged or summarized by perplexity.
  • Chapter 9: Validation and testing
    Performance on new inputs needs held-out examples, task-appropriate metrics, and development choices separated from final testing.

Part III: From Error to Learning

A loss needs gradients, update rules, and useful representations to guide parameter learning.

  • Chapter 10: Optimization and regularization
    Gradients need an update rule, a step size, and a controlled comparison before they can guide useful training choices.
  • Chapter 11: Backpropagation
    Parameter gradients need all contributing derivative paths before an optimizer can apply a consistent update.
  • Chapter 12: Activation functions
    Patterns that one affine boundary cannot separate need nonlinear hidden features before a final classifier can distinguish them.
  • Chapter 13: Embedding tables
    Integer token IDs need trainable vector rows and valid-position aggregation before they can supply numerical representations.
  • Chapter 14: Word vectors from context
    Token vectors need a context-prediction objective to acquire relationships that can be inspected and evaluated.

Part IV: Modeling Sequences

Sequence models need an explicit way to use context while keeping prediction targets outside the visible input.

  • Chapter 15: Recurrent networks: Context, state, and sequential computation
    Sequence predictions need aligned targets and a state mechanism that can carry information beyond a fixed token history.
  • Chapter 16: Attention mathematics
    A position needs a defined set of readable vectors and normalized comparison weights before attention can combine their content.
  • Chapter 17: Transformer blocks: Context, features, and position
    Attention outputs need compatible feature transformations, residual paths, normalization, and position information to form deeper sequence models.
  • Chapter 18: Transformer families: Visibility, targets, and generation
    Different sequence tasks need visibility rules, prediction targets, and generation procedures that agree with the available inputs.
  • Chapter 19: Pretraining data and compute allocation
    Pretraining records need selection, boundary-preserving preparation, and compute allocation that agree with the intended objective.

Part V: Adapting and Running LLMs

A pretrained model needs task evidence and resource measurements to guide adaptation and generation choices.

  • Chapter 20: Model adaptation: Context, preferences, and trainable weights
    Task adaptation needs a choice between changing context and changing parameters, with the training objective separated from the trainable state and weight format.
  • Chapter 21: KV cache: Generation state, latency, and allocation
    Generation needs consistent token and cache state, allocation, and scheduling before its memory and request latency can be assessed.

Part VI: Implementation and Extensions

Other input types, tensor storage, and experiments need separate checks of representation, execution, and task evidence.

  • Chapter 22: Images, audio, and tables: Representations and tasks
    Images, audio, and table fields need representations that preserve the structure required by their distinct output tasks.
  • Chapter 23: Tensor storage: Shapes, views, devices, and lifetime
    Tensor memory and execution claims need storage, layout, numerical type, device, and state lifetime beyond logical shape.
  • Chapter 24: Computational labs: Checks, experiments, and evidence
    Experiments need declared data, fitting procedures, and held-out evidence in addition to local arithmetic and interface checks.
