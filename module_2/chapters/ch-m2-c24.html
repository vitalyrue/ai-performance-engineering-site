24  Computational labs: Checks, experiments, and evidence

Experiments need declared data, fitting procedures, and held-out evidence in addition to local arithmetic and interface checks.

A correct tensor shape does not establish correct gradients, useful predictions, or faster execution. Local calculations isolate those mechanics. A full experiment additionally needs its data, fitting procedure, and held-out results. Keeping those evidence types separate makes a failed comparison easier to diagnose.

A small tensor check can run without the complete dataset or training budget of a full experiment. The supporting notebooks contain larger cases. The protocols below extract the decisions that determine whether their results can be interpreted: data boundaries, preprocessing, initialization, computation budget, metrics, and retained evidence.

Environment and supporting notebooks

An experiment cannot be reproduced from a model name and final score alone. Its record needs the Python and package versions, operating system, device, driver and accelerator runtime when used, seeds, and numerical types. Retain model and tokenizer revisions, data version, split construction, preprocessing, training settings, and decoding choices. A seed does not guarantee identical results across different hardware or kernels.

The downloadable notebooks are unchanged snapshots of the supplied files. Their outputs are historical source results, not results of the code in this book. Open them in an existing compatible notebook environment and inspect dependencies before execution. A package installed for one notebook does not establish compatibility with every other model path.

The local tensor checks use PyTorch 2.12 with ordinary float32 CPU defaults, except where their code selects a type or device. They need no large model downloads. Full experiments may require datasets, pretrained weights, network access, or supported accelerator hardware. When unavailable, retain the failed step and its cause as unexecuted work rather than substituting a toy result.

Each experiment record should connect inputs, intermediate values, parameter changes, metrics, and errors. A trace is this ordered account of a computation’s values and state changes. Its implementation mapping relates mathematical objects to code objects, axes, dtype, and device. Retain the outputs, relevant plots, and explanations. Give each plot a title and label every curve or point group. Comparisons need common axis scales. An unavailable or unexecuted branch remains unexecuted evidence. These records make the conclusion traceable to the experiment that supports it.

The PyTorch basics notebook supplies tensor creation, seeds, indexing, and reshaping practice. Its recorded sequence uses seed 8436, Gaussian samples with mean zero and standard deviation two, uniform samples from negative two to two, and 500 Poisson draws with rate one. Reproducing a later random sample requires the preceding draws as well as the seed because each draw advances the generator state. Its torch.Tensor(1000) allocation is uninitialized and must be filled before its values are used. A ten-bin histogram over values from zero through ten displays only the draws in that range. The Poisson distribution can still produce larger values. These are array-generation checks, not measured neural initialization results.

The gradient source notebook connects hand calculations to logistic fitting. The word-embedding source notebook describes fitting CBOW vectors with min_count=100, window=5, and vector_size=100 on roughly 25,000 computational-linguistics abstracts collected before mid-April 2021. Its /content/arxiv.csv corpus is not bundled, so reproducing the recorded neighbors requires that data or a declared replacement. Its inspection prompts compare nmt with smt and ner, retrieve neighbors of bert, query transformer + lstm - bert, and compare tree with tree - syntax. Record the corpus, preprocessing, vocabulary, Gensim version, settings, query, and seed with any result. The separate three-sentence check in §14.1 uses Gensim 4.4.0, Skip-gram, and supplied local text.

An accelerator comparison first needs to establish which device can run the calculation. In the optional GPU notebook, check torch.cuda.is_available() and torch.cuda.device_count() before choosing a CUDA device. For a selected available device, record get_device_name(device), get_device_capability(device), and memory_allocated(device) from torch.cuda. These report the hardware name, compute-capability version, and bytes currently allocated to tensors. Compute capability identifies a CUDA hardware feature version used to check instruction and compiled-kernel compatibility. It is not a measured speed or a count of cores. They are separate from total device memory. If CUDA is unavailable, record that condition and use a declared CPU comparison or leave the accelerator run unexecuted.

The matrix-vector workload uses a float32 matrix with 100,000 rows and 100 columns, and a vector of width 100. The PyTorch and NumPy timing cells specify 100 loops and three repeats. The NumPy inputs are copied to the CPU before its timed np.dot call. The notebook reports historical ratios of about nine for an earlier comparison compiled with Numba, a Python compiler for numerical functions, and about 100 for PyTorch against NumPy. These ratios describe that hardware and measurement setup. A new result requires the synchronization, transfer boundary, and repeated-accumulation checks in §23.6. The notebook also contains kernel implementations for separate study. Kernel tuning is outside the scope of this book.

24.1 Logistic regression and controlled optimizer comparisons

A classifier experiment needs an update that matches its loss before optimizer settings can be compared. The local check isolates two feature rows. The logistic regression and optimizer lab then extends that calculation to SST-2 sentiment data and controlled training comparisons.

For one binary logit per row, the shape contract is

\[ X\in\mathbb{R}^{B\times F},\quad w\in\mathbb{R}^{F},\quad z=Xw+b\in\mathbb{R}^{B} \tag{24.1}\]

Here \(X\) has \(B\) example rows and \(F\) features, \(w\) has width \(F\), and scalar \(b\) is shared. With \(B=2,F=5\), the product gives two logits. That shape example is separate from the two-feature code below.

For labels \(y_i\in\{0,1\}\) and positive probabilities \(p_i=\sigma(z_i)\), the mean objective is

\[ L=-\frac{1}{B}\sum_{i=1}^{B}\left[y_i\log p_i+(1-y_i)\log(1-p_i)\right],\quad p_i=\sigma(z_i) \tag{24.2}\]

The divisor requires \(B>0\). Labels \((1,0)\) and probabilities \((0.8,0.25)\) give \([-\log0.8-\log0.75]/2\approx0.255413\) nats, or 0.255. The second target uses the negative-class probability. The stable library call receives logits, not thresholded decisions.

The runnable local code computes logits, loss, and gradients without applying an optimizer step.

Code example: Logistic-regression forward, loss, and backward checks

import torch

# Rows are examples; columns are features.
X = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
y = torch.tensor([1.0, 0.0])
w = torch.tensor([0.2, -0.1], requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

# The affine score is the logistic-regression logit.
logits = X @ w + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(logits, y)
loss.backward()
assert logits.shape == (2,)
assert w.grad.shape == w.shape

Its logits are \((0.2,-0.1)\). Their probabilities are approximately \((0.549834,0.475021)\), and the mean loss is approximately 0.621268. The manual mean weight gradient is \((p-y)/2\approx(-0.225083,0.237510)\) because \(X\) is the identity. The bias gradient sums those entries, giving approximately 0.012427.

Compare these derivatives with .grad using an appropriate floating-point tolerance. A separate plain-SGD check at rate 0.1 would give weights approximately \((0.222508,-0.123751)\) and bias \(-0.001243\). It needs an actual update and a new forward call. The existing assertions check shapes, not those values or an update.

Conclusion: The supplied example makes gradient signs and the mean divisor inspectable. It cannot establish convergence or sentiment quality.

The gradient notebook supplies an intermediate experiment before the text classifier. It generates 1,000 two-dimensional examples around centers [-3,-3] and [0,0], with cluster_std=1.25. Convert features to float32 and labels to a [1000,1] column. A [2,1] weight column and shared bias produce one probability per row. First compare the prediction surfaces for different weights and biases. Set both weight entries to 1 while retaining the current bias, then set the bias to 3. Compare equal weight entries of 0.33 with bias 1 against equal weight entries of 5 with bias 15. Retain each prediction surface beside the reference labels. Restore parameters that record gradients before fitting. Record the data-generation and parameter-initialization seeds.

Use up to 1,000 full-data updates at rate 0.1. Store the loss before each update, change weights and bias under torch.no_grad(), clear both gradient buffers, and record every twentieth loop index. With stopping threshold 1e-5, first require finite losses and at least two recorded values. Stop only when the nonnegative improvement satisfies \(0\leq L_{t-1}-L_t<10^{-5}\). Record an increase or nonfinite value as a separate diagnostic event. Calculate the stable loss from logits as in §8.1 rather than taking logs of rounded sigmoid probabilities.

Plot the loss history against the update index, then recalculate predictions from the final parameters before the classification report and accuracy calculation. Use one declared threshold convention throughout, including equality at 0.5. The quantity exp(-mean log-loss) is the geometric mean of the reference-class probabilities. Their arithmetic mean is at least as large, with equality when all those probabilities are equal. State which summary a reported value represents.

This experiment connects a checked gradient to a complete fitting loop and its final metrics. The sentiment experiment adds sparse text features, mini-batches, and validation comparisons. The following protocol defines the larger comparison.

The larger comparison uses the fixed SetFit/sst2 revision and its training and validation splits. Apply one recorded cleaning rule to both splits, fit the vocabulary on training text only, and transform validation text with that saved vocabulary. The notebook’s rule lowercases text, replaces hyphens with spaces, retains ASCII letters, digits, whitespace, and . , ! ?, then collapses repeated whitespace. Because splitting occurs on whitespace, good! and good remain different tokens. Record split sizes and class proportions before fitting. A sparse bag-of-words representation can retain up to 10,000 frequent training tokens. Corpus frequency determines which entries enter the vocabulary, while each document stores its own counts. With vocabulary [movie,good,bad], good movie good becomes [1,2,0].

The one-output sigmoid formulation and the two-class softmax formulation should agree on their binary decisions when they use corresponding parameters and the same threshold convention. Compare both tensor calculations with stable library losses and derivatives. A decision rule such as p >= 0.5 affects reported classes, while the training objective still uses probabilities or logits. The comparison should expose where a naive logarithm or exponential fails and why subtracting the largest logit preserves the softmax probabilities.

Initialization and array orientation are separate experimental choices. Record whether weights begin at zero, from a small random distribution, or from a supplied tensor, together with their seed, type, and shape. A [F,1] weight column and an [F] weight vector return differently shaped logits, so outputs and targets must follow the chosen convention. Mini-batch fitting should shuffle training rows, keep the full feature matrix sparse, and convert only a selected batch when a dense tensor is required. Preserve independent parameter snapshots and per-epoch training and validation measures. Report prediction loss separately from an objective that includes a penalty.

A controlled search crosses learning rates [0.01, 0.03, 0.1, 0.3, 1.0] with batch sizes [50, 100, 200]. The resulting 15 runs need a common update budget, metric, and validation rule, with failures retained rather than removed. A matched table or heatmap can then show which settings converge, diverge, or remain unstable without implying that the best observed setting is universal.

The L1 comparison keeps rate and batch size fixed while varying penalty strength across [0, 1e-4, 1e-3, 1e-2, 1e-1]. Count coefficients under one declared tolerance and retain validation outcomes beside training measures. Ordinary subgradient SGD can cross zero without producing exact zeros, so coefficient sparsity must be measured rather than inferred from the presence of an L1 term. A separate proximal-L1 comparison uses the soft-thresholding rule from §10.6 and answers a different question about exact zeros.

Optimizer behavior can be isolated on the bowl \(x^2+4y^2\) and the six-hump camel function \(f(x,y)=(4-2.1x^2+x^4/3)x^2+xy+(-4+4y^2)y^2\). The second surface has two global minima near \((0.0898,-0.7126)\) and \((-0.0898,0.7126)\), with value about \(-1.0316\), as well as other local minima. GD, Momentum, AdaGrad, and Adam should begin from the same declared point within a comparison and use matched budgets and display axes. Their parameter paths, objective histories, oscillation, and local-minimum behavior show why the observed results differ, without supporting a universal winner.

In float32, \(1-10^{-15}\) rounds to one, so probability clamping at that epsilon still permits \(\log0\). Calculate binary loss from logits with a stable expression, such as \(\log(1+e^z)-yz\) evaluated through a stable log-sum operation, and compare against §8.1. Keep the full count-feature matrix sparse. A mostly zero dense array still allocates its zero entries.

Match the coordinate-grid axes to the objective function’s indexing. The camel surface can fall below \(-1\), where log1p is undefined, so use raw contours or a display transformation defined over the whole plotted range. Pair each stored loss with the parameters that produced it. When recording post-update parameters, recompute their loss or label the stored loss as pre-update. Sample row indices from \(0\) through \(n-1\) with the upper bound \(n\) excluded.

Use validation evidence to compare settings. Keep any final test separate from those decisions. The same gradient and evidence checks can now support a comparison of text representations.

24.2 Tokenizer, embedding, and classifier comparisons

A better nearest-neighbor display need not improve news classification. The AG News classification lab compares representations through a classifier while retaining the official test set for final evaluation. For this lab, use fancyzhx/ag_news and pass the revision in the dataset reference to load_dataset. This snapshot has 120,000 training records and 7,600 test records. Each record has a text string and a label: 0 for World, 1 for Sports, 2 for Business, or 3 for Sci/Tech.1

The runnable local check starts with two equal-length, already supplied token-vector sequences. It averages each sequence, then applies a random MLP to four class logits.

Code example: Pooled token vectors and four-class MLP logits

import torch
import torch.nn as nn

# A real run obtains these token vectors from the trained Word2Vec model.
token_vectors = torch.tensor([
    [[1.0, 0.0, 0.5], [0.5, 1.0, 0.0]],
    [[0.0, 1.0, 0.5], [1.0, 0.5, 0.0]],
])
article_vectors = token_vectors.mean(dim=1)
classifier = nn.Sequential(nn.Linear(3, 8), nn.ReLU(), nn.Linear(8, 4))
labels = torch.tensor([0, 2])

logits = classifier(article_vectors)
loss = nn.CrossEntropyLoss()(logits, labels)
assert article_vectors.shape == (2, 3)
assert logits.shape == (2, 4)
print(loss.item())

The document vectors are [[0.75,0.5,0.25],[0.5,0.75,0.25]], with shape [2,3]. The logits have shape [2,4], and loss is scalar. Random head weights make its value variable. There is no padding here. Unequal sequences need masked pooling or another justified aggregation policy.

Conclusion: The check joins a supplied representation to an MLP loss. It neither learns embeddings nor evaluates a news classifier. The full comparison preserves these requirements:

Keep AG News’s official test split untouched and form any validation subset from training data. Inspect the text and label fields and record split sizes before fitting. Preprocessing, tokenizers, and word vectors use training text only. The four reference categories remain World, Sports, Business, and Sci/Tech under the dataset’s recorded integer mapping.

BPE and WordPiece can use the same example vocabulary budget, such as 10,000 entries, while producing different segmentations and unknown-token behavior. Compare their token sequences and lengths on the same sentences, including unfamiliar words, before choosing one for the classifier. The fitted tokenizer and its preprocessing must be saved together so later comparisons use the same mapping.

Skip-gram and CBOW can then be compared at widths 50, 100, and 200 using the same tokenized training text. Record the actual learned vocabulary because a tokenizer entry may be excluded when its embedding-training frequency is below min_count. Neighbor queries such as movie, sport, and market can expose local vector behavior, including a query absent from the learned vocabulary. They do not establish which representation improves classification. When classification is the selection criterion, compare the candidate embeddings on development data under the same classifier and computation budget.

Mean, sum, max, or another declared pooling rule converts a variable-length token sequence into a fixed-width document vector. The rule must specify missing vectors and empty inputs. A multilayer classifier can consume the pooled vector, but the pooling discards some or all word-order information. Width, activation, optimizer, rate, batch size, and training duration therefore belong in the experiment record rather than being inferred from the representation alone.

After development choices are fixed, evaluate once on the official test split. Retain accuracy, a labeled confusion matrix, and error records containing the text, reference category, and prediction. An attribution method can support diagnosis if its scope is stated, but the prediction and held-out evidence remain valid even when no attribution method is added.

A batch loss is commonly already a mean. To report an epoch mean, multiply each batch mean by its included example count, sum those products, and divide by the total count. Averaging batch means equally gives a shorter final batch too much weight. Training-batch losses also come from changing parameter versions. To measure one checkpoint’s performance, evaluate that fixed checkpoint over the relevant split with gradients disabled and evaluation mode enabled.

An attribution assigns parts of an input a measured contribution under a specified comparison. One possible method keeps the classifier fixed, records its probability for a selected class, then removes one token and recomputes the representation and the same class probability. A drop from 0.80 to 0.55 gives a contribution of 0.25 under that removal. Repeat separately for each position. Removing a token also changes a mean-pooling denominator, so the comparison measures the whole removal operation. Interactions mean these contributions need not add to the original score, and they do not establish a real-world causal effect.

The tokenizers library supplies complete vocabulary trainers for the algorithm comparison. The following offline example uses version 0.22.2, a three-sentence corpus, Whitespace pre-tokenization, and a BPE vocabulary limit of 50. It adds a WordPiece trainer on the same text. These small settings demonstrate the API before the full AG News experiment.

Code example: Training BPE and WordPiece on the same small corpus

import json
from tokenizers import Tokenizer
from tokenizers.models import BPE, WordPiece
from tokenizers.trainers import BpeTrainer, WordPieceTrainer
from tokenizers.pre_tokenizers import Whitespace
corpus = ["I love natural language processing", "Tokenization is important", "BPE builds subword units"]
for name, model, trainer in [
    ("BPE", BPE(unk_token="[UNK]"), BpeTrainer(vocab_size=50, special_tokens=["[UNK]"], show_progress=False)),
    ("WordPiece", WordPiece(unk_token="[UNK]"), WordPieceTrainer(vocab_size=50, special_tokens=["[UNK]"], show_progress=False)),
]:
    tokenizer = Tokenizer(model)
    tokenizer.pre_tokenizer = Whitespace()
    tokenizer.train_from_iterator(corpus, trainer)
    print(json.dumps({"model": name, "vocab_size": tokenizer.get_vocab_size(), "unk_id": tokenizer.token_to_id("[UNK]"), "unhappiness": tokenizer.encode("unhappiness").tokens, "training_sentence": tokenizer.encode(corpus[0]).tokens}))

Tokenizer combines a model with preprocessing, and train_from_iterator fits its vocabulary from the supplied strings. Each trainer reserves [UNK]. The printed records identify the fitted vocabulary size, unknown-token ID, and encoded pieces. In this run both vocabularies contain 50 entries and assign ID 0 to [UNK].

The test word unhappiness contains h, which is absent from this training corpus. BPE retains the known pieces around an unknown marker. WordPiece returns one [UNK] for the whole word under its policy. Repeated WordPiece fits on this tiny corpus produced different vocabularies, so an exact piece sequence must be tied to its fitted tokenizer. Use tokenizer.save(path) to retain the vocabulary, model rules, and preprocessing together before further comparisons.

Conclusion: Both trainers produce reusable tokenizers from the same training text, but their unknown-word handling differs. A small vocabulary trace establishes how to run the comparison, while the full experiment measures whether the representation helps classification.

Retain training histories and the representation settings beside downstream results. Source-vector arithmetic and projection plots from Chapter 14 remain diagnostic evidence, not substitutes for classification evaluation.

24.3 Attention under a controlled input change

Changing a word while redrawing every input vector would confound a claimed word-specific effect. A controlled attention comparison uses the same representation mapping and projection matrices, then changes only the intended input.

The attention and fine-tuning notebook uses the cat sat on the mat at width 16 for its example attention calculation, then replaces cat with dog to compare the outputs. These settings illustrate the experiment. The attention calculation must still work for other inputs and widths.

Use the one-head scaled-attention calculation from §16.1. Queries \(Q\) index updated positions, keys \(K\) index readable positions, and values \(V\) supply the mixed content. Width \(d_k\) scales dot products. The additive mask \(M^{\mathrm{attn}}\) blocks disallowed pairs before softmax, and \(O\) contains outputs. With coefficients \((0.25,0.75)\) and scalar values \((2,6)\), the output is \(0.25(2)+0.75(6)=5\).

The runnable local code supplies projected arrays directly and applies a causal mask. It does not construct representations of actual words.

Code example: Scaled attention values and row-normalization checks

import torch

# Two query positions, two key positions, and scalar values.
Q = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
K = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
V = torch.tensor([[2.0], [6.0]])
scale = Q.shape[-1] ** 0.5
scores = Q @ K.T / scale
causal_mask = torch.triu(torch.full_like(scores, float("-inf")), diagonal=1)
masked_scores = scores + causal_mask
weights = torch.softmax(masked_scores, dim=-1)
output = weights @ V
assert scores.shape == (2, 2)
assert output.shape == (2, 1)
assert weights[0, 1].item() == 0.0
assert torch.allclose(weights.sum(dim=-1), torch.ones(2))

The unmasked score matrix is diagonal with entries \(1/\sqrt2\approx0.707107\). Its masked first row has only the first key available, giving weights \((1,0)\) and output 2. The second row gives weights approximately \((0.330238,0.669762)\) and output 4.679046. These values complement the code’s shape, masked-zero, and row-sum checks.

Conclusion: The first query excludes the future value, while the second mixes both. Row normalization applies only when at least one allowed finite score exists. A fully blocked row needs rejection, skipping, or a declared handling policy before normalization.

For the complete notebook task:

The trace retains the token representations and the query, key, and value projection matrices. It records unmasked scores, the mask, masked scores, normalized weights, and output vectors, with query rows and key columns aligned to token positions. Selected values should agree with an independent manual or trusted-library calculation before the heatmap is interpreted.

A controlled input change replaces one content word while keeping the representation rule and every projection fixed. Comparing the changed token’s projected vectors, the affected score row and column, and the downstream outputs identifies the numerical effect. A linguistic explanation remains a hypothesis unless another controlled comparison supports it.

Multiple heads require independently projected queries, keys, and values. Comparing at least two such heads under the same input change can show different weight patterns. Repeating one projection under two labels would only duplicate the same calculation. The recorded arrays can answer whether the word change affected the weights and whether the heads differ, but a heatmap alone does not prove why the model produced a prediction.

This task isolates representation changes. Adapter training additionally needs evidence of which parameters changed and whether held-out answers improved.

24.4 Audience adaptation with two model families

An adapter parameter count does not establish that an answer suits its intended audience. The fine-tuning notebook requires response-level comparisons for both a causal model and an encoder-decoder model. Their target layouts and adapter targets differ.

The local runnable check counts the factor parameters and tests the first gradient. A separate assertion reconstructs an affine-quantized value. It does not load or train a model.

Code example: LoRA parameter count, usable initialization, and affine dequantization checks

import torch

# A frozen 4 by 4 weight receives a rank-1 update.
d_in, d_out, rank = 4, 4, 1
A = torch.tensor([[1.0, -1.0, 2.0, 0.5]], requires_grad=True)
B = torch.zeros(d_out, rank, requires_grad=True)
trainable = A.numel() + B.numel()
assert trainable == rank * (d_in + d_out)

# A nonzero first factor and zero second factor preserve the base output.
x = torch.tensor([1.0, 2.0, 3.0, 4.0])
delta = B @ (A @ x)
assert torch.allclose(delta, torch.zeros(d_out))
delta.sum().backward()
assert torch.count_nonzero(B.grad) > 0
assert torch.count_nonzero(A.grad) == 0

# Affine quantization reconstructs a value from an integer code.
scale, q, zero_point = 0.1, 13, 3
x_hat = scale * (q - zero_point)
assert x_hat == 1.0

The four-by-four, width-one factors contain \(1(4)+4(1)=8\) trainable values. The chosen nonzero \(A\) and zero \(B\) make the initial adapter output zero. For the supplied input, \(Ax=7\), so a summed-output gradient reaches \(B\) while the gradient of \(A\) is initially zero. After \(B\) changes, a later update can also reach \(A\). §20.4 explains this initialization rule in the full layer.

The separate reconstruction gives \(0.1(13-3)=1.0\). This is affine integer quantization, not an NF4 codebook calculation. Neither assertion measures memory allocated by a quantized model or a completed update.

Conclusion: The snippet establishes eight trainable factor values and a viable first gradient. It also checks one reconstruction rule. The adaptation experiment needs these additional steps:

A Dolly 15K subset provides questions whose answers can be adapted for child, student, and expert audiences. Preserve the dataset revision and the rule used to select rows. The source notebook’s first-5,000-row selection and its keyword filter are examples of bounded sampling, not universal requirements. Inspect the resulting fields and row counts, including an empty selection, before generating training records.

Each selected question needs three answers that differ by audience rather than length alone. A child answer uses simple, intuitive language. A student answer adds moderate technical detail, while an expert answer is precise and specific to the subject. The source answer must be checked for correctness and suitability before it is rewritten. A separately reviewed held-out set should cover all three levels; the source notebook’s budget of 20 total cases is an inspection set, not a dependable population estimate.

Whatever storage format is used, validate the question, audience level, all answer fields, serialization, reload, and formatting on a small batch before fitting. Held-out questions stay outside training and development choices. A causal model can place question, audience level, and answer in one sequence with a response-target mask. An encoder-decoder model instead places the question and level in the source and the answer in the target. Padding and target alignment must follow the selected model interface.

The comparison uses HuggingFaceTB/SmolLM2-360M-Instruct and google/flan-t5-small as two model families. Four-bit loading and LoRA require separate hardware, numerical-format, adapter-target, and trainable-parameter checks for each architecture. A causal q_proj/v_proj fragment is not an encoder-decoder configuration. Unsupported paths remain unexecuted evidence rather than implied results.

Compare each base and adapted model on the same held-out questions and recorded generation settings. Keep the question, requested audience, reference answer, base output, adapted output, audience fit, clarity, relevance, and source faithfulness together. Apply the hallucination and source-faithfulness criteria from §9.4, separating unsupported or contradictory claims from formatting errors and incomplete answers. Interpret observed changes beside training cost, stored base and adapter payloads, peak memory, rank, and the distinction between prompting, LoRA, and QLoRA.

A limited training run may test an environment, but must be labeled with its actual budget. Report which model paths and held-out cases actually ran.

24.5 Character names, shifted targets, and generation feedback

A generated character must become the next recurrent input while the corresponding state is carried forward. The Character LSTM lab trains a dinosaur-name model and compares generation choices. It shares a supporting notebook with the AG News classification lab in §24.2. The small check below only calculates candidates from an untrained network.

Code example: Untrained character LSTM states and top-k candidate probabilities

import torch
import torch.nn as nn

vocab_size, hidden_width = 6, 8
inputs = torch.nn.functional.one_hot(
    torch.tensor([[0, 1, 2]]),
    vocab_size,
).float()
lstm = nn.LSTM(vocab_size, hidden_width, batch_first=True)
output_head = nn.Linear(hidden_width, vocab_size)

states, recurrent_state = lstm(inputs)
logits = output_head(states[:, -1])
top_values, top_ids = torch.topk(logits, k=3, dim=-1)
probabilities = torch.softmax(top_values, dim=-1)

assert states.shape == (1, 3, hidden_width)
assert top_ids.shape == (1, 3)
print(top_ids, probabilities)

One-hot input has shape [1,3,6], states have shape [1,3,8], and the final output head produces six logits. topk retains three IDs and softmax normalizes their scores. The printed probabilities sum to one over those candidates. No draw, append, repeated model call, or parameter update occurs.

Conclusion: The snippet checks a recurrent interface and a filtered candidate distribution. A complete name generator additionally needs learned parameters, token feedback, stopping, and state handling.

Add < and > boundary markers to each name. For example, anna becomes <anna>, so the width-four input <ann has the one-position-shifted target anna. Replacing the mapping after IDs have been created would make those IDs inconsistent.

Each input window is paired with its one-character-offset targets. One-hot encoding appends a vocabulary axis to the input axes and must be converted to the dtype and device expected by the LSTM. A fixed batch should expose each layer’s actual dimensions before training. The source configuration uses hidden width 256, two LSTM layers, dropout 0.5, Adam rate 0.001, batch size 64, ten epochs, and gradient clipping at 5. These values define the recorded case rather than a general recommendation.

Both are disabled in evaluation mode. Training at every position reshapes states from [B,T,256] to [B*T,256], produces logits [B*T,V], and pairs them with targets flattened in the same order. The sequence length used in this reshape must match the chosen window width. Record the actual example and update counts rather than inferring them from an epoch setting.

For a two-layer model, both hidden and cell state have shape [2,B,256], using the current batch size, dtype, and device. Reset them for independent names or windows. Carry them only across deliberate contiguous segments of one stream, with a declared detach policy during training. Carrying state across shuffled unrelated windows would mix their contexts.

Generation encodes a prefix, obtains its state, selects a character, appends it, and feeds that character into the next call with the carried state. The name task has the same next-token alignment as a larger language model. A count predictor instead uses an explicit fixed history, without a learned recurrent state.

24.6 The NLTK count-model tutorial and its extensions

A count table can expose how one observed history produces probabilities before a neural model is fitted. The NLTK notebook demonstrates count-model fitting and generation. Its nltk.lm.MLE model uses the maximum-likelihood principle explained in §8.1, fitting continuation probabilities from their observed relative frequencies. It then generates tokens from that fitted model. Smoothing and held-out perplexity below are book extensions.

The runnable local check uses Python’s standard-library Counter, not nltk. It counts bigrams in two boundary-padded sentences.

Code example: Padded bigram counts and maximum-likelihood probability

from collections import Counter

sentences = [["<s>", "the", "cat", "</s>"], ["<s>", "the", "dog", "</s>"]]
bigrams = Counter(
    (left, right)
    for sentence in sentences
    for left, right in zip(sentence, sentence[1:])
)
contexts = Counter(left for left, _ in bigrams.elements())

probability = bigrams[("the", "cat")] / contexts["the"]
assert probability == 0.5
print(bigrams, probability)

The context the has two continuations, one cat and one dog, giving \(P(\mathrm{cat}\mid\mathrm{the})=1/2\). Its numerator and denominator refer to the same one-token history.

Conclusion: The ratio is defined for this observed history. An unseen continuation has zero MLE probability, and an unseen history has a zero denominator in the direct count ratio. Library fallback behavior must be checked separately.

The NLTK interface adds vocabulary handling and a stored model to this count calculation. The next example uses nltk 3.9.2 and dill 0.4.1 on the same two short sentences, now with trigram histories. The code fits its counts from these local sentences without downloading a corpus or loading pretrained weights.

pad_both_ends adds two <s> tokens and two </s> tokens for order three. These boundary markers are modeled sentence content, unlike dense-batch placeholders excluded by a loss mask. padded_everygram_pipeline supplies one iterator over sentence n-grams of lengths one through three and another over vocabulary tokens. Both consume the original sentence collection, so the example keeps that collection as a reusable list. Inspecting and exhausting an iterator requires creating a fresh one before fitting.2

The tutorial first uses two unequal sentences, ['a','b','c'] and ['a','c','d','c','e','f']. Inspect unpadded bigrams of the first sentence and trigrams of the second to expose the different history lengths before boundary markers are added. Inspect the first sentence with one marker at each end for bigrams and two for trigrams. Then inspect everygrams up to length two and flatten both bigram-padded sentences for the vocabulary stream. Finally, materialize each training sentence’s n-gram iterator and the vocabulary iterator from padded_everygram_pipeline(2, text). Recreate both iterators before fitting. These inspections explain what is counted. They do not pad the unequal sentences into a dense tensor batch.

Code example: NLTK trigram counts, bit-based scores, and a saved-model round trip

from io import BytesIO
import dill
from nltk.lm import MLE
from nltk.lm.preprocessing import pad_both_ends, padded_everygram_pipeline

sentences = [["the", "cat"], ["the", "dog"]]
order = 3
print([list(pad_both_ends(s, n=order)) for s in sentences])
training, vocabulary = padded_everygram_pipeline(order, sentences)
model = MLE(order)
model.fit(training, vocabulary)

history = ("<s>", "the")
count = model.counts[history]["cat"]
total = model.context_counts(history).N()
score = model.score("cat", history)
print(count, total, score)
targets = [history + ("cat",)]
print(model.logscore("cat", history),
      model.entropy(targets), model.perplexity(targets))
print(model.vocab.lookup("never_seen"),
      model.score("never_seen", history))

saved = BytesIO()
dill.dump(model, saved)
saved.seek(0)
restored = dill.load(saved)
assert restored.counts[history]["cat"] == count
assert restored.score("cat", history) == score
assert (count, total, score) == (1, 2, 0.5)

from nltk.tokenize.treebank import TreebankWordDetokenizer

def sentence_text(tokens):
    words = []
    for token in tokens:
        if token == "<s>":
            continue
        if token == "</s>":
            break
        words.append(token)
    return TreebankWordDetokenizer().detokenize(words)

generated = model.generate(20, text_seed=["<s>", "<s>"], random_seed=7)
after_reload = restored.generate(20, text_seed=["<s>", "<s>"], random_seed=42)
assert len(generated) == len(after_reload) == 20
assert after_reload == model.generate(20, text_seed=["<s>", "<s>"], random_seed=42)
print(generated, sentence_text(generated))
print(after_reload, sentence_text(after_reload))

The padded sentences are <s> <s> the cat </s> </s> and <s> <s> the dog </s> </s>. For the two-token history ('<s>', 'the'), cat occurs once among two continuations. The first numerical line is therefore 1 2 0.5. The next is -1.0 1.0 2.0: log score, mean negative log score over the single supplied target, and perplexity. NLTK uses base-two logarithms here, so these log quantities are in bits. Chapter 8’s natural-log loss for probability 0.5 is about 0.693 nats. Either convention gives perplexity 2 when the matching exponential base is used.3

The default vocabulary cutoff is one. Inspect model.vocab and its length before and after fitting to distinguish an initialized model from one with corpus counts. model.vocab.lookup accepts either a token or a token sequence: known tokens retain their identities, while an unfamiliar token maps to <UNK>. import torch

image = torch.arange(16.0).reshape(1, 1, 4, 4)

24.8 A bounded synthesis of mechanism and evidence

An evidence record must distinguish a verified calculation from a claimed task improvement. One bounded task is enough to connect input preparation, model behavior, and held-out evidence without repeating every experiment.

For a classification, sequence-generation, adaptation, or multimodal task, define the input, required output, reference criterion, and one change compared with a baseline. Keep unrelated settings fixed and state which objects change: input representation, parameters, decoding, storage, or scheduling.

The diagram depicts reverse differentiation, which is relevant when the selected task includes training.

Its forward/reverse path repeats the mechanism in §11.6. It supplies no task-specific inputs, targets, values, or completed lab result. An inference-only synthesis instead tracks fixed parameters and changing input or request state.

The resulting evidence should contain five connected elements:

  1. An environment and data record, including the held-out boundary and actual computation budget.
  2. One small input traced through intermediate arrays to an independently checkable numerical result, with the relevant shapes, masks, dtype, reduction, and expected values. A training trace includes a derivative or parameter update. An inference trace includes selection and changing state.
  3. A baseline and one change executed under the same evaluation protocol. Actual training or inference results remain separate from local assertions. An unavailable run stays unexecuted, with its missing dependency identified.
  4. Contrasting outcomes or errors that show what the results support and which proposed causes remain uncertain. A performance claim additionally needs the timing boundary and hardware record from §23.6.
  5. A configuration choice justified by the task criterion and resource cost, together with missing evidence that could change the choice and enough input-output records for another reader to inspect the conclusion.
