24  Experiments and system integration

A correct small calculation does not establish that a trained system solves its task. These experiments connect the earlier mechanisms to complete datasets, controlled comparisons, and inspectable failures. Each result needs enough recorded information for another person to reproduce the comparison and assess its conclusion.

The short code examples below check particular interfaces and calculations. The full protocols require training or inference on the specified data. Their result tables are instructions for collecting evidence, not claims that those experiments have already been completed.

Keep source task statements and visible notebook outputs. Label plots with the measured quantity, axes, and configuration, using shared scales for comparisons. Record dataset and model revisions, preprocessing, splits, seeds, package versions, and hardware. Explain conclusions from the observed evidence rather than from the expected ranking of methods.

24.1 Logistic regression and optimizer comparisons

The first experiment makes every trainable value accessible. Its purpose is to connect a change in the update rule to a change in loss and held-out classification. It follows the SST-2 assignment in LLM_Architectures,_hometask_1.ipynb and the introductory PyTorch classifier notebook.

Checking one update. Start with the two-feature example below. The affine score from Chapter 5, stable binary loss from Chapter 8, and backward computation from Chapter 10 already define its mechanics.

\[ X\in\mathbb{R}^{B\times D},\quad w\in\mathbb{R}^{D},\quad z=Xw+b\in\mathbb{R}^{B} \tag{24.1}\]

For batch size \(B\) and feature width \(D\), inputs have shape \([B,D]\), weights \([D]\), and logits \([B]\). With \(B=2,D=5\), the same rule produces two scores from a \(2\times5\) input. The binary batch objective is:

\[ L=-\frac{1}{B}\sum_{i=1}^{B}\left[y_i\log p_i+(1-y_i)\log(1-p_i)\right],\quad p_i=\sigma(z_i) \tag{24.2}\]

Here \(p_i=\sigma(z_i)\) and \(y_i\in\{0,1\}\). For labels \((1,0)\) and probabilities \((0.8,0.25)\), the mean loss is approximately \(0.255413\) nats. A logits-based implementation avoids taking logarithms of rounded probabilities.

Code example: Logistic-regression forward, loss, and backward checks

import torch.nn as nn

import torch

# Rows are examples; columns are features.
X = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
y = torch.tensor([1.0, 0.0])
w = torch.tensor([0.2, -0.1], requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

# The affine score is the logistic-regression logit.
logits = X @ w + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(logits, y)
loss.backward()
assert logits.shape == (2,)
assert w.grad.shape == w.shape
assert b.grad.shape == b.shape
error = (torch.sigmoid(logits.detach()) - y) / len(y)
assert torch.allclose(w.grad, X.T @ error)
assert torch.allclose(b.grad, error.sum())
before = w.detach().clone()
expected = before - 0.1 * (X.T @ error)
with torch.no_grad():
    w -= 0.1 * w.grad
    b -= 0.1 * b.grad
assert torch.allclose(w, expected)
print(loss.item(), w.detach(), b.detach())

Compare the resulting gradients with the manual derivatives from Section 10.2, then verify one SGD update. Clearing accumulated gradients and rebuilding a forward graph are separate requirements. The assertions compare the manual and automatic derivatives and verify the changed weights.

The convex function is \(f(x,y)=x^2+4y^2\). Its gradient is \((2x,8y)\), and its minimum is at \((0,0)\). The six-hump function is:

The original small example verifies this interface with two documents, two tokens each, and three embedding coordinates:

Code example: Pooled token vectors and four-class MLP logits

import torch
import torch.nn as nn
torch.manual_seed(7)

# A real run obtains these token vectors from the trained Word2Vec model.
token_vectors = torch.tensor([
    [[1.0, 0.0, 0.5], [0.5, 1.0, 0.0]],
    [[0.0, 1.0, 0.5], [1.0, 0.5, 0.0]],
])
article_vectors = token_vectors.mean(dim=1)
classifier = nn.Sequential(nn.Linear(3, 8), nn.ReLU(), nn.Linear(8, 4))
labels = torch.tensor([0, 2])

logits = classifier(article_vectors)
loss = nn.CrossEntropyLoss()(logits, labels)
assert article_vectors.shape == (2, 3)
assert logits.shape == (2, 4)
print(loss.item())

It produces article vectors \([2,3]\), four-class logits \([2,4]\), and a scalar cross-entropy loss. Both positions are valid in this toy batch. Real padded batches need the validity-aware pooling from Chapter 13.

State whether the pretrained embeddings remain frozen. If they are trainable, classifier gradients also change their rows, and the Word2Vec initialization becomes a starting point rather than a fixed representation. Comparing frozen and trainable versions is a useful book extension, separate from the source’s six Word2Vec settings.

An MLP can classify pooled features because their width is fixed. Pooling loses order information, however, so the classifier cannot recover distinctions absent from those features. Compare that limit with the sequence models in Chapter 15.

Evaluating the result. Select architecture and training settings using validation evidence. Then compute test accuracy and a confusion matrix as required by the source. Optional F1 measurements add detail but do not replace accuracy. Chapter 9 explains the metrics and selection boundary.

Display three incorrect predictions with original text, true label, and predicted label. Relate patterns to tokenization, representation, or classification evidence. Neighbor quality alone is not the final classifier result, and an unexplained error pattern is not evidence of a specific internal cause.

The source also asks for a proposed input-influence method, without requiring its implementation. One option removes a token or phrase and compares the original class score under the same model. Explain that deletion changes the input and can create unnatural text, so this is a sensitivity test rather than proof of human-like reasoning.

24.3 N-gram counts and generation

The NLTK tutorial gives a fixed-history baseline whose probabilities can be traced to observed counts. It follows Ngram_Language_Model_with_NLTK_(1).ipynb. The count estimator and unseen-event problem are taught in Section 15.2.

Building counts. The source tutorial uses a text article saved as language-never-random.txt. Load its text, split it into sentences, tokenize each sentence, and lowercase tokens consistently. Inspect the first sentence before constructing counts. Begin the small check below with already tokenized sentences. For order \(n\), add \(n-1\) start and end markers around each sentence, keeping sentence boundaries explicit. padded_everygram_pipeline supplies training sequences containing grams up to that order and vocabulary data for fitting.

A vocabulary cutoff determines which observed words retain their own entries. NLTK’s Vocabulary maps excluded or unseen tokens to <UNK>. Inspect known and rare tokens after applying that mapping, because it changes the counts the estimator receives.

The original two-sentence check remains useful before the library workflow:

Code example: Padded bigram counts and maximum-likelihood probability

from collections import Counter

sentences = [["<s>", "the", "cat", "</s>"], ["<s>", "the", "dog", "</s>"]]
bigrams = Counter(
    (left, right)
    for sentence in sentences
    for left, right in zip(sentence, sentence[1:])
)
contexts = Counter(left for left, _ in bigrams.elements())

probability = bigrams[("the", "cat")] / contexts["the"]
assert probability == 0.5
print(bigrams, probability)

In that count table, the precedes cat once and dog once. Each continuation has probability one half. Neither this example nor an unsmoothed MLE model automatically resolves an unseen history.

Fit NLTK MLE(n) on the padded everygrams. Inspect unigram counts, one history’s continuation counts, and its conditional score. Compare logscore with the base-two logarithm of that probability. NLTK’s base-two log scores differ from the natural-log loss convention used elsewhere in this book.

Generating and restoring a model. Generate a continuation with a fixed text_seed and random_seed. Keep the raw tokens so boundary symbols remain inspectable. For readable text, remove boundary markers under an explicit rule and detokenize with TreebankWordDetokenizer.

The following complete small example covers vocabulary mapping, fitting, inspection, generation, and the source’s dill save/reload operation. It reloads only the file this example just created.

Code example: NLTK vocabulary, counts, generation and model persistence

from pathlib import Path
import math
import dill
from nltk.lm import MLE, Vocabulary
from nltk.lm.preprocessing import padded_everygram_pipeline
from nltk.tokenize.treebank import TreebankWordDetokenizer

sentences = ["the cat sat".split(), "the dog sat".split()] * 2
sentences.append("the hare sat".split())
training, vocabulary_tokens = padded_everygram_pipeline(2, sentences)
vocabulary = Vocabulary(vocabulary_tokens, unk_cutoff=2)
model = MLE(2, vocabulary=vocabulary)
model.fit(training)
assert model.vocab.lookup("hare") == "<UNK>"
assert model.vocab.lookup("unseen") == "<UNK>"
assert model.counts[2][("the",)]["cat"] == 2
assert model.counts[2][("the",)]["<UNK>"] == 1
probability = model.score("cat", ["the"])
assert probability == 2 / 5
assert math.isclose(model.logscore("cat", ["the"]), math.log2(probability))
generated = model.generate(8, text_seed=["the"], random_seed=42)
readable = TreebankWordDetokenizer().detokenize(
    [token for token in generated if token not in {"<s>", "</s>"}]
)
print(model.counts.unigrams, model.counts[2][("the",)])
print(probability, generated, readable)
path = Path("tiny-ngram-model.pkl")
with path.open("wb") as target:
    dill.dump(model, target)
with path.open("rb") as source:
    restored = dill.load(source)
assert restored.score("cat", ["the"]) == probability
assert restored.generate(8, text_seed=["the"], random_seed=42) == generated

The reloaded model must reproduce the conditional score and the same seeded token sequence. Saving only generated text would not preserve the estimator. Record library versions with the artifact, because serialization and generation behavior can depend on them.

Book extension: unseen events and evaluation. The source lists smoothing classes as optional further reading. It does not perform the smoothing and held-out-perplexity comparison requested here. Keep that extension distinguishable from the original tutorial.

Use the add-alpha mechanism in Section 15.2 to compare one zero-count continuation with its smoothed probability. Evaluate on held-out sentences using the same vocabulary and boundary conventions. Chapter 8 explains how mean negative log probability determines perplexity.

An unsmoothed zero probability gives infinite perplexity. A finite smoothed result resolves that numerical failure but does not prove useful language prediction. Report model order, cutoff, smoothing settings, and several generated continuations alongside the loss.

24.4 Character sequences and recurrent generation

An n-gram model limits context to an explicit history length. The character-level assignment replaces that table with learned recurrent state. It uses dinosaur names in the second part of LLM_Architectures_hometask_2_Tel_Aviv.ipynb.

Preparing sequences. Add < and > around each name, then create character-to-ID and ID-to-character mappings. The source illustrates anna as <anna>. Preserve the same mapping across training, validation, and generation.

Split whole names before concatenating each partition and constructing overlapping windows. Alternatively, split a source stream first and prevent windows from crossing that split. Randomly separating already-overlapping windows can place nearly identical character spans in both partitions.

Construct a dataset with __len__ and __getitem__, accepting a sequence length and input names or file path. For each start position, return an input window of length \(T\) and the next-character targets of length \(T\). For <anna> and \(T=4\), input <ann pairs with target anna.

Create training and validation loaders with a recorded batch size. Ensure the vocabulary covers validation characters under a declared policy. Do not silently assign a new ID that exceeds the model’s output width.

Tracing and training the model. One-hot encode an ID tensor \([B,T]\) into floating-point inputs \([B,T,V]\). An LSTM of width \(H\) produces sequence states \([B,T,H]\). The output head maps these to next-character logits \([B,T,V]\).

The recurrence, gates, and state shapes follow Chapter 15. On one fixed batch, print each layer’s output shape and inspect probabilities over the final vocabulary axis. Align every timestep’s logit with its shifted target before reducing cross-entropy.

Train for a fixed epoch budget while recording training and validation loss. Reset state between independent examples or document intentional state carryover. If carrying state across truncated segments, detach at the chosen backward boundary as explained in Chapter 15.

Comparing generation. Supply several prefixes to the trained model. Process the full prefix, then carry recurrent state while feeding back each selected character. Stop at > or a recorded maximum length.

Compare greedy decoding with sampling from the full vocabulary, then vary top-\(k\) and temperature. Chapter 7 contains the selection mechanics. Hold the model and prefix fixed for each comparison and record seeds, because different samples alone cannot establish an improvement.

The original small code checks one untrained LSTM and a top-three distribution:

Code example: Character LSTM state and top-k sampling

import torch
import torch.nn as nn
torch.manual_seed(7)

vocab_size, hidden_width = 6, 8
inputs = torch.nn.functional.one_hot(
    torch.tensor([[0, 1, 2]]),
    vocab_size,
).float()
lstm = nn.LSTM(vocab_size, hidden_width, batch_first=True)
output_head = nn.Linear(hidden_width, vocab_size)

states, recurrent_state = lstm(inputs)
logits = output_head(states[:, -1])
top_values, top_ids = torch.topk(logits, k=3, dim=-1)
probabilities = torch.softmax(top_values, dim=-1)

assert states.shape == (1, 3, hidden_width)
assert top_ids.shape == (1, 3)
print(top_ids, probabilities)

Its hidden states have shape \([1,3,8]\), and the selected candidates have shape \([1,3]\). It does not train a name generator or execute the feedback loop. The complete experiment must add those stages before interpreting name quality.

Keep generated names beside the settings and loss histories. Discuss repeated fragments, incomplete endings, prefix sensitivity, and plausible new combinations using the actual outputs. Attention next provides a different way to inspect information access across a sequence.

24.5 Attention under controlled changes

The attention assignment tests how changing an input affects the weights and output values. It follows the second part of From_Finetuning_to_Attention_Inside_LLMs.ipynb. The complete mechanism is in Chapter 16, and head layouts are in Section 17.1.

Start with the original two-position calculation below. Save projected \(Q,K,V\), unmasked scores, the mask, masked scores, row-wise weights, and weighted outputs. Label both heatmap axes by token and position.

Code example: Scaled attention values and row-normalization checks

import torch

# Two query positions, two key positions, and scalar values.
Q = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
K = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
V = torch.tensor([[2.0], [6.0]])
scale = Q.shape[-1] ** 0.5
scores = Q @ K.T / scale
causal_mask = torch.triu(torch.full_like(scores, float("-inf")), diagonal=1)
masked_scores = scores + causal_mask
weights = torch.softmax(masked_scores, dim=-1)
output = weights @ V
assert scores.shape == (2, 2)
assert output.shape == (2, 1)
assert weights[0, 1].item() == 0.0
assert torch.allclose(weights.sum(dim=-1), torch.ones(2))

The first query cannot read the second key under the causal mask. Every valid row sums to one. In a separate scalar check, weights \([0.25,0.75]\) and values \([2,6]\) produce output five. Compare an unmasked hand calculation and library result before adding masks.

Changing one word. Use the cat sat on the mat, then replace cat with dog. Define one fixed token-to-vector lookup and keep all projection matrices unchanged. Unchanged token IDs must retrieve identical vectors in both runs.

The source’s newly sampled random embeddings would change more than the selected word. Reusing a fixed lookup corrects that experimental control. A toy lookup can show arithmetic effects but cannot establish linguistic meaning in random vectors.

Compare the changed token’s projections, affected score row and column, normalized weights, and context vectors. With causal masking, earlier queries cannot respond to a later changed token. Perturbing a masked value should leave the corresponding output unchanged.

Comparing heads. Repeat the controlled comparison for at least two heads, each with its own fixed \(W_Q,W_K,W_V\). Display their heatmaps on comparable scales, preserving token order. Explain any differences from the actual matrices and outputs.

Separate the single-head output from concatenated head outputs. Check masks before softmax and handle invalid all-masked rows explicitly. Answer whether the word replacement changed weights, whether heads differ, and what complementary information trained heads could provide. A heatmap alone does not establish that a head understands a semantic relation.

The original local patch example isolates only the first representation step:

Code example: Patch tokens as inputs to a vision-language pipeline

import torch

image = torch.arange(16.0).reshape(1, 1, 4, 4)
patches = image.unfold(2, 2, 2).unfold(3, 2, 2)
patches = patches.contiguous().reshape(1, 4, 4)
projection = torch.ones(4, 3)
patch_tokens = patches @ projection

assert patches.shape == (1, 4, 4)

Reference retrieval. Choose three to five object instances or landmarks, collecting at least eight images per category. Preserve the source’s quantitative split: five or six reference images and two or three distinct query images per category. Use a matching pretrained image encoder and preprocessing for reference and query images. Normalize their embeddings and rank references by cosine similarity. State whether the category score uses a nearest reference or an explicit aggregation, and keep that rule fixed during evaluation.

Report the retrieved category, reference image, similarity score, and correct category for each query. Similarity is not a calibrated probability. If the system includes rejection for unknown categories, choose that rule using separate development evidence rather than the final query labels.

Combining components. A separate VQA or captioning component inspects the query image to answer an attribute or action question. Combine the retrieval result with that component’s answer, preserving uncertainty rather than turning a similarity score into certainty.

For example, retrieval might suggest a specific landmark while VQA describes its visible lighting. The combined response should retain both sources of evidence. Test the answer component with correct reference information as well as the retrieved result to distinguish its own failures from propagated retrieval errors.
