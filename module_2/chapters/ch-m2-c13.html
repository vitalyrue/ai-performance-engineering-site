13  Embedding tables

The classifier head needs numerical features, but a token ID only selects a vocabulary entry. Subtracting two IDs does not measure a relationship between their tokens. An embedding table supplies trainable coordinates for each entry.

This chapter follows those coordinates from individual lookups through batch gradients to one vector per sequence. The next chapter supplies a training objective that makes the vectors useful.

13.1 Looking up token vectors

A dense layer can combine numerical features, as Chapter 12 established. For discrete tokens, a token embedding is a vector selected from a trainable table. Its coordinates can change during learning without changing the token’s integer ID.

The embedding matrix \(E\) contains one row per vocabulary item and \(d\) coordinates per row. Here \(V\) is the vocabulary, so \(|V|\) is its size.

\[ E\in\mathbb{R}^{\lvert V\rvert\times d} \tag{13.1}\]

The token at position \(t\) has ID \(x_t\). Its embedding is the corresponding row, with the colon selecting every coordinate in that row.

\[ \operatorname{emb}(x_{t})=E_{x_{t},:} \tag{13.2}\]

For a table with three coordinates per row, ID 4 returns the three values stored at row 4. Renumbering the vocabulary and permuting the table consistently leaves these vectors unchanged. The ID itself does not determine their geometry.

A one-hot vector is a vocabulary-length selector with one coordinate equal to one and all others zero. Treating this selector as a column vector gives the equivalent multiplication:

\[ \operatorname{emb}(x_{t})=\operatorname{onehot}(x_{t})^{T}E \tag{13.3}\]

For four vocabulary entries and ID 2, the column selector is \((0,0,1,0)^\top\). Its transpose multiplies \(E\), retaining row 2 while multiplying every other row by zero. Row indexing produces this result without constructing the selector or processing all its zeros.

The two interfaces below preserve the same selected row. The sparse vector expresses vocabulary identity, while the table supplies its learned coordinates.

Table size still matters. With \(|V|=50{,}000\) and \(d=768\), the matrix contains \(38.4\) million scalar parameters. Float32 weights alone occupy \(153.6\) million bytes. Training may also require gradients and optimizer state, as Chapter 11 explains.

A lookup gathers values rather than performing a dense projection over the whole vocabulary. Its throughput can therefore depend strongly on memory bandwidth and access locality. Embedding width, repeated IDs, caching, and batch size affect that balance.

The tokenizer and table must share the same ID mapping. An ID outside the table’s range is an indexing error. An unknown-token policy must select a valid row, following Section 2.1.

13.2 Batch lookups and gradients

The same lookup rule applies to every position in a batch. A token tensor \(X\) with shape \([B,T]\) selects one vector per position, preserving the batch and sequence axes.

\[ H_{0}=E[X],\quad H_{0}\in\mathbb{R}^{B\times T\times d} \tag{13.4}\]

Here \(B\) is batch size, \(T\) is padded sequence length, and \(d\) is embedding width. The output \(H_0\) has shape \([B,T,d]\). Integer IDs become floating-point values that later layers can combine.

Repeated IDs reuse parameters. In a table containing at least eight rows, the sequence \((2,5,2)\) produces \((E_{2,:},E_{5,:},E_{2,:})\) with shape \([3,d]\). Both occurrences of ID 2 select the same stored row.

During backpropagation, their gradient contributions add. If the three positions receive upstream gradients \(g_1,g_2,g_3\), row 2 receives \(g_1+g_3\), while row 5 receives \(g_2\). Row 7 receives zero from this lookup because it was never selected.

Let \(\mathcal I_B\) be the set of IDs selected in the batch. When the table contributes to the loss only through this lookup, an unselected row has zero gradient:

\[ j\notin\mathcal{I}_{B}\quad\to\quad\frac{\partial L}{\partial E_{j,:}}=0 \tag{13.5}\]

This statement concerns the direct lookup path. Weight tying reuses one parameter matrix in multiple parts of a model. If the same table also scores every output token, that output calculation can give an unselected input row a gradient.

Zero gradient also does not guarantee unchanged weights. Momentum from earlier steps or weight decay may change a row during the optimizer update. These effects follow the update equations in Chapter 11.

PyTorch’s nn.Embedding stores a dense gradient by default, including zeros for unused rows. Its sparse=True option changes the gradient representation, and requires an optimizer that supports it. Mathematical sparsity and sparse storage are separate properties.

A batch lookup still returns a vector at every padded position. The next operation must decide which positions belong to the sequence before reducing them to one representation.

13.3 Pooling sequences

A classifier often needs one vector per example, while a lookup returns one vector per token. Pooling reduces the sequence axis to a fixed width. The reduction determines which information the classifier can retain.

One possible fixed-width representation concatenates token vectors in order. Three vectors of width two, \([1,2]\), \([3,4]\), and \([5,6]\), become \([1,2,3,4,5,6]\). The resulting width is \(TD\) for a fixed maximum length \(T\) and vector width \(D\).

Shorter inputs need padded positions, while longer inputs require truncation or a larger interface. Concatenation preserves separate positions but increases classifier width and binds it to that length limit. Pooling instead keeps one feature coordinate for each embedding coordinate, independent of sequence length.

Mean pooling averages the token vectors coordinate by coordinate. For \(T\) included positions, it produces:

\[ s=\frac{1}{T}\sum_{t}h_{t} \tag{13.6}\]

Here \(h_t\) is the vector at position \(t\), and \(s\) is the sequence vector. Scalar values 2, 4, and 6 average to 4. Vector pooling repeats that calculation independently for each coordinate.

The following PyTorch example uses six vocabulary rows with three coordinates each. Both sequences contain three valid tokens, including ID 0. It averages across positions, computes the mean squared value of the resulting representations, and backpropagates that scalar loss.

Code example: Embedding lookup, pooling, and selected-row gradients

import torch
import torch.nn as nn

torch.manual_seed(7)
embedding = nn.Embedding(num_embeddings=6, embedding_dim=3)
token_ids = torch.tensor([[1, 2, 1], [3, 2, 0]])

token_vectors = embedding(token_ids)
document_vectors = token_vectors.mean(dim=1)
loss = document_vectors.square().mean()
loss.backward()

print(token_vectors.shape, document_vectors.shape)
print(embedding.weight.grad.abs().sum(dim=1))
assert token_vectors.shape == (2, 3, 3)
assert document_vectors.shape == (2, 3)
assert torch.count_nonzero(embedding.weight.grad[4:]) == 0

The token vectors have shape \([2,3,3]\), and the pooled vectors have shape \([2,3]\). Rows 0 through 3 can receive gradients. Rows 4 and 5 remain zero because this example uses the table only through the lookup.

For padded sequences, averaging every position mixes artificial padding into the result. Use the validity mask from Section 2.2. With \(M_{b,t}=1\) for valid positions and zero otherwise, the masked mean is \(s_b=\sum_t M_{b,t}h_{b,t}/\sum_t M_{b,t}\).

The denominator counts real tokens, so each sequence must contain at least one valid position. An empty sequence requires an explicit policy, such as rejection or a separate empty-input token.

Consider vectors \((2,4)\) and \((4,8)\) followed by padding \((0,0)\). An unmasked mean gives \((2,4)\), while the two valid vectors average to \((3,6)\). Adding another padded position would change the unmasked result again despite leaving the text unchanged.

The following calculation keeps the validity mask separate from token values. It rejects an empty sequence and divides each sum by its own valid count.

Code example: A masked mean keeps padding out of the sequence representation

import torch

vectors = torch.tensor([
    [[2., 4.], [4., 8.], [99., 99.]],
    [[1., 2.], [3., 6.], [-99., -99.]],
])
valid = torch.tensor([[True, True, False], [True, True, False]])
counts = valid.sum(dim=1, keepdim=True)
if torch.any(counts == 0):
    raise ValueError("A pooled sequence needs at least one valid token")
masked = vectors.masked_fill(~valid.unsqueeze(-1), 0.)
pooled = masked.sum(dim=1) / counts
print(pooled)
assert torch.allclose(pooled, torch.tensor([[3., 6.], [2., 4.]]))

The result is \([[3,6],[2,4]]\). Changing either padded vector leaves it unchanged, provided the mask remains correct. Zero-valued real features remain valid because validity comes from sequence membership.

Max pooling takes the largest value of each coordinate across valid positions. Padding must be excluded from that comparison too. Replacing it with zero is incorrect when every real value in a coordinate is negative.

Mean and max summaries can also be concatenated. Vectors \((2,4)\) and \((4,8)\) have mean \((3,6)\) and coordinatewise maximum \((4,8)\), giving combined summary \((3,6,4,8)\). This doubles the pooled width but still discards token order. Section 14.3 considers learning a compressed representation through reconstruction instead.

CLS pooling uses the representation of a designated classification token. A raw lookup for that token is identical in every sequence. Earlier processing must combine it with the sequence before it can represent the surrounding text. Chapter 16 introduces such information mixing.

Mean and max pooling over static token rows lose token order. The phrases “dog bites person” and “person bites dog” contain the same tokens and yield the same mean. An order-sensitive task therefore needs additional sequence processing.

Pooling can provide a useful classification or retrieval baseline, but lookup and pooling alone do not create meaningful similarity. Chapter 14 explains how a context-prediction objective trains the coordinates.

Chapter checkpoint

A sentence’s classifier score changes when extra padding is appended. Which intermediate result would you inspect, and what calculation should remain unchanged?

Feedback: Inspect the validity mask and pooled vector. A masked mean over the same valid tokens should remain unchanged. Check both the numerator and the count used as its denominator.

A row absent from the input batch changes after an optimizer step. Does that prove the lookup gradient is wrong?

Feedback: No. Inspect other uses of the same weights, existing momentum, and weight decay. The zero-gradient statement applies to the direct lookup path, not every possible parameter update.
