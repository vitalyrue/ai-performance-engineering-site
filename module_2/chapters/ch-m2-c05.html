5  Linear scores

The document features now have numerical values and consistent coordinates. A model needs a rule that turns those values into a prediction. The simplest useful rule attaches a coefficient to each feature, adds the contributions, and includes an offset.

That calculation can estimate a numerical target or produce evidence for a class. Following it from one example to a batch establishes the matrix operations used throughout the later models.

5.1 Linear prediction

Suppose two measured features help predict a numerical target. Their contributions need not have the same sign or importance. A weight is a coefficient that scales one feature’s contribution. A bias is an offset added independently of the feature values.

Collect the \(D\) features in a vector \(x\) and their weights in a vector \(w\) of the same length. A dot product multiplies matching coordinates and adds the products. The expression \(w^\top x\) means \(w_1x_1+\cdots+w_Dx_D\). The superscript \(\top\) indicates transposition, turning a column into a row for the multiplication.

The prediction is:

\[ \hat{y}=w^\top x+b \tag{5.1}\]

The symbol \(\hat y\) denotes the model’s predicted value, while \(b\) is the scalar bias. The full expression is an affine map, a linear map plus an offset. The term “linear model” commonly includes that offset.

For \(x=(2,-1)\), \(w=(0.5,3)\), and \(b=1\), the contributions are \(0.5\times2=1\) and \(3\times(-1)=-3\). Adding them and the bias gives \(\hat y=1-3+1=-1\). Each weight has a direct role in this calculation. Its interpretation still depends on the feature’s units and the other features present.

The bias can also be included as a constant feature. For \(x=(2,-1)\), use \(x'=(1,2,-1)\) and \(w'=(1,0.5,3)\). Then \(w'^T x'=1+1-3=-1\), exactly the same prediction. The leading constant changes notation, not the model’s behavior.

Across inputs, each coefficient describes how its feature changes the score when other features remain fixed. For one input, the products \(w_jx_j\) describe its individual score contributions. These global coefficients and local contributions are different explanations, and neither establishes a causal effect of changing the real-world feature.

We can judge the prediction only after supplying a target. The residual is the target minus the prediction:

\[ r_i=y_i-\hat{y}_i \tag{5.2}\]

The subscript \(i\) selects an example. A positive residual means the target is above the prediction. For target \(y=3\) and prediction \(-1\), the residual is \(3-(-1)=4\). This sign convention must remain explicit because some implementations define the difference in the opposite order.

Squaring residuals prevents positive and negative errors from canceling. The mean squared error, abbreviated MSE, averages those squared values:

\[ L_{\mathrm{MSE}}=\frac{1}{n}\sum_i(y_i-\hat{y}_i)^2 \tag{5.3}\]

There are \(n\geq1\) examples. Each term \((y_i-\hat y_i)^2\) is nonnegative, and division by \(n\) gives equal weight to the examples. For the one-example calculation above, the squared error and the mean squared error are both \(4^2=16\). An error twice as large contributes four times as much squared error.

This objective measures discrepancy in squared target units. It can emphasize large misses, which matters when some observations contain extreme errors. We have evaluated a model with supplied parameters. The learning chapters will derive how parameters change during training.

Classification uses the same affine calculation, but interprets its result as a score rather than a numerical target estimate.

5.2 Decision boundaries

For a binary classification task, we can use a positive score to favor one class and a negative score to favor the other. A score, also called a logit in this classification setting, is the unnormalized model output before a probability transformation:

\[ z=w^\top x+b \tag{5.4}\]

The feature and weight vectors again have length \(D\), and the bias is scalar. A logit can be any real number. It does not become a probability merely because a class decision uses its sign. Sigmoid will give that score a binary probability interpretation.

The decision boundary contains the inputs at which the chosen decision rule changes class. For the zero-score threshold, it is the set:

\[ \{x\mid w^\top x+b=0\} \tag{5.5}\]

The notation collects all feature vectors \(x\) whose affine score is zero. With nonzero \(w\), the boundary is a line in two dimensions, a plane in three, and a hyperplane in higher dimensions. The weight vector determines its orientation, while the bias shifts its position. A different decision threshold shifts the boundary as well.

Take \(w=(1,-1)\) and \(b=-1\), giving score \(z=x_1-x_2-1\). For \(x_A=(3,1)\), the score is \(3-1-1=1\). For \(x_B=(1,2)\), it is \(1-2-1=-2\). The points lie on opposite sides. For \(x_C=(2,1)\), the score is \(2-1-1=0\), placing it on the boundary itself.

The figure connects those signed scores to regions of feature space. Crossing the boundary changes the decision under this threshold rule.

A score grows along the weight direction, but it is not generally a geometric distance. Multiplying both weights and bias by a positive constant preserves the zero boundary while changing score magnitudes. Those magnitudes matter once the scores become probabilities.

Logistic regression combines an affine score with the sigmoid probability function. The probability varies nonlinearly with the score, while the zero-score boundary remains linear in the supplied features. A single boundary cannot separate every pattern. Nonlinear representations will construct an example where changing the feature representation is necessary.

For more than two mutually exclusive classes, the model needs a score for each candidate. Matrix multiplication computes those scores for many examples at once.

5.3 Scoring a batch

Processing one row at a time repeats the same weighted sum. Stacking rows into a matrix exposes the shared operation. Let \(X\) have shape \([B,D]\), with \(B\) examples and \(D\) features. A weight vector of shape \([D]\) produces one score per example:

\[ z=Xw+b \tag{5.6}\]

The multiplication consumes the feature axis and leaves a result \(z\) of shape \([B]\). The same scalar bias is added to every row’s score. A feature-width mismatch is a mathematical error before it is a library error: a row with three features cannot form this dot product with two weights.

Use the three-example batch \(X=[[1,0],[0,1],[1,1]]\), targets \(y=[1,0,1]\), weights \(w=[0.8,-0.3]\), and bias \(b=0.1\). The scores are:

  • First row: \(1(0.8)+0(-0.3)+0.1=0.9\).
  • Second row: \(0(0.8)+1(-0.3)+0.1=-0.2\).
  • Third row: \(1(0.8)+1(-0.3)+0.1=0.6\).

Thus \(z=[0.9,-0.2,0.6]\). The targets remain separate and do not enter the score calculation. They will be used to judge the predictions. These same rows and scores continue through the probability, loss, and gradient calculations.

The runnable PyTorch example creates the small tensors explicitly. The @ operator performs matrix multiplication, and adding the scalar bias applies the same offset to all three results.

Code example: The running batch from features to logits

import torch

X = torch.tensor([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]])
y = torch.tensor([1.0, 0.0, 1.0])
w = torch.tensor([0.8, -0.3])
b = torch.tensor(0.1)

logits = X @ w + b
print(logits)  # tensor([ 0.9000, -0.2000,  0.6000])

The printed vector contains 0.9000, -0.2000, and 0.6000. No parameter update has occurred. One scalar score per row is sufficient for the binary probability representation introduced next.

For a multiclass model, each feature needs a separate coefficient for each output class. A weight matrix places those coefficients in columns. The complete vocabulary-feature calculation is:

\[ Z=XW+b,\quad X\in\mathbb{R}^{B\times\lvert V\rvert},\quad W\in\mathbb{R}^{\lvert V\rvert\times K},\quad b\in\mathbb{R}^{K},\quad Z\in\mathbb{R}^{B\times K} \tag{5.7}\]

Here \(B\) is the number of documents, \(|V|\) is the number of input features, and \(K\) is the number of output classes. The matrix \(W\) has shape \([|V|,K]\), and the bias vector has shape \([K]\). Entry \(Z_{b,k}\) adds the products of document row \(b\) and weight column \(k\), then adds the class bias \(b_k\). In this formula, the subscript \(b\) indexes a document, while the vector symbol \(b\) denotes biases.

The output has shape \([B,K]\). The vocabulary axis is consumed by the multiplication, leaving a batch axis and a class axis. Class scores therefore do not share a vocabulary axis with the input matrix.

For two documents and three features, use:

\[X=\begin{bmatrix}2&1&0\\0&1&3\end{bmatrix},\qquad W=\begin{bmatrix}0.5&-0.2\\1.0&0.4\\-0.5&0.8\end{bmatrix},\qquad b=[0.1,-0.1].\]

The first document’s scores are \(2(0.5)+1(1.0)+0(-0.5)+0.1=2.1\) and \(2(-0.2)+1(0.4)+0(0.8)-0.1=-0.1\). The second document’s scores are \(0(0.5)+1(1.0)+3(-0.5)+0.1=-0.4\) and \(0(-0.2)+1(0.4)+3(0.8)-0.1=2.7\).

The result is \(Z=[[2.1,-0.1],[-0.4,2.7]]\). Each row contains two competing scores for one document. The matrix figure shows how the matching feature dimensions align in those dot products.

Adding the bias vector uses broadcasting. An elementwise operation can expand an axis of length 1 across the matching axis of another input. Here the library treats shape \([K]\) as \([1,K]\) and applies that same bias row to all \(B\) rows. It does not add together the documents or create new learned bias values.

More generally, elementwise broadcasting compares axes from the right. Corresponding lengths must be equal, or one must be 1. This rule differs from matrix multiplication. For example, adding shapes \([B,1]\) and \([B]\) can unexpectedly produce \([B,B]\), so dimensions alone must be checked against their intended roles.

The next runnable example performs the two-document calculation and checks every result. It uses a dense tensor for inspection. A large count matrix would usually remain sparse and require a compatible multiplication.

Code example: Vocabulary-feature batches mapped to class logits

import torch

# Rows are documents; columns are vocabulary features.
X = torch.tensor([[2.0, 1.0, 0.0], [0.0, 1.0, 3.0]])
W = torch.tensor([[0.5, -0.2], [1.0, 0.4], [-0.5, 0.8]])
b = torch.tensor([0.1, -0.1])

# Matrix multiplication computes every document-class dot product.
Z = X @ W + b
expected = torch.tensor([[2.1, -0.1], [-0.4, 2.7]])
assert Z.shape == (2, 2)
assert torch.allclose(Z, expected)

PyTorch’s nn.Linear(D,K) stores its weight array in the transposed orientation, shape \([K,D]\). If that stored array is \(A\), the same calculation is \(XA^\top+b\). This storage convention changes how we read a parameter array, rather than changing the affine model. Tensor layout later examines storage and operation costs in more detail.

We now have scores with defined meanings and dimensions. The next chapter converts one binary score or a row of competing scores into probabilities.
