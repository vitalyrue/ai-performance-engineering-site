7  Decoding strategies

A next-token distribution describes several possible continuations. An application still needs one visible output. Decoding selects a token, appends it to the available context, and repeats the process when more text is required.

This chapter follows inference with a fixed model. Changing a decoding rule changes how its scores are used, while its trained parameters remain fixed. After exploring that branch, we return to the probability assigned to an observed training target.

7.1 Greedy selection

Suppose the model assigns probabilities \((0.6,0.3,0.1)\) to three candidate tokens. The most direct rule chooses the first candidate. Greedy decoding always selects the highest-probability outcome at the current step:

\[ \mathrm{next}=\operatorname*{arg\,max}_{i}p_i \tag{7.1}\]

The index \(i\) identifies a candidate, and \(p_i\) is its probability. The operator \(\operatorname*{arg\,max}\) returns an index attaining the largest value. With zero-based token indices, \((0.1,0.7,0.2)\) selects index 1. Equal maximum values require a tie policy if the result must be deterministic.

A decoder step computes next-token scores for the current context. Their vocabulary distribution is:

\[ P(\mathrm{next}=i\mid\mathrm{context})=\operatorname{softmax}(\mathrm{logits})_i \tag{7.2}\]

The softmax calculation is the one established in Chapter 6. Greedy selection can operate directly on logits because softmax preserves their ordering. It does not need to materialize every probability merely to find the largest score.

A classifier may make one such choice and stop. An autoregressive language model appends the selected token, computes scores for the extended context, and selects again. The selected token is therefore an input to later decisions. Generation ends when the stopping rule is met, for example after an end marker or a maximum output length.

Greedy decoding solves the current one-step choice. It does not guarantee the most probable complete continuation, because a slightly less likely first token can lead to much more likely later tokens. It also repeats the same choices under the same scores and tie rules, which may be unsuitable when the application needs several alternatives.

Selection should be distinguished from the computation producing the scores. The serving chapter reuses model state to avoid repeated work. Such reuse aims to preserve the same model computation. A decoding rule deliberately changes how candidate outputs are chosen.

7.2 Sampling controls

Sampling can produce several continuations from the same prompt, but very low-probability choices may be unhelpful. We can adjust the distribution before drawing a token. Temperature changes its concentration, while top-k and top-p restrict which candidates remain eligible.

For positive temperature \(T\), divide every logit by \(T\) before normalization:

\[ p_i^{(T)}=\frac{e^{z_i/T}}{\sum_j e^{z_j/T}} \tag{7.3}\]

Here \(T\) is temperature, rather than the sequence length used in other chapters. At \(T=1\), the original softmax is recovered. A value above 1 reduces score differences and makes the distribution flatter. A value between 0 and 1 increases those differences and makes it sharper. The formula is undefined at zero. Interfaces that offer zero-temperature generation typically select greedily through a separate rule.

Start with logits \([2,1,0]\), whose probabilities are approximately \([0.665,0.245,0.090]\). At temperature 2, the logits become \([1,0.5,0]\), giving approximately \([0.506,0.307,0.186]\). The largest candidate is still largest, but the alternatives receive more probability. For the two-logit case \((2,1)\), temperature 2 likewise changes the score gap from 1 to 0.5.

Top-k sampling retains exactly the \(k\) largest candidates before drawing a token. Let \((i_1,\ldots,i_V)\) order the vocabulary indices from highest to lowest probability, breaking ties consistently. The retained set is:

\[ S_k=\{i_1,\ldots,i_k\},\quad p_{i_1}\ge p_{i_2}\ge\ldots\ge p_{i_V},\quad 1\le k\le V \tag{7.4}\]

The vocabulary contains \(V\) candidates, and \(1\leq k\leq V\). The retained support is the set of outcomes allowed to receive nonzero probability. For probabilities \((0.5,0.3,0.2)\) and \(k=2\), only the first two indices remain.

Top-p sampling, also called nucleus sampling, retains the smallest leading set whose total probability reaches a threshold. Write that threshold as \(\tau\) to distinguish it from the individual probabilities \(p_i\):

\[ S_\tau=\{i_1,\ldots,i_m\},\quad m=\min\left\{r:\sum_{j=1}^{r}p_{i_j}\ge\tau\right\},\quad 0<\tau\le1 \tag{7.5}\]

The candidates use the same decreasing order, and \(0<\tau\leq1\). For \((0.5,0.3,0.2)\) and \(\tau=0.8\), the first two probabilities reach the threshold exactly. A sharply concentrated distribution may need only one candidate. A flatter distribution may need many.

After either filter selects a nonempty set \(S\), the remaining mass must be normalized again. For \(i\in S\), use \(q_i=p_i/\sum_{j\in S}p_j\), and set \(q_i=0\) outside it. Sampling then draws from \(q\), so excluded candidates cannot be selected.

Keep the starting point explicit when comparing settings. Filtering the original \([0.665,0.245,0.090]\) with \(k=2\) gives approximately \([0.731,0.269,0]\). Top-p with threshold 0.8 retains the same two candidates because their original combined mass is about 0.910. It therefore gives the same renormalized result in this case.

Combining temperature 2 with top-k is a different experiment. First obtain \([0.506,0.307,0.186]\), then retain the largest two values and renormalize. The result is approximately \([0.622,0.378,0]\). Top-p at 0.8 also keeps those two under this distribution, whose combined mass is about 0.814. Applying top-k to the original probabilities while describing temperature-adjusted sampling would mix two different computations.

The following runnable PyTorch example uses four scores, temperature 0.8, and top-k 2. torch.topk returns the retained values and indices. The code places negative infinity at excluded positions, so their exponentials become zero during softmax.

Code example: Temperature and top-k filtering for one next-token decision

import torch

logits = torch.tensor([2.0, 1.0, 0.5, -1.0])
temperature = 0.8
top_k = 2

scaled = logits / temperature
values, indices = torch.topk(scaled, top_k)
filtered = torch.full_like(scaled, float("-inf"))
filtered[indices] = values
probabilities = torch.softmax(filtered, dim=-1)

print(probabilities)
print(torch.multinomial(probabilities, num_samples=1))

The resulting probabilities are approximately \([0.777,0.223,0,0]\). The final call draws one retained index and returns an integer tensor with one element. That sampled result is random. A specified generator seed helps make an experiment repeatable, although exact reproducibility also depends on the implementation and execution environment.

Generation interfaces such as GenerationConfig and generate expose these choices through settings including do_sample, temperature, top_k, and top_p. Their supported combinations and defaults must be checked for the selected implementation. The library map connects those interfaces to their practical use.

Lower temperature and narrower support do not establish factual correctness. They concentrate choices according to the model’s existing scores. The application must evaluate whether the resulting diversity, repetition, and errors meet its needs.

7.3 Beam search

Greedy decoding discards every alternative to the best current token. Beam search instead retains several partial continuations. Its beam width is the number kept after each expansion. This trades additional computation and state for a broader search over sequences.

Suppose the first-token probabilities are \(P(A)=0.6\) and \(P(B)=0.4\). After \(A\), the next-token probabilities are \(P(X\mid A)=0.51\) and \(P(Y\mid A)=0.49\). After \(B\), they are \(P(X\mid B)=0.9\) and \(P(Y\mid B)=0.1\). Compare continuations of exactly two tokens.

Greedy decoding chooses \(A\), then \(X\), giving sequence probability \(0.6\times0.51=0.306\). A beam of width 2 retains both \(A\) and \(B\) after the first step. Expanding them produces \(AX:0.306\), \(AY:0.294\), \(BX:0.36\), and \(BY:0.04\). Keeping the best two gives \(BX\) and \(AX\). The most probable complete sequence here starts with the locally less likely first token.

Rather than multiplying many small probabilities, beam search usually adds their logarithms. A sequence score for a candidate prefix is:

\[ score(y_{1:t})=\sum_{i=1}^{t}\log P(y_i\mid y_{<i},x) \tag{7.6}\]

The sequence \(y_{1:t}\) contains \(t\) generated tokens, and \(x\) is the supplied prompt or input. Each factor conditions on that input and the earlier generated tokens. The logarithm converts the probability product into a sum. A larger log score represents a more probable sequence under this criterion.

For a two-token candidate with probabilities 0.5 and 0.4, the score is \(\log(0.5)+\log(0.4)=\log(0.2)\approx-1.609\). Every added probability factor is at most 1, so additional tokens cannot increase the raw log score. Comparing different lengths therefore requires care.

A length normalization modifies that comparison. One simple choice divides the accumulated log score by \(t^\alpha\), with a specified exponent \(\alpha\). This is a new search criterion, rather than the raw sequence probability. For a two-token sequence with probability 0.2 and a three-token sequence with probability 0.18, the raw scores favor the first. With \(\alpha=1\), their normalized scores are about \(-0.805\) and \(-0.572\), favoring the second. Different libraries may use different length formulas.

An implementation must also state how completed sequences and unfinished beams compete, when an end marker stops expansion, and what happens at the output-length limit. Those choices can change the result even at a fixed beam width.

Beam search remains approximate because discarded prefixes are not reconsidered. A wider beam searches more alternatives, but the model’s preferred sequence need not be the most useful response. With deterministic model outputs and tie handling, beam search is a deterministic search procedure. It is distinct from drawing random candidates from a distribution.

The output branch has now converted probabilities into visible tokens. We next return to an observed target and ask how much penalty its assigned probability should contribute during training.
