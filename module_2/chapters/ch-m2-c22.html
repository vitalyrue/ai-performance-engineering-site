22  Images, audio, and multimodal models

A transformer receives vectors, but pixels, audio samples, and table fields have different structures. Their first representation must preserve the information the task needs. Connecting these representations to text also requires a suitable training objective or generation interface.

This chapter follows each input through its conversion, then distinguishes matching across modalities from generating an answer about them. The final comparison asks which model structure is justified by the data and task.

22.1 Image features and patches

An image contains neighboring pixels on a two-dimensional grid. A model can exploit those local relationships before combining information over a larger region. A convolution applies a shared weighted filter to local neighborhoods.

For unit stride, one output value is:

\[ Y_{i,j,c_{\mathrm{out}}}=b_{c_{\mathrm{out}}}+\sum_{u,v,c_{\mathrm{in}}}W_{u,v,c_{\mathrm{in}},c_{\mathrm{out}}}X_{i+u,j+v,c_{\mathrm{in}}} \tag{22.1}\]

Here \(X\) is the input feature map, \(W\) contains filter weights, and \(b\) is the output-channel bias. Indices \(i,j\) identify an output location, \(u,v\) identify filter offsets, and the channel indices select input and output features. Deep-learning libraries usually implement this unflipped-filter form, mathematically a cross-correlation, under the convolution name.

For a two-by-two patch \([[1,2],[3,4]]\), a kernel of ones and zero bias produces \(1+2+3+4=10\). Moving the kernel to another neighborhood reuses the same learned weights.

Stride is the distance between successive filter positions. Padding supplies values around the input border. With dilation one, kernel width \(k\), stride \(s\), and padding \(p\) on both sides, one output dimension is:

\[ n_{\mathrm{out}}=\left\lfloor\frac{n_{\mathrm{in}}+2p-k}{s}\right\rfloor+1 \tag{22.2}\]

The floor counts complete filter placements. For input width five, kernel width three, no padding, and stride one, the output width is three. A valid configuration must permit at least one placement.

Repeated filters share a detection rule across image locations. After nonlinear activation, spatial pooling or strided layers can reduce resolution, allowing later features to combine information from a wider input region. Sharing a filter does not make the complete classifier invariant to every translation, crop, or background change.

A wolf classifier that relies on snow may succeed on familiar photographs and fail on wolves against other backgrounds. Keep subject and background variation in the evaluation design. This is the same shortcut-learning problem as the spurious text features discussed in Section 9.1.

A convolutional neural network, or CNN, stacks these local transformations. A residual network, or ResNet, adds compatible inputs around learned convolutional branches. The residual mechanism is the one from Section 17.3.

A vision transformer, or ViT, instead processes a sequence of projected image regions called patch tokens. Dividing an image of height \(H\) and width \(W\) into nonoverlapping square patches of side \(P\) gives:

\[ N_{\mathrm{patches}}=\left(\frac{H}{P}\right)\left(\frac{W}{P}\right) \tag{22.3}\]

This expression assumes \(P\) divides both dimensions. Otherwise preprocessing must crop or pad explicitly. Flattening each \(P\times P\) patch with \(C\) channels creates \(P^2C\) values. A learned matrix projects that vector to model width \(D\).

\[ Z=\operatorname{flatten}(\mathrm{patches})W_{\mathrm{patch}},\quad Z\in\mathbb{R}^{B\times N\times D} \tag{22.4}\]

Here \(W_{\text{patch}}\) has shape \([P^2C,D]\), and \(Z\) has shape \([B,N,D]\) for \(N\) patches. Position information preserves their locations, using the principles in Section 17.2.

A \(224\times224\) image with \(16\times16\) patches produces \(14\times14=196\) positions. An additional classification token would make 197. Halving patch side length to eight gives 784 patch positions, four times as many. Their full pairwise attention count increases by a factor of sixteen.

In a separate smaller example, a \(32\times32\) RGB image with \(8\times8\) patches produces sixteen tokens. Each patch contains \(8(8)(3)=192\) values. Projection to width 64 gives shape \([B,16,64]\) before any optional classification token.

Patch projection itself can be implemented by a convolution whose kernel and stride both equal the patch size. The following code applies that operation to two RGB images, then converts the spatial output grid into a sequence.

Code example: Patchifying an image with a strided convolution

import torch
import torch.nn as nn

torch.manual_seed(7)
images = torch.randn(2, 3, 224, 224)
patch_projection = nn.Conv2d(in_channels=3, out_channels=64, kernel_size=16, stride=16)

patch_grid = patch_projection(images)          # [2, 64, 14, 14]
patch_sequence = patch_grid.flatten(2).transpose(1, 2)  # [2, 196, 64]

print(patch_grid.shape)
print(patch_sequence.shape)
assert patch_grid.shape == (2, 64, 14, 14)
assert patch_sequence.shape == (2, 196, 64)

The grid has shape \([2,64,14,14]\), and the sequence has shape \([2,196,64]\). flatten(2) combines the spatial axes, while transpose(1,2) puts patch positions before features. Subsequent transformer blocks consume those vectors after the model’s position and token conventions are applied.

Local filters and patch attention encode different assumptions about useful relationships. Neither representation by itself explains how an image should match a sentence.

22.2 Matching images and text

An image-retrieval task needs a comparable score for an image and a text query. Contrastive Language-Image Pre-training, or CLIP, learns separate image and text encoders whose outputs can be compared. Its training data supplies matching image-caption pairs. The CLIP paper develops this paired supervision.

For \(B\) pairs, normalize their embedding vectors and compute a similarity matrix \(S\) with shape \([B,B]\). Row \(i\) compares image \(i\) with every caption. Column \(j\) compares caption \(j\) with every image. The recorded matches occupy the diagonal.

A contrastive loss rewards matched pairs relative to comparison candidates. CLIP uses both image-to-text and text-to-image cross-entropy, with temperature \(\tau>0\):

\[ L_{\mathrm{CLIP}}=\frac{1}{2}\left[\operatorname{CE}\!\left(\frac{S}{\tau},y\right)+\operatorname{CE}\!\left(\frac{S^{T}}{\tau},y\right)\right] \tag{22.5}\]

Here \(y=(0,\ldots,B-1)\) supplies zero-based diagonal class indices to the code. Each cross-entropy receives scaled similarity logits and averages its batch. The final factor one half averages the two directions.

Consider temperature-scaled scores \(S/\tau=\begin{bmatrix}\log9&0\\\log2&\log8\end{bmatrix}\). The first image row gives its correct caption probability \(9/(9+1)=0.9\). The second gives its correct caption probability \(8/(2+8)=0.8\).

The image-to-text loss is \([-\log(0.9)-\log(0.8)]/2\approx0.164252\). Reversing the direction requires normalizing the columns of the same matrix. Their correct-image probabilities are \(9/11\) and \(8/9\).

The text-to-image loss is \([-\log(9/11)-\log(8/9)]/2\approx0.159227\). Averaging both directions gives approximately \(0.161739\). The following calculation verifies all three values.

Code example: The two directions of a contrastive batch loss

import torch
import torch.nn.functional as F

scaled_scores = torch.log(torch.tensor([[9., 1.], [2., 8.]], dtype=torch.float64))
targets = torch.arange(2)
image_loss = F.cross_entropy(scaled_scores, targets)
text_loss = F.cross_entropy(scaled_scores.T, targets)
loss = (image_loss + text_loss) / 2
print(image_loss.item(), text_loss.item(), loss.item())
assert abs(image_loss.item() - 0.164252033486018) < 1e-9
assert abs(text_loss.item() - 0.159226865559) < 1e-9
assert abs(loss.item() - 0.161739449523) < 1e-9

The batch provides comparison candidates without separately listing every negative example. However, an unmatched caption can still correctly describe another image. Such ambiguous pairs can give a misleading training signal and require attention to dataset construction.

At inference, either encoder can supply a vector for similarity-based retrieval. CLIP’s matching score does not itself generate a caption or answer a question. A task requiring text output needs an additional generation component.

Image captioning generates a description conditioned on visual features. Visual question answering, or VQA, also conditions on a question. A vision encoder can supply projected vectors to a language decoder through a supported combined-input or cross-attention interface.

The conditional-generation mechanics follow Chapter 18. The visual preprocessing and connection to the language model must match its training. A generic feature vector cannot simply be inserted into any unrelated text model.

Two other representation choices clarify this distinction. A vector-quantized variational autoencoder, or VQ-VAE, selects entries from a learned codebook, a finite table of vectors, to represent encoded input regions. Its decoder reconstructs the input from those selected vectors. Neural Discrete Representation Learning introduces this approach.

For encoded vector \((0.9,0.1)\) and codebook entries \((0,0)\), \((1,0)\), and \((0,1)\), the nearest entry is \((1,0)\). Its squared distance is \(0.02\), compared with \(0.82\) and \(1.62\) for the others. The selected entry’s index can be treated as a discrete token.

Training combines reconstruction with terms that keep the encoder outputs and codebook entries close. Nearest-entry selection is discrete. A common gradient approximation treats that selection as an identity operation for the encoder’s backward path. This is different from uniformly rounding a stored weight in Section 20.5.

The Vision-and-Language Transformer, or ViLT, processes projected image patches and text tokens together, avoiding a separate heavy convolutional region-feature stage. The ViLT paper describes this joint interaction architecture. It differs from CLIP’s separate encoders and pairwise output comparison.

In merged attention, image and text vectors enter one sequence after projection to a compatible width. Modality indicators distinguish their origins, while position information retains spatial or textual relationships. With two image patches and three text tokens, full self-attention compares five positions through a \(5\times5\) score matrix, excluding extra special tokens.

Cross-attention can instead connect separate streams. Three text queries attending to two image positions produce a \(3\times2\) score matrix. The query, key, and value mechanics remain those in Chapter 16. Separate encoders whose final vectors are only compared, as in CLIP, do not by themselves perform this cross-attention.

ViLT combines objectives for matching paired inputs, reconstructing selected text tokens, and relating words to patches. These supervision signals act on a representation where the modalities already interact. Cropping and flipping can expand image training variation, but an augmentation must preserve the caption or label’s meaning. Flipping an image described as “the cup on the left” can violate that condition.

The combined experiment in Section 24.7 evaluates retrieval separately from captioning and answering. That separation shows whether an error arose in matching evidence, interpreting the image, or producing the answer.

22.3 Audio samples and spectral frames

An audio recording changes over time rather than across an image grid. A waveform is a sequence of sampled amplitudes. Its sampling rate states how many samples represent one second, and its channels represent separate recorded signals.

Pulse-code modulation, or PCM, stores quantized amplitude samples. Bit depth controls the available amplitude codes. Sampling rate and bit depth describe different properties: temporal sampling and amplitude resolution.

A 44.1 kHz, 16-bit stereo recording stores 44,100 sample frames per second, each containing two channel values. Its uncompressed sample payload is \(44{,}100\times2\times2=176{,}400\) bytes per second, excluding headers. A model expecting mono at another rate needs an explicit channel conversion and resampling step.

A frequency analysis can reveal oscillations in these samples. Applying one Fourier transform to a whole recording does not retain a separate description of when each frequency occurs. The short-time Fourier transform, or STFT, analyzes a sequence of local windows instead.

For the complete-frame convention used here, each window contains \(N\) samples and the hop \(R>0\) is the distance between window starts. Frame \(m\) begins at sample \(mR\). Its transform is:

\[ X[m,k]=\sum_{n=0}^{N-1}x[mR+n]w[n]\exp\!\left(-\frac{2\pi i kn}{N}\right) \tag{22.6}\]

The local index \(n\) runs from zero to \(N-1\), so the waveform value is \(x[mR+n]\). The window \(w[n]\) weights those samples. The frequency-bin index is \(k\), and \(i\) denotes the imaginary unit. The complex result records magnitude and phase for that frame and frequency.

For four samples \((1,0,-1,0)\) and a rectangular window, the zero-frequency component is their sum, zero. The four-point transform is \((0,2,0,2)\) under this convention. The nonzero components capture the alternating structure that the zero-frequency sum misses.

The discrete Fourier transform, or DFT, is the finite transform evaluated above. A fast Fourier transform, or FFT, is an efficient algorithm for computing it. The FFT does not itself choose the windows or advance through time.

An inverse DFT reconstructs the windowed samples when the full complex coefficients and matching normalization are retained. Magnitudes alone discard phase. A mel representation also combines frequency bins, so it generally cannot be inverted to the original waveform exactly. Spectral features are a modeling choice: some systems learn directly from waveform samples.

Moving to another frame must advance the waveform indices. For samples \([0,0,0,0,1,1,1,1]\), window length four and hop four give zero-frequency sums zero and four. Shifting only the window while reusing the first four waveform samples would miss the second segment.

The number of complete left-aligned frames is:

\[ F=\left\lfloor\frac{S-N}{R}\right\rfloor+1,\quad S\ge N \tag{22.7}\]

Here \(S\) is the total sample count, and the expression assumes \(S\ge N\). Starts \(0,R,2R,\ldots\) are valid when \(mR+N\le S\). Counting from frame zero produces the final plus one. If \(S<N\), this convention yields zero complete frames and handles that case separately.

For \(S=8\), \(N=4\), and \(R=4\), starts zero and four give two frames. For \(S=10\), \(N=4\), and \(R=3\), starts zero, three, and six give three. Centering or padding in a library call can produce a different frame count.

The following NumPy calculation checks the spectrum, advancing frame indices, and the short-input case under this exact convention.

Code example: Complete spectral frames with explicit sample indices

import numpy as np

def complete_stft(samples, window, hop):
    samples = np.asarray(samples, dtype=float)
    window = np.asarray(window, dtype=float)
    if samples.ndim != 1 or window.ndim != 1 or len(window) == 0:
        raise ValueError("Use one-dimensional samples and a nonempty window")
    if not isinstance(hop, int) or hop <= 0:
        raise ValueError("Hop must be a positive integer")
    width = len(window)
    starts = range(0, len(samples) - width + 1, hop)
    frames = [np.fft.fft(samples[start:start + width] * window) for start in starts]
    return np.stack(frames) if frames else np.empty((0, width), dtype=complex)

single = complete_stft([1, 0, -1, 0], np.ones(4), 4)
shifted = complete_stft([0, 0, 0, 0, 1, 1, 1, 1], np.ones(4), 4)
np.testing.assert_allclose(single[0], [0, 2, 0, 2])
np.testing.assert_allclose(shifted[:, 0], [0, 4])
assert shifted.shape == (2, 4)
assert complete_stft(np.arange(10), np.ones(4), 3).shape == (3, 4)
assert complete_stft([1, 2], np.ones(4), 2).shape == (0, 4)
print(single, shifted[:, 0])

Stacking the frame spectra produces a time-frequency matrix. A mel filterbank groups spectral energy into perceptually spaced frequency bands. A mel spectrogram records these band values over time, often followed by logarithmic scaling.

Whisper is an encoder-decoder speech model that processes log-mel audio features and generates text tokens. Its overall feature-to-encoder-to-decoder path is described in Robust Speech Recognition. This chapter’s four-sample example illustrates the transform, not Whisper’s actual preprocessing dimensions.

The model’s expected sample rate, window settings, channel handling, and feature scaling must be preserved. Recognition quality can differ across languages, recording conditions, and domains. A strong result on one language or dataset does not establish performance on another.

Different output requirements explain the other audio systems discussed in the course. wav2vec 2.0 learns speech representations from waveform input. It masks latent positions and trains a contrastive prediction against quantized targets. Fine-tuning with transcriptions then supports speech recognition. This representation-learning model is not a waveform decoder.

AudioLM instead generates audio continuations through discrete token sequences. Semantic tokens describe longer-range structure, while acoustic tokens retain details needed by an audio codec’s decoder. Predicting more tokens extends an audio prompt, and decoding their acoustic representation returns a waveform. Text token generation alone cannot reconstruct those acoustic details.

SpeechVerse connects representations from a speech model to a language model through a small set of trainable parameters. Audio and a textual instruction can then condition a text response, such as a transcription or task answer. The speech and text base models stay frozen in its described training setup. Its interface combines the adaptation principle from Chapter 20 with the cross-modal connections discussed above.

These systems have different outputs: recognition text, generated audio, or an instruction-conditioned answer. Choose an evaluation that matches the output. A correct transcript does not establish natural audio synthesis, and plausible audio does not establish transcription accuracy.

22.4 Tabular fields

A table row has distinct fields whose types and units can differ. Its column order is usually a schema convention rather than the time or spatial order of a signal. The representation should preserve field identity and missing-value meaning.

Categorical values can select embedding rows, following Chapter 13. Numeric values can be standardized using training-set statistics or passed through learned projections. Missing values need an explicit indicator or handling rule rather than an accidental ordinary value.

TabTransformer uses attention over categorical field embeddings. Other tabular transformer designs also turn numeric fields into vectors. The details differ, so a schema-to-vector mapping must identify both the value and its field.

In the original TabTransformer arrangement, the contextual categorical vectors are concatenated with normalized numerical fields before an MLP predicts the target. For three categorical vectors of width four and two numeric values, that classifier receives \(3(4)+2=14\) coordinates. This separates attention over categories from the final mixed-field prediction.

For a design that represents every field, \(B\) records with \(F\) fields can produce a tensor \([B,F,D]\). Attention compares fields within each record. It does not make identically encoded values from different columns interchangeable.

The course also compares gradient-boosted decision trees, an ensemble that adds trees sequentially to improve the current predictions under a loss. Trees partition feature values through decision rules, providing a different way to model nonlinear field interactions.

A regularized linear model and boosted trees provide useful comparison points for supervised tables. Match their training and validation splits and compare quality, missing-value behavior, and resource cost. A transformer can be useful when its representations or transfer learning offer an advantage, but table format alone does not establish that advantage.

22.5 Choosing the input model

Each conversion preserves some structure and discards other detail. A model choice should follow the required output and observed errors, together with the cost of processing its representations.

Input or task | Representation and comparison | |—|—| | Image classification | Compare local convolutional features with patch-based models under the required resolution and data budget | | Speech transcription | Preserve the time axis and preprocessing contract, then compare suitable sequence models on the target recordings | | Supervised table | Preserve field types and missing values, with linear and tree baselines alongside richer models | | Image-text retrieval | Compare normalized representations and inspect the ranking of relevant candidates | | Captioning or VQA | Evaluate generated text conditioned on image features, separating visual errors from response errors |

The expensive stage can be input feature extraction, attention over many patches or frames, or output generation. Expert routing, if present, follows Section 17.6 and adds its own scheduling costs. It is not an input modality.

The final system exercise in Section 24.7 records component outputs and combined failures. Chapter 23 first examines how these representations occupy tensor storage, so memory measurements can be interpreted correctly.
