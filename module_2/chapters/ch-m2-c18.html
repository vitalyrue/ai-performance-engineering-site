18  Transformer architectures

A transformer block defines how representations change. The complete architecture also determines which inputs each prediction can use and where its targets come from. Those choices connect the same block components to classification, text completion, and translation.

We compare information flow first, then construct the corresponding training records and inference interfaces. This separates a model’s structure from the application expressed through it.

18.1 Architecture families

The block in Chapter 17 preserves a sequence of representations. Its visibility mask and connections determine which sequence those representations describe. Three common architecture families organize that information differently.

An encoder-only transformer creates representations of an available input sequence, commonly using bidirectional self-attention. A decoder-only transformer uses causal self-attention to support left-to-right prediction. An encoder-decoder transformer represents a source sequence with an encoder and generates a separate target sequence with a decoder.

The encoder-decoder’s target side uses causal self-attention over earlier target inputs. Its cross-attention reads the encoded source, following Section 16.4. Source and target lengths can differ.

Example task | Visible information | Output and target | |—|—|—| | Encoder-only review classification | All valid review tokens | One pooled representation feeds class logits, compared with the review label | | Decoder-only continuation | The current input token and preceding inputs | Each eligible position produces logits for its following token | | Encoder-decoder translation | Complete encoded source and the available target prefix | Each target position predicts the next target-language token |

The application does not uniquely determine the family. A decoder can classify an article by generating its category text. An encoder can supply vectors for retrieval or feed a token-labeling head. These interfaces require different target formats even when the user asks for the same final decision.

Architecture also does not uniquely determine the training objective. The objective must respect available information, but an encoder can learn from classification, reconstruction, or other suitable targets.

18.2 Training objectives

A legal attention pattern establishes what the model can see. A training objective specifies which prediction errors change its parameters. Comparing the target sets makes the differences between model families concrete.

Causal language modeling predicts a sequence through its next-token conditional probabilities. Its summed loss is:

\[ L_{\mathrm{CLM}}=-\sum_t\log P_{\theta}(x_t\mid x_{<t}) \tag{18.1}\]

The target shift and valid-position reduction are established in Section 1.2 and Section 8.2. For IDs \([4,8,9]\), the manual input-target pairs are \([4,8]\) and \([8,9]\). This familiar alignment remains the same inside a causal transformer.

If two targets receive probabilities \(0.5\) and \(0.25\), their summed loss is approximately \(2.079442\). Averaging instead gives approximately \(1.039721\) per supervised token. State which reduction is being compared.

Masked language modeling, or MLM, predicts selected hidden tokens from the remaining context. Let \(M\) contain the selected target positions.

\[ L_{\mathrm{MLM}}=-\sum_{t\in M}\log P_{\theta}(x_t\mid x_{\mathrm{visible}}) \tag{18.2}\]

For “the cat sat”, select the middle token and supply “the [MASK] sat”. The target is “cat” at the selected position. The model may use both neighboring words, but it must not read the unchanged target token at that position.

Only selected positions contribute to this simplified masked objective. With two target probabilities \(0.8\) and \(0.4\), their summed loss is \(-\log(0.8)-\log(0.4)\approx1.139434\). Original token IDs elsewhere supply context rather than additional targets in this record.

Actual masking recipes can also replace selected tokens with random words or retain some unchanged inputs. Those choices alter the training corruption process and must be recorded explicitly. The simple example above uses explicit masking throughout.

Original BERT also used next sentence prediction, or NSP, alongside masked-token loss. Its input paired two text segments, and a binary classifier predicted whether the second followed the first in the source. Their combined objective trained token reconstruction and a segment-level decision. Later encoder models need not use NSP, so masked-token training alone does not imply this additional objective.

The pair uses the structural tokens from Section 3.3: [CLS] A [SEP] B [SEP]. BERT’s final representation at [CLS] feeds the NSP classifier. Learned segment embeddings also tell the model whether each token belongs to A or B. The separator marks a boundary, while the segment embedding adds membership information at every position. These distinct roles are shown in the original BERT input specification.

Sequence-to-sequence training predicts a target sequence conditioned on a separate source. Its objective is:

\[ L_{\mathrm{seq2seq}}=-\sum_t\log P_{\theta}(y_t\mid y_{<t},x_{\mathrm{source}}) \tag{18.3}\]

Here \(x_{\text{source}}\) is the full source and \(y_{<t}\) is the earlier target prefix. During training, teacher forcing supplies the recorded earlier target tokens, as in Section 15.4. The encoder provides source representations independently of that target shift.

For two target probabilities \(0.5\) and \(0.25\), the summed loss is again approximately \(2.079442\). The arithmetic matches the causal example, while the conditional information includes a separate source sequence.

Some encoder-decoder pretraining uses denoising, which reconstructs clean text from a corrupted version. Missing spans become targets, and the corrupted text supplies the source. This uses the same source-target interface as other conditional sequence tasks.

These objectives evaluate different conditions and target sets. Their raw losses cannot be compared fairly without matching tokenization, reduction, and evaluation protocol. Masked-token conditional probabilities also do not automatically form the left-to-right sequence likelihood used by a causal model.

18.3 Model interfaces

An objective becomes executable only when its input and target records match the model interface. A pretrained checkpoint contains parameters learned before the current task-specific adaptation. Loading it does not determine how a new dataset should be formatted.

For encoder classification, one record can contain a review’s token IDs, its validity mask, and one integer class label. A task head consumes the encoder representation. Its loss compares class logits with that label, using the classification mechanics in Chapter 8.

For a decoder-only instruction model, a record combines the instruction, optional evidence, and answer into one token sequence. At generation time, only the instruction and available evidence are supplied. At training time, a loss mask can supervise answer tokens while keeping the prompt as visible context.

For an encoder-decoder model, the source instruction and target answer are separate sequences. Source padding and target padding can therefore have different lengths and masks. The target decoder receives shifted target inputs, usually prepared from labels by the model’s supported training interface.

The model class must match that architecture. Hugging Face’s AutoModelForSequenceClassification supplies a task head, AutoModelForCausalLM supplies a causal generation head, and AutoModelForSeq2SeqLM supports an encoder-decoder generation interface. Their label conventions must be checked for the actual checkpoint and library version.

Some causal language-model APIs shift labels internally, allowing labels initially copied from the input IDs. Applying another manual shift would misalign predictions. The manual calculation in Section 8.2 establishes what the API must implement, without requiring every API to accept the same tensors.

The distinction from Section 1.1 concerns what probability is modeled. A discriminative classifier estimates \(P(y\mid x)\) for labels. A generative model can describe \(P(x)\) or a joint distribution \(P(x,y)\). Conditional generation produces structured or textual outputs given an input context.

Prompted classification, extraction, translation, and open-ended writing can all use conditional token generation. The interface changes how the task is expressed, while the decoder still produces token distributions. Generated label text may require parsing and validity checks that an integer class head avoids.

For a causal sequence with conditional probabilities \(0.5\), \(0.4\), and \(0.25\), the sequence probability is \(0.05\). This follows the factorization in Section 1.2. Changing architecture or prompt format does not remove the need to define what sequence and conditioning information that probability describes.

The paired model experiment in Section 24.6 uses causal and encoder-decoder checkpoints with their respective formats. It compares task outputs under one rubric rather than treating their raw training tensors as interchangeable.

18.4 Iterative generation

Causal generation commits to successive tokens through a growing prefix. Another approach begins with an incomplete sequence and refines several positions over multiple passes. This changes the generation procedure as well as its dependencies.

A diffusion language model learns to reverse a corruption process applied to text representations. In masked-token approaches, training hides tokens at varying corruption levels and learns to recover them. Generation repeatedly predicts and reveals or revises selected positions. Large Language Diffusion Models develops one such formulation.

For an illustrative three-position output, a procedure might begin with “[MASK] [MASK] [MASK]”, retain “cat” at the middle position, and refine the remaining positions. The actual sampler determines which proposals to keep, which to mask again, and when to stop. This is a mechanism sketch, not a claimed output from a trained model.

Several positions can be processed together within a pass, but refinement passes still depend on earlier passes. Cost therefore depends on output length, number of passes, architecture, and implementation. Parallel updates alone do not establish lower latency or better output quality.

This comparison concerns text generation. It is separate from the expert routing in Section 17.6 and the model-compression methods in Section 20.6. Those choices change activated or stored parameters rather than defining this refinement procedure.

All these models still need suitable training examples. Chapter 19 examines how corpus selection, packing, and compute allocation shape the distribution on which an objective is optimized.

Chapter checkpoint

Two systems classify the same review. One returns class logits and the other generates a category string. Which parts of their evaluation can be shared, and which need different checks?

Feedback: Both can be evaluated against the same category targets and split. The generative system also needs a rule for parsing invalid or unexpected label text. Its token loss is not directly the classifier’s class loss.

A masked-token model has a lower loss than a causal model. Does this show that it is better at continuation?

Feedback: Not by itself. It may see right context and predict a different subset of tokens. Evaluate both on the intended task with an appropriate common protocol.
