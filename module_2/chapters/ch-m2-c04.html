4  Count vectors and TF-IDF

A topic classifier can often learn useful distinctions from the words an article contains. Before building a model that follows every token position, we can test a simpler representation: count selected words or phrases and give every document the same feature coordinates.

Count vectors and TF-IDF provide this representation. They make the connection between a document and its numerical features visible, while exposing what is lost when most word order is discarded.

4.1 Counting text

Suppose two articles contain cat, sat, and dog in different amounts. Assigning one coordinate to each of these terms lets us compare the articles using the same measurements. A bag-of-words representation records term counts while discarding their order. A count vector stores those counts in a fixed vocabulary order.

For vocabulary [cat, sat, dog], the text cat sat cat becomes \([2,1,0]\). The first coordinate counts cat, the second counts sat, and the third counts dog. Swapping the vocabulary order without rearranging the vector would change its meaning.

The count at one coordinate is:

\[ \operatorname{BoW}(d)_j=\operatorname{count}(t_j\in d) \tag{4.1}\]

Here \(d\) is the document, \(t_j\) is the term assigned to coordinate \(j\), and \(\operatorname{BoW}(d)_j\) is its count. Scanning the document increments the selected coordinate whenever the term occurs. The vector width depends on the vocabulary, rather than the document’s length.

We can count longer local patterns as well. An n-gram is a contiguous sequence of \(n\) tokens. A unigram contains one token, a bigram contains two, and a trigram contains three. Sliding a two-token window over new york new york produces new york, york new, and new york. The first bigram therefore has count 2.

\[ \phi_{\mathrm{ngram}}(d)_g=\operatorname{count}(g\in d) \tag{4.2}\]

The symbol \(g\) identifies one n-gram, and \(\phi_{\mathrm{ngram}}(d)_g\) gives its feature count. Each retained n-gram has its own coordinate. Bigrams preserve evidence of adjacent order, although they do not retain the full sequence. An n-gram feature counts a pattern within a document. An n-gram language model uses context counts to predict a next token, which is a different operation.

The unit being counted must be fixed before interpreting a coordinate. Word, character, and subword features create different vocabularies. The figure compares those choices at the feature-construction stage.

A character feature can remain useful inside an unfamiliar word. A word feature is easier to interpret directly but treats different spellings as distinct terms. Combining unigrams and bigrams expands the feature space, so the choice affects storage as well as the evidence a model can use.

To process several documents, stack their feature vectors into a document-term matrix. Each row represents a document, and each column represents the same vocabulary feature in every row:

\[ X\in\mathbb{R}^{N\times\lvert V\rvert} \tag{4.3}\]

The matrix \(X\) has \(N\) document rows and \(|V|\) feature columns. For 10 documents and 500 retained features, its shape is \([10,500]\). A batch of \(B\) selected documents uses the same feature columns, giving shape \([B,|V|]\).

Most documents contain only a small fraction of a large vocabulary. A sparse matrix stores the nonzero values and information identifying their positions, rather than storing every zero explicitly. The vocabulary axis still contains every retained feature, including those absent from a particular document.

A feature vector can also combine measurements chosen for a task. The course’s sentiment example uses six coordinates: positive-word count, negative-word count, presence of no, pronoun count, presence of !, and log word count.

For a concrete version, lowercase the text and separate punctuation from words. Let the positive lexicon contain good, the negative lexicon contain bad, and the pronoun list contain i and you. The text I feel good, no bad news! has six words and gives \((1,1,1,1,1,\log 6)\). Its last coordinate is approximately \(1.792\).

The presence indicators are 1 when their condition holds and 0 otherwise. The logarithm compresses differences in document length, so a tenfold length increase adds \(\log 10\) to this feature. An empty document needs a separate rule because \(\log 0\) is undefined. Using \(\log(1+\text{word count})\) is one possible change, which must be applied consistently.

These measurements encode the designer’s assumptions about sentiment. Counting no does not identify which phrase it negates, and a small lexicon can miss domain-specific meanings. Learned features in Chapter 12 address a different question: which transformations of the supplied measurements should training adjust?

Counts expose which terms occur, but a common term may contribute little to distinguishing documents. Weighting addresses that limitation.

4.2 Weighting terms with TF-IDF

A word repeated within one article may be informative. A word appearing in almost every article may be less useful for distinguishing topics. Term frequency-inverse document frequency, or TF-IDF, combines these two observations.

The term frequency \(\mathrm{tf}_{d,j}\) measures how often term \(j\) appears in document \(d\). Here it is the raw count. The document frequency \(\mathrm{df}_j\) counts how many fitted documents contain that term at least once. Repeating a word ten times within one document increases its term frequency, but adds only one to its document frequency.

The following unsmoothed teaching formula combines the two:

\[ \mathrm{tfidf}_{d,j}=\mathrm{tf}_{d,j}\log\left(\frac{N}{\mathrm{df}_j}\right) \tag{4.4}\]

There are \(N\geq1\) fitted documents, and a retained term has \(1\leq\mathrm{df}_j\leq N\). The inverse-document-frequency factor is \(\log(N/\mathrm{df}_j)\), using the natural logarithm. A term present in every fitted document gives ratio 1 and logarithm 0. A rarer term gives a larger positive factor.

If a term appears three times in one document and in 10 of 100 fitted documents, its weight is \(3\log(100/10)=3\log(10)\approx6.91\). Its within-document repetition increases the weight. Its occurrence in only one tenth of the corpus keeps the inverse-document-frequency factor substantial.

This weighting changes the values of the feature coordinates, while retaining their vocabulary meanings. It does not create a learned semantic relationship between different words. It also depends on the fitted corpus, so the same count can receive a different weight when the corpus changes.

Library defaults can use a different formula. Scikit-learn’s default smoothed factor is \(1+\log((1+N)/(1+\mathrm{df}_j))\). It then normalizes each nonzero document row by its Euclidean length. That length is the square root of the sum of squared row entries. The resulting row has length 1, so a longer document is not larger merely because all its counts are larger.

For \(N=3\) and \(\mathrm{df}_j=2\), the smoothed factor is \(1+\log(4/3)\approx1.288\) before row normalization. This differs from the unsmoothed factor \(\log(3/2)\approx0.405\). A comparison with the unsmoothed formula must therefore state both smoothing and normalization settings.

The vocabulary and document frequencies must now be fitted without allowing held-out data to influence the representation.

4.3 Fitting the representation

A model evaluated on new documents needs the same feature coordinates that it received during training. Fitting a vectorizer establishes its vocabulary and, for TF-IDF, its document-frequency statistics. Transforming text applies those established objects to another document collection.

Fit on the training split, then transform the validation and test splits. Fitting again on validation text could add columns, change their order, and alter the weights. Even when the final matrix shape stays the same, using held-out text to choose the representation changes the experiment’s information boundary.

The runnable scikit-learn example below fits unigrams and bigrams on three training documents. A count vectorizer supplies the vocabulary. A TF-IDF vectorizer then uses that same vocabulary and learns its document frequencies from the same training documents. The final transformation processes one new document without refitting.

Code example: Count and TF-IDF matrices with a fixed training vocabulary

from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer

train_documents = ["cat sat", "dog sat", "cat chased dog"]
new_documents = ["dog chased cat"]

counts = CountVectorizer(ngram_range=(1, 2))
X_count = counts.fit_transform(train_documents)

tfidf = TfidfVectorizer(vocabulary=counts.vocabulary_, ngram_range=(1, 2))
X_tfidf = tfidf.fit_transform(train_documents)
X_new_tfidf = tfidf.transform(new_documents)

print(counts.get_feature_names_out())
print(X_count.shape, X_tfidf.shape, X_new_tfidf.shape)
print(X_count.toarray())

The feature list is cat, cat chased, cat sat, chased, chased dog, dog, dog sat, and sat. Both training matrices have shape \([3,8]\), and the new TF-IDF matrix has shape \([1,8]\). Their rows differ in value, while the columns retain the same meanings.

For cat sat, the count row is \([1,0,1,0,0,0,0,1]\). For dog sat, it is \([0,0,0,0,0,1,1,1]\). For cat chased dog, it is \([1,1,0,1,1,1,0,0]\). These values account separately for individual words and retained adjacent pairs.

The new document dog chased cat contains known unigrams, but its bigrams dog chased and chased cat are absent from the fitted vocabulary. They do not create new columns. A document containing no retained feature can produce a zero row, which requires a deliberate downstream policy.

The matrices remain sparse. Calling toarray() in the example makes the small counts visible, but allocating a dense copy of a large document-term matrix can consume substantial memory. Libraries such as scipy.sparse store these matrices, and a compatible classifier can operate on their sparse representation.

The corpus is deliberately small so each column can be checked. It supports an implementation demonstration, rather than a meaningful comparison of classifier quality.

4.4 Limits of count features

Two inputs can have identical count vectors while expressing different meanings. The phrases good not bad and bad not good have the same unigram counts. A classifier using those counts receives the same representation for both. No choice of classifier weights can recover the discarded order from that identical input.

Bigrams distinguish some such cases, but a fixed local window cannot represent every long-distance relationship. Vocabulary identity creates another limitation: car and automobile occupy different coordinates, so the representation itself supplies no evidence of their similarity. Training a classifier may still learn similar weights for them when the data supports that association.

Count features remain useful when transparency, limited training data, or a simple baseline matters. A coordinate can be traced directly to a word or phrase. Dense representations use many nonzero values in a smaller coordinate space. Learned embeddings are one such representation, developed in Chapter 13. Their coordinates are adjusted during training and need not correspond to individual words.

Sparse document features and token embeddings are alternative starting representations. A sequence model can look up embeddings directly from token IDs. It does not need to turn a document into bag-of-words counts first. Conversely, a sparse classifier can use count or TF-IDF features without an embedding table.

We have now constructed numerical inputs with fixed, interpretable axes. The next chapter introduces the model coefficients that act on those inputs, then calculates one score for each possible class. That multiplication will consume the feature axis and produce a distinct class axis.
