11  Momentum and AdamW

Backpropagation has supplied a gradient for each relevant parameter. A training procedure must now decide how far to move and whether previous gradients should influence that step. Different choices can change convergence, memory use, and behavior on held-out examples.

This chapter compares update rules using explicit state and arithmetic. It then separates parameter penalties, learning-rate schedules, and gradient clipping, which affect different parts of the training procedure.

11.1 Gradient estimates

The basic gradient-descent step uses the derivative of a stated objective. Computing it from every training example before each update can be expensive. Full-batch gradient descent uses the whole training set, stochastic gradient descent uses one sampled example, and mini-batch gradient descent uses a group of examples. In common software terminology, SGD also includes mini-batch updates.

For a batch index set \(B\), average its per-example gradients:

\[ g_B=\frac{1}{\lvert B\rvert}\sum_{i\in B}\operatorname{grad}L_i(\theta) \tag{11.1}\]

The cardinality \(|B|\) is its number of examples, and \(L_i\) is the loss for example \(i\) at the current parameters \(\theta\). With individual gradients \([1,3]\) and \([-1,5]\), the batch gradient is \(([1,3]+[-1,5])/2=[0,4]\).

Under representative sampling, a mini-batch gradient estimates the full empirical-risk gradient. Its value varies with the sampled examples. Increasing batch size generally reduces that sampling variation under comparable conditions, while increasing intermediate storage and changing the number of updates per pass through the dataset.

The update uses that estimate:

\[ \theta_{t+1}=\theta_t-\eta\,\operatorname{grad}L(\theta_t) \tag{11.2}\]

The index \(t\) counts parameter updates, and \(\eta\) is the learning rate. The formula matches the earlier basic step. Parameter 1 with gradient 3 and learning rate 0.1 becomes 0.7. A larger step can overshoot and increase the loss. A small step may require many updates before the loss changes appreciably.

The figure follows one parameter from its current value through a gradient step. The update moves opposite to the gradient direction, with its size set by the learning rate.

The runnable PyTorch example uses the same three-example classifier as Chapter 10. Creating torch.optim.SGD replaces the manual parameter assignment with a library-managed step. The forward, backward, and buffer-clearing mechanics remain those already derived.

Code example: One optimizer step on the running logistic-regression batch

import torch
import torch.nn.functional as F

X = torch.tensor([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]])
y = torch.tensor([1.0, 0.0, 1.0])
w = torch.tensor([0.8, -0.3], requires_grad=True)
b = torch.tensor(0.1, requires_grad=True)
optimizer = torch.optim.SGD([w, b], lr=0.1)

optimizer.zero_grad()
loss = F.binary_cross_entropy_with_logits(X @ w + b, y)
loss.backward()
optimizer.step()

print(loss.item(), w.detach(), b.detach())

The printed loss is the value calculated before the step. The printed parameters are their values after it. Plain SGD in this configuration uses the current gradient without a persistent momentum or squared-gradient buffer. Adding history changes that behavior.

11.2 Momentum

Successive gradients can agree in one direction while oscillating in another. Momentum combines the current gradient with a decayed history. It stores a velocity tensor having the same shape as its parameter:

\[ v_{t} = \beta v_{t-1} + g_{t},\quad\quad \theta_{t+1} = \theta_{t} - \eta v_{t} \tag{11.3}\]

The current gradient is \(g_t\), the stored velocity is \(v_t\), and \(0\leq\beta<1\) controls decay. This convention adds the new gradient without a factor of \(1-\beta\). It is an exponentially weighted sum. Another convention includes that factor and produces an exponential moving average, so coefficients and learning rates must be compared with the convention stated.

With \(\beta=0.9\), previous velocity 0.2, and current gradient 0.5, the new velocity is \(0.9(0.2)+0.5=0.68\). At learning rate 0.1, its contribution to the parameter step is 0.068. Repeated gradients in the same direction reinforce the stored velocity, while alternating contributions can partly cancel.

Momentum differs from simply increasing the learning rate because the step depends on previous directions. It can also carry the parameters in a direction that no longer matches the current gradient. Its benefit depends on the objective and settings, rather than a guarantee of escaping every plateau or minimum.

Each parameter needs one additional velocity buffer. Momentum retains signed direction history. The next methods track coordinate scales instead.

11.3 Adaptive scaling

Different parameter coordinates can receive gradients with very different magnitudes. A single global learning rate does not account for that difference. Adaptive scaling uses a stored magnitude statistic for each coordinate when calculating its update.

An elementwise square squares each coordinate independently. For gradient \([2,-3]\), the squared vector is \([4,9]\). This removes sign and records scale. An optimizer accumulator stores such information across updates.

AdaGrad adds every squared gradient to a cumulative state:

\[ G_{t} = G_{t-1} + g_{t}^{2},\quad\quad \theta_{t+1} = \theta_{t} - \eta\,\frac{g_{t}}{\sqrt{G_{t}} + \epsilon} \tag{11.4}\]

Here \(G_t\) is the nonnegative accumulated state, and the square root and division act coordinatewise. The positive constant \(\epsilon\) stabilizes division when the state is very small. Coordinates receiving repeated large gradients develop larger denominators.

Take two successive scalar gradients of 2, initial \(G_0=0\), and learning rate 0.1. Then \(G_1=4\) and \(G_2=8\). Ignoring a negligible \(\epsilon\) for this arithmetic, the two step magnitudes are \(0.1(2)/\sqrt4=0.1\) and \(0.1(2)/\sqrt8\approx0.0707\).

The cumulative state never decreases. This can help coordinates that occur infrequently, but can make later steps very small after a long history. RMSprop instead keeps a decaying average of squared gradients:

\[ s_{t} = \beta s_{t-1} + (1-\beta)g_{t}^{2},\quad\quad \theta_{t+1} = \theta_{t} - \eta\,\frac{g_{t}}{\sqrt{s_{t}} + \epsilon} \tag{11.5}\]

The state \(s_t\) emphasizes recent magnitudes, with decay \(0\leq\beta<1\). For the same two gradients and \(\beta=0.5\), \(s_1=0.5(4)=2\) and \(s_2=0.5(2)+0.5(4)=3\). The corresponding step magnitudes are about 0.1414 and 0.1155 when the stabilizer is negligible.

This does not imply that RMSprop steps always exceed AdaGrad steps. The values depend on the history, decay, learning rate, and stabilizer. Both methods scale coordinates using unsigned statistics, while momentum carries signed history. Adam combines those roles.

11.4 Adam

Adam keeps two moving averages per parameter coordinate. Its first-moment estimate retains signed gradient information:

\[ m_{t} = \beta_{1}m_{t-1} + (1-\beta_{1})g_{t} \tag{11.6}\]

Its second-moment estimate retains squared-gradient information:

\[ v_{t} = \beta_{2}v_{t-1} + (1-\beta_{2})g_{t}^{2} \tag{11.7}\]

The symbols \(m_t\) and \(v_t\) denote those states, and \(\beta_1\) and \(\beta_2\) are their decay coefficients. Both start at zero in the standard initialization. After only a few updates, their accumulated weights sum to less than one. Adam compensates with bias correction:

\[ \widehat{m}_{t} = \frac{m_{t}}{1-\beta_{1}^{t}},\quad \widehat{v}_{t} = \frac{v_{t}}{1-\beta_{2}^{t}} \tag{11.8}\]

For a constant gradient, the first-moment weights sum to \(1-\beta_1^t\). Dividing by that quantity recovers the constant gradient exactly. The corresponding second-moment correction uses \(1-\beta_2^t\). This accounts for zero initialization, while the states still reflect their chosen moving histories when gradients vary.

The parameter update combines the corrected direction and scale:

\[ \theta_{t+1} = \theta_{t} - \eta\,\frac{\widehat{m}_{t}}{\sqrt{\widehat{v}_{t}}+\epsilon} \tag{11.9}\]

The square root and division remain coordinatewise, with \(\epsilon>0\). The denominator is a scale estimate, not an independent learning-rate schedule.

For first gradient \(g_1=2\), \(\beta_1=0.9\), and \(\beta_2=0.99\), the raw states are \(m_1=0.1(2)=0.2\) and \(v_1=0.01(4)=0.04\). Their corrections give \(\hat m_1=0.2/0.1=2\) and \(\hat v_1=0.04/0.01=4\). With learning rate 0.1 and negligible stabilizer, the step is \(0.1(2)/\sqrt4=0.1\).

Compare a negative-gradient case: parameter 0.6, gradient \(-0.4\), and learning rate 0.1. SGD produces \(0.6-0.1(-0.4)=0.64\). Adam with \(\beta_1=0.9\) and \(\beta_2=0.999\) starts with \(m_1=-0.04\) and \(v_1=0.00016\). Bias correction gives \(\hat m_1=-0.4\) and \(\hat v_1=0.16\), producing approximately 0.70 after the update.

Adam’s larger step in this example comes from normalizing the gradient magnitude. It is not a general promise of more aggressive or steadily decreasing steps. Under a constant nonzero gradient and a negligible stabilizer, corrected Adam keeps approximately the same step magnitude at a fixed learning rate. Changing gradients and accumulated direction can produce other behavior.

The parameter, gradient, and two Adam states have matching coordinate counts. With four-byte values, the two moments add eight bytes per parameter beyond parameter and gradient storage. Actual implementations may use different precisions and additional buffers. The extra state also requires memory reads and writes during updates, which the storage chapter examines in context.

11.5 Regularization

Improving training fit can worsen held-out behavior. Regularization constrains fitting, for example by penalizing large parameters or perturbing intermediate representations. Its settings must be judged with the validation procedure.

An L2 penalty adds the squared parameter length to the data loss:

\[ L_{\mathrm{total}} = L_{\mathrm{data}} + \lambda\,\theta^{T}\theta \tag{11.10}\]

The coefficient \(\lambda\geq0\) controls its strength, and \(\theta^\top\theta=\sum_i\theta_i^2\). For \(\theta=[3,4]\) and \(\lambda=0.1\), the added penalty is \(0.1(9+16)=2.5\). If the data loss is the empirical risk, the regularized objective is equivalently \(J(\theta)=\widehat R(\theta)+\lambda\theta^\top\theta\).

Differentiating this penalty adds \(2\lambda\theta\) to the data gradient. For plain gradient descent, the update becomes:

\[ \theta_{t+1} = \theta_{t} - \eta\,(g_{t} + 2\lambda\theta_{t}) \tag{11.11}\]

The symbol \(g_t\) denotes the gradient of the data loss alone. With \(\theta_t=1\), \(g_t=0.4\), \(\eta=0.1\), and \(\lambda=0.01\), the next value is \(1-0.1(0.4+0.02)=0.958\). Some texts use a penalty \(\lambda\|\theta\|^2/2\), which removes the factor 2 from its derivative. Keep the convention fixed when comparing coefficients.

An L1 penalty instead adds absolute parameter magnitudes:

\[ L_{\mathrm{total}} = L_{\mathrm{data}} + \lambda\sum_{i}\lvert\theta_{i}\rvert \tag{11.12}\]

For \(\theta=[3,-4]\) and \(\lambda=0.1\), the penalty is \(0.1(3+4)=0.7\). Away from zero, its derivative is \(\lambda\) times the parameter’s sign. At zero, absolute value has a corner and no unique ordinary derivative. The update procedure must handle that point explicitly.

L1 can encourage sparse parameter vectors, but ordinary gradient steps do not guarantee exact zeros. A thresholding update for a candidate value \(a\) can use \(\operatorname{sign}(a)\max(|a|-\eta\lambda,0)\). Values with magnitude at most \(\eta\lambda\) become zero. For \(a=0.03\) and \(\eta\lambda=0.05\), the result is zero. The regularization experiment counts retained coefficients, so record whether its update uses ordinary gradient steps or this thresholding operation.

Dropout perturbs activations during training instead of directly penalizing parameter magnitudes. With drop probability \(q\in[0,1)\), sample \(m_j\sim\operatorname{Bernoulli}(1-q)\) and use \(\widetilde h_j=m_jh_j/(1-q)\). The scaling preserves each activation’s expected value because the mask’s mean is \(1-q\).

For \(h=[2,-4]\), \(q=0.5\), and mask \([1,0]\), the output is \([4,0]\). During evaluation, dropout is disabled and the output is \(h\). Too much dropout can remove useful signal. In PyTorch, model.eval() changes module behavior such as dropout, while torch.no_grad() separately controls gradient recording.

Early stopping uses validation evidence to select when training ends. It does not add an L1 or L2 penalty. These interventions can improve transfer in some settings, but none guarantees it. In adaptation, overfitting can include memorizing narrow examples or losing useful behavior outside the adaptation data.

11.6 Weight decay and schedules

An L2 penalty and direct parameter shrinkage coincide under a suitable coefficient convention for plain gradient descent. With adaptive updates, adding the penalty to the gradient also changes the moment states and their scaling. Decoupled weight decay keeps shrinkage separate from that calculation.

AdamW computes Adam’s moments from the supplied data gradient and applies a separate decay term:

\[ \theta_{t+1} = \theta_{t} - \eta\,\frac{\widehat{m}_{t}}{\sqrt{\widehat{v}_{t}}+\epsilon} - \eta\lambda\theta_{t} \tag{11.13}\]

Here \(\lambda\) is the decay coefficient, rather than automatically the same numerical coefficient as the earlier L2 penalty. The term \(-\eta\lambda\theta_t\) acts directly on parameters. It is not divided by the second-moment denominator.

If the current parameter is 1, the adaptive contribution is 0.02, and the decay contribution is 0.001, the next parameter is \(1-0.02-0.001=0.979\). The choice of parameters receiving decay also matters. An implementation may exclude selected biases or normalization parameters by using separate parameter groups.

A learning-rate schedule changes \(\eta\) over training. Warmup begins with smaller values before reaching a target rate. A simple linear version is:

\[ \eta_{t} = \eta_{\max}\,\min\!\left(1,\frac{t}{T_{\mathrm{warmup}}}\right) \tag{11.14}\]

The target rate is \(\eta_{\max}\), and \(T_{\mathrm{warmup}}>0\) counts warmup updates. With \(\eta_{\max}=0.001\) and 1,000 warmup steps, step 250 uses 0.00025. The formula stays at the target after warmup. A separate decay schedule may take over then, while the optimizer’s moment state continues.

Warmup changes the step size, rather than the data loss. It can help control early updates, but its duration needs evaluation. Record whether schedule steps count optimizer updates or microbatches. During accumulation, advancing a schedule after every microbatch would differ from advancing it after each completed parameter step.

11.7 Gradient clipping

A batch can produce a gradient much larger than recent ones. Gradient clipping limits that stored gradient before the optimizer reads it. For norm clipping, regard the selected parameter gradients as one vector and measure its Euclidean norm, \(\|g\|_2=\sqrt{\sum_i g_i^2}\).

For nonzero \(g\) and threshold \(c>0\), use:

\[ g_{\mathrm{clipped}} = g\,\min\!\left(1,\frac{c}{\lVert g\rVert_{2}}\right) \tag{11.15}\]

If the norm is below the threshold, the multiplier is 1. If it exceeds the threshold, multiplication by \(c/\|g\|_2\) reduces the norm to \(c\). A zero gradient remains zero without evaluating a division by zero. For norm 10 and threshold 1, every coordinate is multiplied by 0.1.

This common multiplier preserves gradient direction. It does not guarantee the direction or magnitude of an adaptive optimizer’s eventual parameter update. For plain SGD without other terms, the step norm is at most \(\eta c\). Momentum, adaptive scaling, and direct weight decay can change that relationship.

The following abbreviated PyTorch fragment assumes an existing model, loss, and optimizer. It belongs after gradient computation and before the parameter step. For an intentionally accumulated batch, clip after all its gradients have been combined.

Code example: Gradient clipping in a PyTorch training step

import torch

loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
optimizer.zero_grad()

clip_grad_norm_ returns the norm before clipping and modifies the gradient buffers when needed. Clipping before backward would not process the current batch’s gradients. Clipping does not repair a wrong objective, invalid data, or nonfinite arithmetic, so repeated clipping should motivate inspection of the underlying computation.

11.8 Comparing update rules

An update rule is one part of an experiment. Compare optimizers with a stated data split, initialization, learning-rate policy, batch size, training budget, and metric. Their default settings need not create an equal comparison.

A checkpoint stores a model’s state at a particular training point. Resuming the same optimization procedure also requires its optimizer and schedule state. An ablation changes or removes a component to examine its effect while other relevant conditions remain fixed.

The experiment-selection section defines grid, random, and Bayesian search. Use those methods with validation evidence to select settings, then preserve the test set for the final comparison. The optimizer-surface assignment compares gradient descent, momentum, AdaGrad, and Adam on the supplied objectives, separately from the classifier experiments.

Record parameter trajectories and loss curves, rather than only the final value. A noisy path, slow progress, increasing loss, and high memory use suggest different problems. The data-loader iteration also belongs in that record because it determines which examples contribute to each gradient.

The book can now explain both how a gradient is calculated and how a rule uses it. We next examine a limitation that no optimizer can resolve on its own: a representation whose decision boundary cannot express the required pattern.
