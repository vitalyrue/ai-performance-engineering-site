20  Low-rank adaptation and preference alignment

A pretrained model may know the relevant language yet miss a task’s facts, output format, or preferred behavior. Those failures call for different interventions. Some can be addressed through input context, while others require changing parameters or training targets.

This chapter starts from the missing capability and follows what each intervention changes. It then separates the training objective, the parameters allowed to move, and the numerical format used to store them.

20.1 Prompting and retrieved context

Before continuing training, test whether the model can perform the task when its instructions and evidence are explicit. Prompting supplies those instructions through the input. In-context examples demonstrate the desired input-output pattern within that same context.

For a review classifier, a prompt might request exactly positive or negative, then show one labeled example of each. The next review follows without its label. This changes the conditional input while leaving the parameters fixed.

Compare the instruction alone with the instruction plus examples on the same held-out reviews. Inspect classification errors and invalid output formats separately. Examples consume context space, and their wording or order can affect the result.

When required facts live outside the model, retrieval-augmented generation, or RAG, supplies selected evidence before generation. Its complete text procedure here is to index source passages, retrieve relevant passages for a query, include them in the prompt, and generate an answer. Record the passages supporting that answer so it can be checked.

The conditional distribution becomes:

\[ P_{\theta}(y\mid\mathrm{prompt},\mathrm{retrieved\,context}) \tag{20.1}\]

Here \(\theta\) remains fixed, and \(y\) is the answer. As a hypothetical observation, useful evidence might raise an answer’s probability from \(0.2\) to \(0.6\) without changing a weight. Irrelevant or misleading evidence can instead reduce answer quality.

Retrieval addresses access to changing or extensive source material. It also adds indexing, search, and context-processing costs. A retrieval failure and an answer-generation failure require different corrections, as the final system experiment in Section 24.7 demonstrates.

Prompting and retrieval can be combined with later fine-tuning. If the failure persists despite sufficient evidence and clear instructions, fine-tuning on targeted examples may improve the reliability of its responses.

20.2 Supervised fine-tuning

Fine-tuning continues training from a pretrained checkpoint. Supervised fine-tuning, or SFT, uses examples of desired inputs and outputs. Instruction tuning is SFT whose records contain instructions and expected responses, sometimes with additional evidence.

The training objective remains a loss on the target outputs. For a causal instruction model, prompt tokens condition the answer, while a loss mask can restrict supervision to answer positions. The architecture-specific formats are established in Section 18.3.

Suppose a toy record has prompt IDs \([11,12]\) and answer IDs \([21,22,9]\), where 9 is the answer’s end token. The combined input is \([11,12,21,22,9]\). For an API that shifts labels internally, response-only labels are \([-100,-100,21,22,9]\).

After that internal shift, the last prompt input predicts the first answer token. The next answer input predicts the following answer token, and the final supervised prediction is the end token. The two ignored prompt positions supply context but no direct target loss in this record.

Do not apply an additional manual shift to an API that already performs it. Padding validity, response boundaries, and empty-answer handling need explicit checks. The reduction over valid targets follows Section 8.2.

Full fine-tuning allows base parameters to change under the update rule from Chapter 11. One simple gradient step is:

\[ \theta^{\prime}=\theta-\eta\nabla L_{\mathrm{task}}(\theta) \tag{20.2}\]

For scalar \(\theta=1\), gradient \(0.4\), and learning rate \(0.1\), the result is \(\theta'=0.96\). Larger models apply the same principle through an optimizer and many parameter tensors.

Fine-tuning can strengthen a stable task format, decision boundary, or instruction pattern. A small or narrow dataset can also cause overfitting. Catastrophic forgetting is loss of useful earlier behavior during adaptation.

Mixing several tasks or retaining representative earlier examples can reduce pressure toward a narrow behavior. It also increases data preparation and may dilute improvement on the main target task. Parameter-efficient updates can still cause forgetting, so preserving frozen base weights does not remove the need to evaluate the adapted model.

Compare held-out task performance before and after training, and retain tests of important base behavior. Tune learning rate and training duration on validation data rather than assuming that more updates are beneficial. Save the exact base checkpoint, tokenizer, record format, and target-mask procedure.

The course uses reasoning language model, or RLM, for a model trained to produce intermediate solution steps before an answer. For example, a training response can show \(3\times4=12\), then \(12+2=14\), and finally give 14. SFT can supervise that entire response using the same target-mask rule.

Intermediate steps consume additional generated tokens and can contain errors even when they sound plausible. Assess the answer and, where possible, the validity of each step. The displayed text does not by itself reveal the computation inside the model. RLM describes a training and response behavior here, rather than a separate attention architecture.

The adaptation experiment in Section 24.6 supplies a complete data and evaluation protocol. Some desired behaviors are easier to express through comparisons between answers than through one reference answer. Preference objectives use that additional form of supervision.

20.3 Learning from preferences

SFT imitates supplied outputs. Preference learning instead uses a judgment that one response is better than another for the same prompt. Alignment describes training and evaluation intended to bring behavior closer to the selected instructions, preferences, or constraints.

A reward model assigns a score \(r_\phi(x,y)\) to response \(y\) for prompt \(x\). One way to train it uses preferred and rejected pairs, increasing the preferred response’s score relative to the rejected response. The score reflects its training judgments and can be inaccurate outside them.

Reinforcement learning from human feedback, or RLHF, can use this scorer to improve a response-generating policy. Here a policy is the model’s conditional distribution over responses. A reference policy remains fixed to provide a comparison point.

A common objective balances expected reward against a Kullback-Leibler penalty, using the divergence defined in Section 8.4.

\[ \max_{\pi}\mathbb{E}_{x}\!\left[\mathbb{E}_{y\sim\pi(\cdot\mid x)}[r_{\phi}(x,y)]-\beta\operatorname{KL}\!\left(\pi(\cdot\mid x)\mathbin{\|}\pi_{\mathrm{ref}}(\cdot\mid x)\right)\right] \tag{20.3}\]

For each prompt, \(\beta>0\) controls the penalty for departure from the reference distribution. The expectation includes responses sampled from the policy being trained. With reward 2, divergence \(0.5\), and \(\beta=0.2\), the penalized value is \(2-0.2(0.5)=1.9\).

Proximal Policy Optimization, or PPO, is one policy-update method used in RLHF. It limits changes to action-probability ratios through a clipped objective while learning from sampled responses and their scores. That clipping differs from clipping a gradient norm.

Reinforcement learning from AI feedback, or RLAIF, uses model-generated judgments for some feedback. The evaluation must still test whether those judgments reflect the intended criteria. Optimizing an imperfect scorer can increase its score without improving the actual task.

Direct Preference Optimization, or DPO, trains from preferred and rejected responses without fitting a separate reward model and running an online reward-optimization loop. Its loss compares each response’s policy log probability with its reference log probability. Direct Preference Optimization derives this formulation.

\[ -\log\sigma\!\left(\beta\left((\log\pi_{\theta}(y_w\mid x)-\log\pi_{\mathrm{ref}}(y_w\mid x))-(\log\pi_{\theta}(y_l\mid x)-\log\pi_{\mathrm{ref}}(y_l\mid x))\right)\right) \tag{20.4}\]

Here \(y_w\) is the preferred response and \(y_l\) is the rejected response. Each response log probability is the sum of its token log probabilities, with the prompt used as conditioning context. The reference parameters remain fixed.

Take policy log probabilities \(-2.5\) for the preferred response and \(-3.5\) for the rejected response. Let both reference log probabilities be \(-4\). The reference-relative values are then \(1.5\) and \(0.5\).

With \(\beta=0.5\), their scaled difference is \(0.5(1.5-0.5)=0.5\). The sigmoid is approximately \(0.622459\), and the loss is \(-\log(0.622459)\approx0.474077\). Both response probabilities increased relative to the reference in this example, but the preferred response increased more.

The following small calculation verifies the loss and its local derivatives with respect to the two policy log probabilities.

Code example: DPO pair loss from response log probabilities

import torch
import torch.nn.functional as F

policy_logp = torch.tensor([-2.5, -3.5], dtype=torch.float64, requires_grad=True)
reference_logp = torch.tensor([-4., -4.], dtype=torch.float64)
relative = policy_logp - reference_logp
margin = 0.5 * (relative[0] - relative[1])
loss = -F.logsigmoid(margin)
loss.backward()
print(margin.item(), loss.item(), policy_logp.grad)
assert torch.isclose(loss, torch.tensor(0.4740769841801067, dtype=torch.float64))
assert policy_logp.grad[0] < 0 < policy_logp.grad[1]

The derivatives are approximately \(-0.188770\) for the preferred log probability and \(0.188770\) for the rejected one. They favor a larger reference-relative preference gap. Actual parameter gradients also depend on how the policy produces these log probabilities.

Preference training does not guarantee factual correctness, stable general behavior, or agreement across evaluators. Test those properties separately. The chosen objective also leaves open how many parameters should be allowed to change.

20.4 Low-rank updates

Updating every weight can require substantial gradient and optimizer memory. Parameter-efficient fine-tuning, or PEFT, changes only selected or added parameters. Several PEFT choices change different parts of the interface. A task head adds trainable output layers, while selective tuning updates a chosen subset of existing weights. A bottleneck adapter inserts a narrow trainable transformation inside the frozen network. With input width eight and bottleneck width two, its two matrices contain \(8(2)+2(8)=32\) weights before biases.

Soft prompt tuning learns additional input vectors while retaining the base weights. Four prompt vectors of width eight contain 32 trainable values and add four input positions. These are learned continuous vectors, whereas the ordinary prompt in Section 20.1 supplies fixed token IDs. Their equal parameter count does not make a soft prompt equivalent to an internal adapter.

Low-Rank Adaptation, or LoRA, represents an update to a frozen matrix through two smaller trainable factors.

The rank concept from Section 14.3 applies to the update here, rather than to a compressed data matrix. For base weight \(W\in\mathbb R^{d_{\text{out}}\times d_{\text{in}}}\), the effective weight is:

\[ W_{\mathrm{eff}}=W+\frac{\alpha}{r}BA \tag{20.5}\]

Factor \(A\) has shape \([r,d_{\text{in}}]\), and \(B\) has shape \([d_{\text{out}},r]\). Their product has the same shape as \(W\) and rank at most \(r\). The scale \(\alpha/r\) controls its contribution.

For a four-by-four identity base, choose \(r=1\), \(\alpha=1\), \(A=[1,0,-1,2]\), and \(B=[1,2,0,-1]^\top\). Their product is:

\[ BA=\left[\begin{aligned}1&\quad 0&\quad -1&\quad 2\\2&\quad 0&\quad -2&\quad 4\\0&\quad 0&\quad 0&\quad 0\\-1&\quad 0&\quad 1&\quad -2\end{aligned}\right] \tag{20.6}\]

Each row is a multiple of \(A\), showing its rank-one structure. For input \(x=(1,0,1,0)^\top\), \(Ax=0\), so the adapter contributes zero and the output remains \(x\).

For \(x=(1,0,0,0)^\top\), \(Ax=1\) and \(BAx=(1,2,0,-1)^\top\). Adding the identity base output gives \((2,2,0,-1)^\top\). The same adapter can therefore leave one input unchanged while changing another.

The two factors contain eight trainable values, compared with sixteen in a full four-by-four update. More generally:

\[ \operatorname{params}_{\mathrm{LoRA}}=r(d_{\mathrm{in}}+d_{\mathrm{out}}) \tag{20.7}\]

For a \(4096\times4096\) weight and \(r=8\), each factor contains 32,768 values. The total is 65,536, compared with 16,777,216 base values, or \(0.390625\%\). This fraction excludes other adapted layers, biases, and any additional trainable modules.

A frozen weight still participates in forward computation. Gradients can pass through its operation to earlier trainable components without accumulating an update for that weight. LoRA commonly starts with nonzero random \(A\) and zero \(B\), giving a zero initial adapter contribution.

At that initialization, \(B\) can receive a gradient while \(A\) initially receives zero through the product. Initializing both factors to zero would block both product gradients. The following calculation verifies the complete matrix example and this initialization behavior.

Code example: A complete rank-one update and its initial gradients

import torch

W = torch.eye(4)
A = torch.tensor([[1., 0., -1., 2.]])
B = torch.tensor([[1.], [2.], [0.], [-1.]])
delta = B @ A
print(delta)
x_unchanged = torch.tensor([1., 0., 1., 0.])
x_changed = torch.tensor([1., 0., 0., 0.])
assert torch.equal((W + delta) @ x_unchanged, x_unchanged)
assert torch.equal((W + delta) @ x_changed, torch.tensor([2., 2., 0., -1.]))

A = A.clone().requires_grad_()
B = torch.zeros(4, 1, requires_grad=True)
output = W @ x_changed + B @ (A @ x_changed)
output.sum().backward()
assert W.grad is None
assert torch.count_nonzero(A.grad) == 0
assert torch.equal(B.grad, torch.ones(4, 1))
print(A.grad, B.grad)

Setting requires_grad=False excludes a tensor from gradient accumulation. The optimizer must also contain the intended trainable parameters and execute a step. The flag alone neither updates weights nor proves that the optimizer was configured correctly.

For inference, additive linear paths can be merged into one matrix.

\[ W_{\mathrm{merged}}=W+\frac{\alpha}{r}BA \tag{20.8}\]

Merging removes the separate adapter branch but makes switching adapters less convenient. Supported PEFT models expose a merge operation such as merge_and_unload(). Quantized bases can require reconstruction or requantization, so merging may alter numerical results and needs validation.

LoRA reduces trainable parameter state, but the base weights and activation computation remain. Quantization addresses the base-weight storage component separately.

20.5 Quantized bases

Quantization represents values with a smaller set of stored codes. Dequantization reconstructs approximate numerical values from those codes for computation. Fewer bits can reduce weight storage while introducing reconstruction error.

A simple uniform quantizer uses scale \(s\) and zero point \(z\): \(q=\operatorname{clip}(\operatorname{round}(w/s)+z,q_{\min},q_{\max})\). Its reconstruction rule is:

\[ \hat{x}=\mathrm{scale}\cdot(q-\mathrm{zero\,point}) \tag{20.9}\]

The stored code identifies a level. Values between levels are rounded, and values beyond the representable range are clipped. The reconstructed number can therefore differ from the original even before any model calculation.

Block quantization gives smaller groups of values their own scales. This limits how far one outlier can stretch a shared range, at the cost of more scale metadata. For block \(b\) and value index \(i\):

\[ \hat{w}_{b,i}=s_b(q_{b,i}-z_b) \tag{20.10}\]

With code 13, scale \(0.1\), and zero point 3, the reconstructed weight is \(0.1(13-3)=1\). Double quantization also compresses the collection of block scales.

\[ \hat{s}_b=s_s(q_b^{s}-z_s) \tag{20.11}\]

If the scale code is 8, its reconstruction scale is \(0.01\), and its zero point is zero, the reconstructed block scale is \(0.08\). Using that reconstructed scale with weight code 13 and zero point 3 gives \(0.8\). This second approximation changes the reconstructed weight again.

NormalFloat 4, or NF4, uses sixteen nonuniform reconstruction levels with greater resolution near zero. It was designed for approximately normally distributed normalized weights. An NF4 code selects a lookup level that is then scaled, rather than using the uniform zero-point formula above.

Quantized Low-Rank Adaptation, or QLoRA, combines a frozen quantized base with trainable LoRA factors. Its forward calculation can be represented as:

\[ y=\operatorname{dequant}(W_{4\mathrm{bit}})x+\frac{\alpha}{r}BAx \tag{20.12}\]

Low-bit codes determine how the base is stored. A supported floating-point compute dtype, such as bfloat16, determines how reconstructed values participate in arithmetic. The adapter path retains trainable values in a suitable higher precision. QLoRA combines this approach with NF4, double quantization, and memory-management techniques.

The following setup function expects an actual causal-model checkpoint, its revision, and compatible projection names. It uses PyTorch, Transformers, PEFT, bitsandbytes, and hardware that supports the selected quantized path and compute dtype. The PEFT quantization guide specifies preparation before adapter insertion.

Code example: Preparing a compatible quantized causal model for adapter training

import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

def make_qlora(checkpoint_id, revision, target_modules):
    quantization = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=torch.bfloat16,
        bnb_4bit_use_double_quant=True,
    )
    base = AutoModelForCausalLM.from_pretrained(
        checkpoint_id, revision=revision,
        quantization_config=quantization,
    )
    base = prepare_model_for_kbit_training(base)
    config = LoraConfig(
        r=8, lora_alpha=16, target_modules=target_modules,
        bias="none", task_type="CAUSAL_LM",
    )
    model = get_peft_model(base, config)
    model.print_trainable_parameters()
    trainable = [key for key, parameter in model.named_parameters() if parameter.requires_grad]
    if not trainable:
        raise RuntimeError("No trainable adapter parameters were attached")
    return model

Rank 8 and \(\alpha=16\) give adapter scale 2. The caller chooses projection names that exist in the checkpoint, such as q_proj and v_proj for a compatible architecture. Adapting all supported linear layers is a broader choice with a different trainable parameter count.

The printed parameter report should show which values are trainable. It does not establish that a training batch fits in memory. Activations, optimizer state, reconstruction buffers, and the device’s kernels also matter. Chapter 23 examines these storage lifetimes.

The complete experiment in Section 24.6 specifies the checkpoints, target records, and before-and-after evaluation. Quantization and low-rank updates should be assessed against that task evidence, rather than inferred from compression ratios.

20.6 Distillation and pruning

Adapters reduce the cost of changing a base, but the deployed model can still be large. Knowledge distillation trains a student model from outputs supplied by a teacher model. Pruning removes selected parts of a model’s existing parameter structure.

Distillation can use teacher-generated answers as training examples. It can also match teacher probability distributions or selected intermediate representations. Matching probabilities requires compatible output meanings, and comparing intermediate values may require an additional projection when their widths differ.

Soft teacher targets preserve alternatives that a single hard label discards. If a teacher assigns \((0.7,0.2,0.1)\), a student can learn that the second class is a more plausible alternative than the third. A cross-entropy or KL objective from Chapter 8 measures the distribution mismatch.

For teacher distribution \((0.75,0.25)\) and student distribution \((0.5,0.5)\), their cross-entropy is \(0.693147\) and the teacher entropy is approximately \(0.562335\). The KL divergence is therefore approximately \(0.130812\). The teacher’s uncertainty remains part of the target.

Some methods soften both distributions with a temperature before comparing them. That changes the training target and requires a defined temperature and loss scale. Other methods match teacher answers directly and do not require shared token-level distributions.

A small language model has fewer parameters relative to the compared larger model. There is no universal size boundary implied here. A smaller student can lower storage and computation, but the teacher’s quality does not automatically transfer to it.

Pruning uses a stated criterion to remove weights, channels, attention heads, or larger structures. Unstructured pruning removes individual weights. Structured pruning removes complete groups that an implementation can more readily exclude from dense operations.

Setting many weights to zero does not guarantee less memory or faster dense matrix multiplication. The storage format and kernels must exploit the removed structure. Quality can also fall, requiring further training or a less aggressive pruning decision.

These choices change different objects. Distillation changes the student’s supervision, pruning changes retained structure, and quantization changes numerical representation. LoRA constrains an update, while the expert routing in Section 17.6 selects active computation. A model can combine several of them.

Choose the intervention from the observed failure and resource constraint. Measure task quality, retained base behavior, and the relevant memory or latency cost. Chapter 21 follows the adapted model into the request-processing loop where those serving costs become visible.
