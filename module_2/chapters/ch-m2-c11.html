10  Backpropagation

The running classifier has a mean loss of about 0.459. That number evaluates its current predictions, but does not yet say which parameter should change. To improve the model, we need to trace how a small parameter change affects the loss through the score and probability calculations.

Derivatives describe those local changes. The chain rule connects them through a computation graph, and backpropagation applies that rule to all relevant parameters. We then use the resulting gradients for one complete training step.

10.1 Local change and gradients

Consider \(f(x)=3x^2+1\). Near \(x=2\), increasing \(x\) slightly increases \(f(x)\) by about twelve times as much. The derivative is this local rate of change. Formally, it is the limit of \((f(x+h)-f(x))/h\) as the increment \(h\) approaches zero.

Expanding the difference gives \(3((x+h)^2-x^2)/h=6x+3h\). As \(h\) approaches zero, the derivative becomes \(f'(x)=6x\). At \(x=2\), it is 12. This derivative describes local behavior, rather than a fixed slope for every value of \(x\).

If a loss depends on several parameters, a partial derivative changes one parameter while holding the others fixed. The gradient collects all those partial derivatives. For parameter vector \(\theta\), the gradient \(\nabla_\theta L\) has one component for each parameter. A matrix parameter has a gradient with matching matrix dimensions.

For a small displacement \(\Delta\theta\), the first-order change in loss is approximately \(\nabla_\theta L^\top\Delta\theta\). A positive derivative means increasing that coordinate increases the loss locally. Moving against the gradient therefore provides a local direction of decrease when the gradient is nonzero and the step is sufficiently small.

The magnitude depends on the current parameters, the example, and the parameter’s scale. A large derivative is not a universal measure of that parameter’s importance. We need the derivative of the complete loss, rather than the sensitivity of an isolated intermediate value.

10.2 The chain rule and computation graphs

A parameter usually affects the loss indirectly. It changes a score, which changes a probability, which changes the penalty. The chain rule multiplies the local rates along that dependency:

\[ \frac{dL}{dx} = \frac{dL}{dy}\,\frac{dy}{dx} \tag{10.1}\]

Here \(x\) is an earlier value, \(y\) is an intermediate value depending on \(x\), and \(L\) depends on \(y\). If \(dL/dy=5\) and \(dy/dx=3\), then \(dL/dx=15\). The two rates answer different questions, and their product describes the complete effect.

A computation graph records the values and operations producing a result. Its nodes represent values or operations, and its directed edges record dependencies. A forward pass evaluates those operations from inputs to outputs. The reverse calculation starts from the output sensitivity and returns derivatives to the earlier values.

Use the scalar classifier with input \(x=2\), weight \(w=0.5\), bias \(b=0.1\), and positive target 1:

\[ z = wx+b,\quad p=\sigma(z),\quad L=-\log(p) \tag{10.2}\]

The multiplication gives \(wx=1.0\), the addition gives \(z=1.1\), sigmoid gives \(p\approx0.7503\), and the loss is \(L=-\log p\approx0.2873\). These are distinct nodes in one dependency chain.

We first need the local derivative of sigmoid. Differentiating \((1+e^{-z})^{-1}\) gives \(e^{-z}/(1+e^{-z})^2\), which can be written using the sigmoid value itself:

\[ \sigma'(z)=\sigma(z)\bigl(1-\sigma(z)\bigr) \tag{10.3}\]

Thus \(dp/dz=p(1-p)\). At the example’s probability, this is approximately \(0.7503\times0.2497=0.1874\). At the earlier sigmoid example \(z=2\), it is approximately \(0.8808\times0.1192=0.1050\). This is the local sensitivity that becomes small near probabilities 0 and 1.

For the positive-target loss, \(dL/dp=-1/p\approx-1.3329\). Multiplying the local derivatives gives \(dL/dz\approx-1.3329\times0.1874\approx-0.2497\). It would be incorrect to infer the loss derivative from the sigmoid derivative alone.

The affine operation supplies the next local derivative:

\[ \frac{dz}{dw}=x \tag{10.4}\]

Here \(dz/dw=x=2\) and \(dz/db=1\). The weight derivative follows the same chain rule:

\[ \frac{dL}{dw}=\frac{dL}{dz}\,\frac{dz}{dw} \tag{10.5}\]

The results are \(dL/dw\approx-0.2497\times2=-0.4995\) and \(dL/db\approx-0.2497\). The graph figure places each multiplication beside the path that requires it.

For a general binary target, differentiate the full BCE expression from Chapter 8. Its probability derivative is \(-y/p+(1-y)/(1-p)\). Multiplying by \(p(1-p)\) gives \(-y(1-p)+(1-y)p\), which simplifies to:

\[ \frac{dL}{dz}=p-y \tag{10.6}\]

This explains the result \(p-y\) rather than assuming it. With \(p=0.8\), a positive target gives \(-0.2\) and a negative target gives \(0.8\). A confidently wrong probability of 0.95 for target 0 gives derivative 0.95, despite sigmoid’s small local slope there. The isolated probability function did not determine the complete learning signal.

A value can affect several later operations. The complete derivative then adds the contributions of all paths:

\[ \operatorname{grad}_{x}=\sum_{\text{paths }p}\operatorname{contribution}_{p} \tag{10.7}\]

For example, contributions 2 and 5 sum to 7. This mathematical path sum is one meaning of gradient accumulation. Adding gradients from separate backward calls is a related storage behavior, discussed after the vector form of the chain rule.

10.3 Vector-Jacobian products

A layer can produce many output coordinates from many inputs. Differentiating each output independently would describe their relationships, but a scalar loss needs a particular weighted combination of them. A Jacobian arranges all local output-input derivatives into a matrix:

\[ J_{i,j}=\frac{\partial y_{i}}{\partial x_{j}} \tag{10.8}\]

For \(x\in\mathbb R^n\) and \(y=f(x)\in\mathbb R^m\), the Jacobian \(J\) has shape \([m,n]\). Row \(i\) describes output \(y_i\), and column \(j\) describes input \(x_j\).

Take \(y=(x_1+2x_2,3x_1-x_2)\). Its Jacobian is \(J=[[1,2],[3,-1]]\). Suppose the loss sensitivities to the two outputs are \((2,3)\). These are the upstream gradient, the rates already calculated for the outputs of this operation.

A vector-Jacobian product combines those sensitivities with the operation’s Jacobian:

\[ \frac{dL}{dx}=\frac{dL}{dy}\,J \tag{10.9}\]

This equation uses row-vector gradients. Shapes \([1,m]\) and \([m,n]\) produce \([1,n]\). For the example, \((2,3)J=(2\times1+3\times3,2\times2+3\times(-1))=(11,1)\). The first input receives contributions 2 and 9 from the two output paths.

Writing that multiplication for one coordinate makes the path sum explicit:

\[ \frac{\partial L}{\partial x_{j}}=\sum_{i}\frac{\partial L}{\partial y_{i}}\,\frac{\partial y_{i}}{\partial x_{j}} \tag{10.10}\]

The input coordinate \(j\) is fixed, while \(i\) ranges over output coordinates. For a diagonal Jacobian with diagonal \((1,4)\) and the same upstream gradient \((2,3)\), the result is \((2,12)\). These examples retain both cross-coordinate and independent-coordinate cases.

Reverse-mode differentiation begins with output sensitivities and applies these products toward the inputs. A local backward operation can often compute the product directly, without materializing every entry of the full Jacobian. This is particularly useful when one scalar loss depends on many parameters.

The categorical loss provides another example. For softmax, \(\partial p_i/\partial z_j=p_i(\delta_{ij}-p_j)\), where \(\delta_{ij}\) is 1 when the indices are equal and 0 otherwise. Differentiating the observed-target cross-entropy gives \(-\sum_i y_i(\delta_{ij}-p_j)\). Because the target indicators sum to 1, the result is \(p_j-y_j\).

For probabilities \((0.7,0.2,0.1)\) and target class 0, the logit gradient is \((-0.3,0.2,0.1)\). Its dimensions match the three logits. Treating logits as independently adjustable values, gradient descent would raise the target logit and lower its competitors. A real parameter update combines shared paths and examples, so it need not move every logit exactly as an independent update would.

The mathematics now specifies what each reverse operation must return. Automatic differentiation manages that computation and its stored values.

10.4 Automatic differentiation

Writing a derivative for every parameter by hand becomes impractical as the graph grows. Automatic differentiation evaluates the chain rule through the actual sequence of differentiable operations. Backpropagation is this reverse calculation applied to a model’s computation graph. It computes gradients, while an optimizer later uses them to change parameters.

PyTorch’s autograd system records relevant operations when gradient tracking is enabled. A leaf tensor is a tensor that begins a tracked computation rather than resulting from another tracked operation. Parameters are usually leaves with requires_grad=True. A non-leaf result can carry a grad_fn referring to the operation needed for its backward calculation.

For an input batch \(X\) of shape \([B,D]\) and parameter \(w\) of shape \([D,H]\), an intermediate result can have shape \([B,H]\). Such an intermediate output is also called an activation. A reduced loss is scalar, and the gradient computed for \(w\) has shape \([D,H]\).

The backward pass traverses the dependencies in reverse and sums contributions before continuing to earlier values. This differs from computing another forward prediction.

The common scalar call loss.backward() begins with sensitivity 1 for the loss itself. If the output contains several values, a caller must supply an upstream tensor specifying their weighted combination. That is a vector-Jacobian product, rather than an unexplained requirement that every differentiable output be scalar.

By default, leaf parameters receive accumulated derivatives in their .grad buffers. Intermediate derivatives are used during computation, but their .grad fields are not necessarily retained. The graph and the gradient buffer are separate objects with different lifetimes.

The runnable example below differentiates \(3x^2+1\) at \(x=2\). The first backward pass yields 12. A second backward pass through the already-consumed graph fails because saved intermediates have been freed. A fresh forward computation creates a new graph, whose derivative is then added to the existing buffer, producing 24.

The figure separates the recorded operations from the leaf gradient buffer.

Code example: A scalar loss creates gradients on tensors that require them.

import torch

x = torch.tensor(2.0, requires_grad=True)
result = 3 * x ** 2 + 1
result.backward()
assert x.grad.item() == 12.0
print(x.grad.item())

try:
    result.backward()
except RuntimeError:
    print("The consumed graph needs a new forward calculation.")
else:
    raise AssertionError("Expected this graph's saved values to be unavailable")

fresh_result = 3 * x ** 2 + 1
fresh_result.backward()
assert x.grad.item() == 24.0
print(x.grad.item())

x.grad = None
(3 * x ** 2 + 1).backward()
assert x.grad.item() == 12.0
print(x.grad.item())

Clearing x.grad prepares its buffer for another independent derivative. It does not recreate the old graph. Conversely, explicitly retaining a graph preserves saved values but does not clear its accumulated gradients. These controls solve different problems.

The operation detach() breaks a tensor’s connection to earlier tracked operations. A torch.no_grad() context prevents recording operations performed inside it. In-place changes can also invalidate values required by backward. Use those controls deliberately when defining which paths should contribute, rather than treating a missing gradient as an optimizer problem.

The forward pass may retain intermediate values for the backward pass, or a training method may recompute them later. This creates a memory cost beyond the parameter arrays themselves. For small models, interpreter overhead and data movement can dominate. Larger tensor operations may instead be limited by arithmetic or memory throughput, so the bottleneck must be measured.

10.5 One training step

The gradients describe local loss changes. Gradient descent subtracts a scaled gradient from the current parameters:

\[ \theta_{\mathrm{new}} = \theta - \eta\,\nabla_{\theta}L(\theta) \tag{10.11}\]

The positive scalar \(\eta\) is the learning rate, and \(\theta\) collects the parameters. For \(\theta=1\), gradient 3, and \(\eta=0.1\), the next value is \(1-0.1\times3=0.7\). The negative gradient is the steepest first-order decrease direction under the usual Euclidean length constraint. A finite step still needs a suitable scale and does not guarantee a global solution.

For one weight, the same update is:

\[ w_{\mathrm{next}}=w-\mathrm{lr}\,\frac{dL}{dw} \tag{10.12}\]

The symbol lr denotes the learning rate in this form. The update is a separate operation after the gradient has been calculated.

Complete the running three-example classifier. Its probabilities are approximately \([0.71095,0.45017,0.64566]\) and targets are \([1,0,1]\). The per-example logit differences are \([-0.28905,0.45017,-0.35434]\). Because the objective is a mean, each contributes one third of its local derivative.

The weight gradient is \(X^\top(p-y)/3\). Its first coordinate is \((-0.28905-0.35434)/3\approx-0.21446\). Its second is \((0.45017-0.35434)/3\approx0.03194\). The bias gradient is their three-example mean, approximately \(-0.06441\).

With learning rate 0.1, weights \([0.8,-0.3]\) become approximately \([0.82145,-0.30319]\), and bias 0.1 becomes 0.10644. Recomputing the scores gives approximately \([0.92789,-0.19675,0.62469]\). The mean loss falls from about 0.45893 to 0.45386 for this batch and step. That observed decrease verifies this example, rather than proving every future step must decrease loss.

The runnable code below compares autograd with the analytical gradients before applying the update. torch.no_grad() keeps the parameter assignment outside the next gradient graph. The example recomputes the loss after the update instead of interpreting the old loss value as a new measurement.

Code example: Analytical and automatic gradients for the same three-example batch

import torch
import torch.nn.functional as F

X = torch.tensor([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]], dtype=torch.float64)
y = torch.tensor([1.0, 0.0, 1.0], dtype=torch.float64)
w = torch.tensor([0.8, -0.3], dtype=torch.float64, requires_grad=True)
b = torch.tensor(0.1, dtype=torch.float64, requires_grad=True)
logits = X @ w + b
loss = F.binary_cross_entropy_with_logits(logits, y)
error = logits.detach().sigmoid() - y
expected_w = X.T @ error / len(y)
expected_b = error.mean()
loss.backward()
assert torch.allclose(w.grad, expected_w)
assert torch.allclose(b.grad, expected_b)
print(loss.item(), w.grad.tolist(), b.grad.item())

with torch.no_grad():
    w -= 0.1 * w.grad
    b -= 0.1 * b.grad
    after = F.binary_cross_entropy_with_logits(X @ w + b, y)
    assert after < loss
    print(w.tolist(), b.item(), after.item())
w.grad = None
b.grad = None

The same method applies to a two-feature example with \(x=[2,-1]\), \(w=[0.5,-0.3]\), \(b=0.1\), and target 1. Its score is \(2(0.5)+(-1)(-0.3)+0.1=1.4\). Using unrounded values, sigmoid gives about 0.80218 and the loss is about 0.22042.

Its logit derivative is \(p-1\approx-0.19782\). Multiplying by the two inputs gives weight derivatives \([-0.39563,0.19782]\), while the bias derivative is \(-0.19782\). At learning rate 0.1, the new weights are approximately \([0.53956,-0.31978]\) and the new bias is 0.11978. Use unrounded intermediate values when checking the step, because rounding a probability before taking its logarithm changes later displayed decimals.

An optimizer step performs the parameter change using gradient buffers and any additional optimizer state. It receives gradients on parameters, rather than raw examples. A typical loop clears previous gradients, computes predictions and loss, calls backward, and then takes an optimizer step. Clearing immediately after the step can also be valid if the intended accumulation boundary remains explicit.

The complete map now separates the training branch from inference. Targets enter the loss calculation independently of the model’s input, and the optimizer follows gradient computation.

For a library-managed loop, optimizer.zero_grad() prepares the buffers and optimizer.step() applies the update. With set_to_none=True, clearing can leave a buffer absent until a later backward pass supplies it. This is distinct from storing a tensor of zeros, which some update rules treat differently.

The loss surface also limits what an update can guarantee. A convex function never lies above the straight-line interpolation between any two points in its domain. For a differentiable convex objective, a zero gradient identifies a global minimum when such a point exists. This property alone does not make every learning rate converge.

For \(f(w)=w^2\), gradient descent gives \(w_{t+1}=(1-2\eta)w_t\). Its magnitude shrinks when \(0<\eta<1\). At \(\eta=1\), the sign alternates without shrinking. Larger values can make the iterates grow even though the function is convex.

Practical stopping rules include an update budget, small changes in loss or parameters, and validation-based early stopping. A small gradient can also occur near a saddle point or a saturated region. Use the loss history and held-out behavior alongside local derivative size. Section 24.1 compares convex and nonconvex surfaces explicitly.

The following additional runnable example retains the column-shaped binary interface: input \([32,4]\), targets \([32,1]\), weights \([4,1]\), and bias \([1]\). It uses random data to demonstrate shapes and buffer handling. It makes no claim about useful model quality.

Code example: A minimal binary logistic regression step.

import torch

torch.manual_seed(7)

X = torch.randn(32, 4)
y = torch.randint(0, 2, (32, 1)).float()
w = torch.randn(4, 1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)

logits = X @ w + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(logits, y)
loss.backward()
assert w.grad.shape == (4, 1)
assert b.grad.shape == (1,)

with torch.no_grad():
    w -= 0.1 * w.grad
    b -= 0.1 * b.grad
    w.grad.zero_()
    b.grad.zero_()

The weight and bias gradients have shapes \([4,1]\) and \([1]\). The no-grad block changes the parameters and clears both buffers. Using nn.Linear(D,1) with an appropriate stable BCE loss supplies the same model interface. The next chapter compares update rules and their additional state.

10.6 Accumulating a larger batch

A desired batch may require more intermediate storage than the device can hold at once. A microbatch is a smaller group processed as part of one intended batch. Gradient accumulation can combine their contributions before a single optimizer step.

Suppose the intended batch contains the same three examples, split into groups of one and two. To obtain the full-batch mean gradient, divide each group’s sum of losses by 3 before its backward pass. The first contributes one example’s share and the second contributes two. Taking an unweighted mean of the two group means would instead give the lone first example half the total weight.

An equivalent rule weights each microbatch mean by its valid-example count divided by the total valid count. For token losses, count supervised tokens rather than padded positions. Parameters must remain fixed until all the intended contributions have accumulated.

The runnable check compares a full-batch gradient with the accumulated gradients from those unequal groups. Each group receives a fresh forward graph, while the parameter buffers retain the sum. Only after the comparison would an optimizer step be taken.

Code example: Unequal microbatches retain the full-batch mean gradient

import torch
import torch.nn.functional as F

X = torch.tensor([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]], dtype=torch.float64)
y = torch.tensor([1.0, 0.0, 1.0], dtype=torch.float64)
w = torch.tensor([0.8, -0.3], dtype=torch.float64, requires_grad=True)
b = torch.tensor(0.1, dtype=torch.float64, requires_grad=True)
F.binary_cross_entropy_with_logits(X @ w + b, y).backward()
full_w, full_b = w.grad.clone(), b.grad.clone()
w.grad = None
b.grad = None

for start, stop in [(0, 1), (1, 3)]:
    logits = X[start:stop] @ w + b
    partial = F.binary_cross_entropy_with_logits(logits, y[start:stop], reduction="sum") / len(y)
    partial.backward()

assert torch.allclose(w.grad, full_w)
assert torch.allclose(b.grad, full_b)
print(w.grad.tolist(), b.grad.item())

The gradients agree to numerical precision because the per-example computation and parameter values are the same. A layer whose output depends on the other examples in its batch can break that equivalence. Random operations and differing numerical execution can also change exact results, so the assumptions belong with the comparison.

This distinction completes the training mechanism: a graph determines derivatives, buffers accumulate them, and an update rule changes parameters at a stated boundary. We can now compare those update rules without treating gradients as unexplained inputs.

Chapter checkpoint

A second call to backward fails after the first graph has been consumed. Would clearing parameter gradients recreate that graph? When combining microbatches of one and two examples into a three-example mean, how should their losses be weighted?

Feedback: Clearing a gradient buffer does not recreate saved operations. Recompute the forward graph, or retain it deliberately when the task requires reuse. Divide each microbatch’s summed losses by 3, or weight its mean by its share of the three examples. Take one parameter step after all contributions are accumulated.
