3  Subword tokenization

A word vocabulary gives common words short representations, but new names, spellings, and technical terms are difficult to cover. A character vocabulary can spell them, but it often produces much longer sequences. Subword tokenization uses reusable pieces between those extremes.

The vocabulary must be learned before a trained model can rely on its IDs. This chapter follows that construction, compares alternative selection rules, and explains the structural tokens that accompany ordinary text.

3.1 Byte pair encoding

Suppose many words share the characters u followed by g. Storing ug as one vocabulary entry can shorten those words without adding an entry for every complete word. Byte Pair Encoding, or BPE, repeatedly adds entries by merging frequent adjacent symbols. It adapts an earlier compression method to vocabulary construction.

There are two distinct operations. Training a tokenizer determines its vocabulary and merge rules from a corpus. Applying the tokenizer uses those fixed rules on new text. Recounting pairs in each new sentence would create a changing representation that no fixed model could reliably interpret.

Start with a base set of symbols, such as characters or bytes. Count adjacent pairs in the training corpus, including the number of times each training word occurs. The merge rule selects a pair with the largest count:

\[ (a^\star,b^\star)=\operatorname*{arg\,max}_{a,b}\operatorname{count}(a,b) \tag{3.1}\]

The symbols \(a\) and \(b\) identify candidate adjacent pieces. The function \(\operatorname{count}(a,b)\) adds their occurrences across the corpus. The operator \(\operatorname*{arg\,max}\) returns the pair attaining the largest value. A deterministic tie rule is needed when several pairs have that value.

The selected pair becomes a single new symbol:

\[ V_{k+1}=V_k\cup\{a^\star b^\star\} \tag{3.2}\]

Here \(V_k\) is the vocabulary after \(k\) merges, and \(a^\star b^\star\) is the concatenation of the selected pieces. If that symbol is new, the vocabulary grows by one entry. Each word representation is then updated by replacing matching, nonoverlapping pairs. Counts must be recomputed on the updated representation before selecting another merge.

For example, counts 30 for (l,o) and 12 for (o,w) favor the first pair. If a new merged symbol is added to a vocabulary of size 100, its size becomes 101. These small calculations describe one decision. The following corpus shows why the recount is essential.

Use word counts hug:10, pug:5, pun:12, bun:4, and hugs:5. Initially, each word is split into characters followed by a separate </w> boundary marker. Thus hug begins as [h,u,g,</w>]. Boundary markers are eligible for merging in this example.

In round 1, (u,g) occurs \(10+5+5=20\) times, (p,u) occurs \(5+12=17\) times, and (u,n) occurs \(12+4=16\) times. The most frequent pair is (u,g), so the first new symbol is ug.

In round 2, the new representations include [h,ug,</w>] and [p,ug,</w>]. The counts of (h,ug) and (ug,</w>) are each 15. Both (u,n) and (n,</w>) occur 16 times. Using the first pair encountered in the fixed corpus order breaks the tie in favor of (u,n), creating un.

In round 3, the two words ending in un now contribute \(12+4=16\) occurrences of (un,</w>). That pair exceeds the counts of 15 for (h,ug) and (ug,</w>). The third merge therefore creates un</w>. Omitting the boundary pairs from the recount would incorrectly select hug at this step.

In round 4, (h,ug) and (ug,</w>) each occur 15 times. The same tie rule selects (h,ug), creating hug. The word hug is now represented by [hug,</w>], and pun by [p,un</w>]. Both use two symbols instead of four. The original eight-symbol vocabulary has gained ug, un, un</w>, and hug.

The source’s variant omits the boundary marker and starts with seven characters. Its first three merges are ug, un, and hug, reaching the stated vocabulary size ten. Adding a mergeable boundary symbol changes the candidate counts, which explains the extra round in the trace above. Both variants need their boundary policy stated explicitly.

The runnable example below calculates those four rounds. Each tuple stores one word’s current symbols, while its integer weight records the word count. The scan replaces nonoverlapping occurrences from left to right. Python’s insertion order supplies the stated tie rule for this fixed corpus.

Code example: Four BPE merges with weighted recounts and explicit boundaries

from collections import Counter

corpus = [(tuple(word) + ("</w>",), count) for word, count in
          [("hug", 10), ("pug", 5), ("pun", 12), ("bun", 4), ("hugs", 5)]]
merges = []
for _ in range(4):
    pairs = Counter()
    for symbols, weight in corpus:
        for pair in zip(symbols, symbols[1:]):
            pairs[pair] += weight
    best = max(pairs, key=pairs.get)
    merges.append(best)
    updated = []
    for symbols, weight in corpus:
        merged, position = [], 0
        while position < len(symbols):
            if tuple(symbols[position:position + 2]) == best:
                merged.append("".join(best))
                position += 2
            else:
                merged.append(symbols[position])
                position += 1
        updated.append((tuple(merged), weight))
    corpus = updated
    print(best, pairs[best])

assert merges == [("u", "g"), ("u", "n"), ("un", "</w>"), ("h", "ug")]
assert corpus[0][0] == ("hug", "</w>")
assert corpus[2][0] == ("p", "un</w>")

The printed merge sequence is ('u','g'), ('u','n'), ('un','</w>'), and ('h','ug'). A production tokenizer also needs a normalization policy, stopping criterion, and treatment of special symbols. This example isolates merge selection and replacement so their effect is visible.

The figure follows the same distinction between selecting a pair and applying its replacement. Each later decision reads the representation produced by the earlier one.

At application time, the tokenizer uses the learned merge order on the new input. The model’s input and output tables still assume the resulting vocabulary IDs. Changing the tokenizer underneath a trained model can change both the meaning of an ID and the number of positions the model receives.

3.2 WordPiece and SentencePiece

Raw frequency is one way to choose reusable pieces. Another is to ask whether two pieces occur together more strongly than their separate frequencies suggest. WordPiece uses subword units and often marks a continuation piece with ##. The course illustrates its selection idea with this relative pair score:

\[ score(a,b)=\frac{\operatorname{count}(a,b)}{\operatorname{count}(a)\,\operatorname{count}(b)} \tag{3.3}\]

The numerator counts adjacent occurrences of \(a\) and \(b\). The denominator multiplies their separate counts. A pair can therefore have a lower raw count and a higher relative score. This simplified score explains the comparison. It is not a complete specification of every WordPiece trainer.

Suppose u occurs 40 times, n occurs 20 times, and g occurs 15 times. If (u,n) occurs 16 times, its score is \(16/(40\times20)=0.02\). If (n,g) occurs 12 times, its score is \(12/(20\times15)=0.04\). The second pair wins despite having fewer occurrences.

The runnable code starts from those counts and reports the pair with the largest score. The dictionaries preserve the pieces and pair frequencies so the denominator can be checked directly.

Code example: WordPiece pair scores from corpus counts

from collections import Counter

piece_counts = Counter({"u": 40, "n": 20, "g": 15})
pair_counts = Counter({("u", "n"): 16, ("n", "g"): 12})

scores = {
    pair: count / (piece_counts[pair[0]] * piece_counts[pair[1]])
    for pair, count in pair_counts.items()
}
print(max(scores, key=scores.get), scores)

The result selects ('n','g'). At application time, a typical WordPiece tokenizer finds vocabulary pieces within a word, using continuation markers for pieces after its beginning. The vocabulary and segmentation policy remain fixed. Rare text is represented by available pieces, or by an unknown-token policy when segmentation fails.

SentencePiece addresses a different part of the interface. It trains from raw sentences without requiring whitespace to be a hard word boundary. Spaces can be represented explicitly, which is useful for multilingual text. SentencePiece is a framework that supports both BPE and a unigram tokenizer. It is therefore not simply a third merge rule alongside BPE and WordPiece.

The unigram tokenizer starts with more candidate pieces than it intends to retain. It assigns probabilities to pieces and considers possible segmentations of the training text. A segmentation’s probability multiplies the probabilities of its pieces. Summing across valid segmentations gives the probability assigned to the text under that vocabulary.

The teaching objective selects a vocabulary subject to a target size:

\[ V^\star=\operatorname*{arg\,min}_{V:\,|V|=K}\left[-\sum_{s\in C}\log P(s\mid V)\right] \tag{3.4}\]

Here \(C\) is the training corpus, \(s\) is one text, \(K\) is the vocabulary budget, and \(P(s\mid V)\) includes the available segmentations and their estimated piece probabilities. The negative natural logarithm gives likely text a smaller penalty. For example, probability 1 contributes 0, while probability 0.1 contributes about 2.303. The sum combines those penalties across the corpus.

Without a vocabulary-size constraint or another penalty, the expression does not explain why a trainer should remove pieces. Practical unigram training estimates probabilities and prunes candidates toward the required size, retaining the symbols needed by its coverage policy. This is an iterative approximation, rather than an exhaustive search over every possible vocabulary.

Suppose removing pu changes corpus loss from 10.00 to 10.01, while removing hug changes it to 10.80. The first removal causes less damage under that comparison. Repeating such decisions reduces vocabulary size while monitoring how well the remaining pieces represent the corpus.

The comparison figure separates pair-based construction from vocabulary pruning. Both produce integer token sequences, although their treatment of whitespace and rare words may produce different sequence lengths.

Domain text makes these choices tangible. Code identifiers, biomedical terms, and Hebrew words may be split into many pieces by an unsuitable vocabulary. Longer sequences require more stored positions and more subsequent computation. A domain token is a piece added or retained for such text. Adding it to an existing model also requires compatible model parameters and training, so it is not merely a spelling change.

The text-classification experiment compares BPE and WordPiece on the same sentences before measuring a downstream model. That separates an observed segmentation difference from an unsupported claim that one tokenizer must be better overall.

3.3 Structural tokens

Ordinary subwords describe text content, but a model also needs to distinguish sequence boundaries and input roles. A special token reserves a vocabulary entry for such structure. Its role comes from the data format and training convention.

Beginning and end markers delimit a sequence. Padding fills unused batch positions, with validity recorded separately as Chapter 2 explains. Separators can distinguish segments within one input. These roles may use different IDs, or share an ID under a specific interface convention.

BERT reserves [CLS], a classification token, at the start of an input for predictions about that input as a whole. Its [SEP] token separates text segments and marks their end. A pair of segments can therefore have the format [CLS] A [SEP] B [SEP]. These markers identify structure, rather than words supplied by the user. Chapter 18 explains how the model uses this format for a prediction about the relationship between two segments.

A mask token marks missing content in a masked-language-model input. Let \(M\) be a set of selected positions. A simple corruption rule replaces the original token at each selected position:

\[ x'_t=\begin{cases}\mathrm{MASK},&t\in M,\\x_t,&\text{otherwise}\end{cases} \tag{3.5}\]

The original ID is \(x_t\), and the presented input ID is \(x'_t\). If \(t\in M\), the input contains the mask token. Otherwise it retains \(x_t\). The symbol \(M\) here denotes a set of positions, rather than Chapter 2’s array of validity indicators.

For \(x=[5,6,7]\) and \(M=\{2\}\), the presented sequence is [5,MASK,7]. The target at the selected position remains 6. The model must infer that token from permitted surrounding information. A mask token is consequently different from padding: its position carries an intentional prediction problem.

Chat formats use role markers or separators to identify system, user, assistant, and tool spans. A role token is a token used for one of those structural roles. The marker remains an integer ID to the model. It gains its learned function through the training examples and the input format used at inference time.

Tokenization now supplies a vocabulary, segmentation rules, and explicit sequence structure. One modeling route retains the ordered IDs for learned representations. Another counts selected pieces into document features, which the next chapter develops.

Chapter checkpoint

After merging u and n, a corpus contains 16 occurrences of [un,</w>] and 15 of [h,ug]. Boundary markers are eligible for merging. Which pair should BPE select next? Why should applying the trained tokenizer to one new sentence avoid recomputing a new merge ranking?

Feedback: It selects (un,</w>) because 16 exceeds 15. The counts must describe the updated symbols. Applying a fixed merge policy keeps the vocabulary interface compatible with the trained model. Learning a fresh ranking from the new sentence would change that interface.
