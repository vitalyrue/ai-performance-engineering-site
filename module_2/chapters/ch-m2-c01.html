1  Prediction targets

A model is useful when its outputs help answer the question posed by an application. Before choosing its architecture, we need to specify that question and the evidence available to answer it. An article classifier needs a topic for each article. A text generator needs a continuation for the text already supplied.

Both tasks begin with examples, but they obtain their targets differently. This chapter defines those objects and shows how text supplies its own targets. It then combines individual errors into a training objective.

1.1 Defining the task

Suppose an application sorts news articles into business and sport. To judge a proposed classifier, we need an article and the topic it should receive. The input is the article, the target is its recorded topic, and the prediction is the model’s proposed topic. An example is one observation used in learning or evaluation. For this prediction task, its training record pairs an input with a target.

These roles describe the task before they describe a model. A long article and a short headline can both be inputs. The target still has to express the decision the application needs. If the application requires several topics per article, a single topic label cannot represent a correct answer.

A classification target selects a category. Binary classification has two possible categories, while multiclass classification selects one from several categories. Multilabel classification allows several categories to apply together. A regression target is a numerical quantity, such as a delivery time. A sequence target contains an ordered series of outputs, as in translation or text continuation. The form of the target determines what an error means.

The target’s source is a separate choice. In supervised learning, a dataset supplies target values, often through annotation or recorded outcomes. A label is a supplied target, such as the topic attached to an article. In self-supervised learning, the training procedure constructs targets from the observed data. Hiding part of a sentence, for example, leaves a visible input and a hidden target. The procedure still needs an explicit rule for deciding which information the model may see.

In unsupervised learning, no separate task label is supplied for each example. Clustering groups observations by a chosen similarity, while dimensionality reduction represents them with fewer coordinates. Their usefulness still requires a criterion, such as preserved relationships or performance in a later task.

Reinforcement learning uses feedback from actions rather than a correct output label for every input. A policy specifies how actions are chosen, and a reward assigns a numerical outcome to their consequences. The learner observes a state, chooses an action, and receives a new state and reward from its environment. Feedback can arrive after several actions, complicating the assignment of credit. Section 20.3 connects preference-based rewards to language-model adaptation.

Returning to prediction with a target for each input, the dataset notation records these pairs without committing to an architecture:

\[ D = \{(x_i,y_i)\}_{i=1}^{n} \tag{1.1}\]

Here \(D\) is a dataset of \(n\geq1\) examples. The index \(i\) selects an example, \(x_i\) is its complete input, and \(y_i\) is its target. The braces collect the pairs. They do not imply that the input is already a numerical vector.

For instance, \(D\) can contain ("markets rise", business) and ("team wins", sport). Later, a feature gives the model a numerical description of an input. If those descriptions are \([1,0]\) and \([0,1]\), and the class labels are 1 and 0, the numerical dataset is \(\{([1,0],1),([0,1],0)\}\). The representation has changed, while the pairing between an input and its target remains intact.

There is another distinction concerning what probability a model describes. A conditional probability, written \(P(y\mid x)\), describes possible outputs when an input is supplied. A discriminative model learns that relationship directly, as a topic classifier does. A generative model describes how observations, or structured outputs, can be generated. A language model describes probabilities of token sequences. It can also generate a continuation conditioned on an existing prefix. These are modeling choices, rather than additional target types alongside classification and regression.

The task also leaves room for different architectures. A classifier can use a linear model, a recurrent network, or a transformer. Each must produce an output that can be compared with the same topic target. The later architecture chapters explain how these models combine information. Choosing an architecture does not repair a target that fails to represent the application’s decision.

To estimate behavior on new examples, we separate the data before fitting the model. The training split supplies examples used to adjust model parameters. Parameters are the model’s adjustable numerical values. The validation split guides choices such as model size and training settings. The test split is reserved for the final evaluation. Repeatedly choosing a model from its test results makes those results part of the selection process and weakens their value as an independent estimate.

The following runnable pandas example creates four labeled rows. It places three in training and one in validation, retaining the same columns in both. This deliberately tiny split illustrates data organization. It cannot provide a reliable estimate of prediction quality, and it omits the separate test split required by a real experiment.

Code example: A small labeled dataset with explicit train and validation splits

import pandas as pd

# Each row is one example; label is the supervised target.
examples = pd.DataFrame({
    "text": ["markets rise", "team wins", "shares fall", "player scores"],
    "label": [0, 1, 0, 1],
})

train = examples.iloc[:3]
validation = examples.iloc[3:]
print(train[["text", "label"]])
print(validation[["text", "label"]])

The first table contains “markets rise,” “team wins,” and “shares fall.” The validation table contains “player scores.” Their row indices are disjoint, and each text retains its label. In a real dataset, related or duplicated examples may also need to stay in the same split. Evaluation develops that requirement.

Article labels must be supplied with the data. A text continuation can obtain its target from the next observed part of the text itself.

1.2 Preparing next-token targets

Consider a sequence with three symbols: cat, sat, and a marker for the end of the sequence. After seeing cat, a model should predict sat. After seeing cat sat, it should predict the end marker. Each training input contains only information available before its target.

A token is a unit into which a tokenizer divides text. Tokens may be words, word pieces, characters, or special markers. For this example, suppose the three tokens have integer IDs \([4,8,9]\). Chapter 2 explains the vocabulary mapping. The integers here identify symbols, and their numerical distances carry no meaning.

A prefix is the sequence available before predicting the next token. In autoregressive generation, the model extends that prefix one token at a time. A context window limits how many token positions the model can use when making a prediction.

For a sequence of \(T\) tokens, a next-token target is defined by shifting the sequence one position:

\[ \operatorname{target}_t=x_{t+1},\quad t=1,\ldots,T-1 \tag{1.2}\]

The symbol \(x_t\) now denotes the token at position \(t\), rather than the whole example \(x_i\) used above. The position index runs from 1 to \(T-1\). For \([4,8,9]\), the visible positions are \([4,8]\) and their aligned targets are \([8,9]\). At the second position, the input prefix is \([4,8]\) and the required target is 9. The final token has no following target inside this sequence.

Training can evaluate several positions together if the computation prevents an earlier position from reading its future target. This restriction is causal: a prediction depends only on permitted earlier information. The attention chapter explains how a model enforces it. At this stage, the essential rule is that the input must not reveal the answer it is being evaluated on.

A probability is a number between 0 and 1 describing how likely an outcome is under a model. Probabilities over all possible next tokens sum to 1. For a particular sequence, the probability chain rule combines successive conditional probabilities:

\[ P(x_{1:T}) = \prod_{t=1}^{T} P(x_t\mid x_{<t}) \tag{1.3}\]

Here \(x_{1:T}\) means the entire sequence, and \(x_{<t}\) means the tokens before position \(t\). The product symbol multiplies one factor for each position. The first factor describes the first token, with an empty prefix or a specified beginning marker. Later factors describe a token given the preceding tokens.

If the three factors are \(0.5\), \(0.4\), and \(0.25\), their product is \(0.5\times0.4\times0.25=0.05\). This does not assume the tokens are independent. The second and third probabilities already depend on the earlier tokens. A finite context window may approximate that dependence by retaining only a recent prefix.

The chain rule includes a first-token factor, while the within-sequence shift above supplies \(T-1\) targets. To train the first-token prediction as well, the data preparation must supply an initial context, such as a beginning marker. Keeping these conventions explicit prevents a silent mismatch between a probability formula and its training examples.

Some stored positions do not supply training targets. Padding may be inserted to form a rectangular batch, or an application may deliberately exclude part of an example from supervision. Such positions must be distinguished from genuine next-token targets. Preparing batches records their validity, and loss calculation uses it when combining errors.

1.3 Combining example losses

A dataset usually contains many predictions to judge. One model may improve on one example while becoming worse on another. We therefore need a stated rule for combining individual errors into a quantity that can guide training.

A loss assigns a numerical penalty to a prediction and its target. Its formula depends on the task. For now, assume the penalties have already been calculated. A model produces losses of 0.341, 0.598, and 0.437 on three examples. Their sum is 1.376, and their mean is \(1.376/3\approx0.459\). The mean gives each example equal weight.

The empirical risk is the average loss on the observed dataset:

\[ \widehat{R}(\theta)=\frac{1}{n}\sum_{i=1}^{n}\operatorname{loss}(f_\theta(x_i),y_i) \tag{1.4}\]

The model \(f_\theta\) uses parameters \(\theta\) to predict an output for \(x_i\). The function \(\operatorname{loss}\) compares that output with \(y_i\). The summation adds the \(n\) penalties, and division by \(n\) forms their mean. The expression is undefined for an empty dataset.

This average is one possible training objective, the quantity a training procedure seeks to reduce. It is a scalar, meaning one number, even when the predictions contain many values. Scores, probabilities, and loss functions will explain where the three example penalties come from. Backpropagation will then show how the objective guides a parameter update.

An average must match the unit being judged. Averaging one loss per document gives documents equal weight. Averaging one loss per valid token gives longer documents more influence because they supply more targets. Padding supplies no observed target and must not enlarge the denominator. Chapter 8 develops the full token-loss calculation, including explicit masks and excluded positions.

The training objective measures fit to the available training data. It does not establish that the model helps on new examples. That is why the dataset split and the later evaluation procedure remain necessary even when the average training loss becomes small.

We now have inputs, targets, and a rule for combining errors. The next step is to turn the text inputs into numerical objects without losing which token occupies each position.

Chapter checkpoint

A next-token example stores IDs \([4,8,9]\). A colleague uses \([4,8]\) as both the input positions and their targets. What has changed about the task? Separately, three valid predictions have total loss 1.8, and two padding positions occupy storage. What denominator gives the mean loss per valid prediction?

Feedback: The copied targets ask the model to reproduce the currently visible token. Next-token targets should be \([8,9]\), with future information excluded from each prediction. The valid-prediction denominator is 3, giving \(1.8/3=0.6\). Padding does not create two additional observed targets.
